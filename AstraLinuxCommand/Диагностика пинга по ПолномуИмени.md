### Если в Linux не пингуется узел по полному доменному имени (FQDN), но по IP-адресу пинг проходит, проблема обычно связана с разрешением имен. Вот основные шаги для диагностики и решения
________________________________________
#### 1. Проверьте разрешение имени
Убедитесь, что DNS корректно преобразует FQDN в IP-адрес:
```bash
nslookup <полное_имя_узла>
```
или
```bash
dig <полное_имя_узла>
```
Если IP-адрес не возвращается, проблема в настройках DNS.
________________________________________
#### 2. Проверьте файл /etc/hosts
Убедитесь, что в файле /etc/hosts нет некорректной записи для этого имени. Пример:
```bash
cat /etc/hosts | grep <имя_узла>
```
________________________________________
#### 3. Проверьте DNS-клиент
•	Файл /etc/resolv.conf: Убедитесь, что указаны корректные DNS-серверы.
```bash
cat /etc/resolv.conf
```
•	Проверка через systemd-resolve (если используется):
```bash
systemd-resolve --status
```
________________________________________
#### 4. Порядок разрешения имен
Проверьте файл /etc/nsswitch.conf. Убедитесь, что DNS указан в списке источников для разрешения имен:
```text
hosts: files dns
```
Если порядок files dns, система сначала проверит /etc/hosts, затем DNS.
________________________________________
#### 5. Проблемы с сетевым экраном
Убедитесь, что DNS-запросы (порт 53) не блокируются фаерволом:
```bash
sudo iptables -L -n | grep 53
```
Для диагностики временно отключите фаервол:
```bash
sudo systemctl stop firewalld  # для RedHat-based
sudo systemctl stop ufw        # для Debian-based
```
________________________________________
#### 6. Проверка DNS-сервера
Если DNS-сервер недоступен, добавьте альтернативные ``DNS (например, 8.8.8.8 или 1.1.1.1) в /etc/resolv.conf``:
```bash
echo "nameserver 8.8.8.8" | sudo tee -a /etc/resolv.conf
```
________________________________________
#### 7. Кэш DNS
Очистите кэш DNS (если используется systemd-resolved):
```bash
sudo systemd-resolve --flush-caches
```
________________________________________
#### 8. Проверка домена по умолчанию
Если имя указано без домена, система может добавить домен из ``/etc/resolv.conf`` (опция search). Используйте ``FQDN`` с точкой в конце, чтобы избежать этого:
```bash
ping <hostname.example.com.>
```
________________________________________
#### 9. Логи
Проверьте логи для диагностики:
```bash
journalctl -u systemd-resolved -f
```
________________________________________
#### 10. Пример диагностики:
```bash
# Проверяем DNS-запрос
dig example.com

# Проверяем, есть ли ответ от DNS
```bash
ping -c 3 8.8.8.8

# Сравниваем IP из DNS и IP, который пингуется

ping -c 3 <IP_из_DNS>
```
Если проблема сохраняется, проверьте настройки сети (NAT, VPN, прокси) или корректность самого FQDN.

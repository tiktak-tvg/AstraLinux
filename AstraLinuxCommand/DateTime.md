### Как найти локальный сервер времени 
Определите установленный сервис.

Затем выполните проверку конкретных служб:

- Chrony (современный стандарт): systemctl status chronyd
- NTP (классический): systemctl status ntp
- systemd (встроенный): systemctl status systemd-timesyncd

Для Chrony (рекомендуется):

Откройте конфигурацию: ``sudo nano /etc/chrony/chrony.conf``

Добавьте строку, разрешающую доступ (например, для всей локальной сети 192.168.1.0/24):

```text
allow 192.168.1.0/24
```
Перезапустите службу: ``sudo systemctl restart chronyd``

Для NTP (ntpd):

Откройте конфигурацию: sudo nano /etc/ntp.conf

Добавьте или измените строки restrict:

```text
# Разрешить доступ клиентам из локальной сети
restrict 192.168.1.0 mask 255.255.255.0 nomodify notrap
```
Перезапустите службу: ``sudo systemctl restart ntp``

##### Проверка работоспособности
Убедитесь, что сервер отвечает на запросы:

- Если используете Chrony: chronyc sources -v
- Если используете NTP: ntpq -p
> - Если NTP не активен: Запустить синхронизацию проще всего через ``sudo timedatectl set-ntp true``

#####  Как узнать, работает ли ваш сервер?

Команда	|Что делает?	|Как интерпретировать
------|------|----------
chronyc tracking	|Показывает текущее состояние синхронизации	|Ищите Leap status: Normal и System time: с малыми значениями.
chronyc sources -v	|Список NTP-серверов, к которым ваш ПК обращается за временем	|Звездочка ^* в первом столбце означает, что сервер выбран основным.
systemctl status chronyd	|Проверяет, запущен ли сам сервис	|Должен быть статус active (running).

##### Настройка сервера (чтобы другие ПК видели его)

По умолчанию chrony работает только как клиент. Чтобы ваш ПК стал сервером, нужно выполнить два шага:

Разрешить доступ:

Откройте файл настроек: ``sudo nano /etc/chrony/chrony.conf``

Найдите секцию с allow. Если её нет — добавьте. Например, для всей локальной сети ``192.168.1.0/24``:

```text
allow 192.168.1.0/24
```
Без этой директивы chrony будет игнорировать входящие запросы.

Открыть порт в фаерволе:

NTP использует UDP-порт 123. Разрешите его (если включен фаервол):

```bash
sudo firewall-cmd --add-port=123/udp --permanent
sudo firewall-cmd --reload
(Для ufw: sudo ufw allow 123/udp)
```
Перезапустите сервис:

```bash
sudo systemctl restart chronyd
```
##### Как увидеть клиентов (кто подключился)
Чтобы убедиться, что ваш ПК работает как сервер, посмотрите список подключившихся клиентов с помощью команды:

```bash
chronyc clients
```
Она покажет IP-адреса и количество принятых пакетов. Если колонка NTP (количество пакетов) растет — всё работает идеально

#### Если нет доступа в интернет, нужно указать chrony использовать локальный источник времени (например, системные часы или аппаратный RTC) в качестве эталонного

**Вот два основных способа:**

**Способ 1.** Использовать локальные системные часы (самый простой)

Добавьте в конфигурационный файл /etc/chrony/chrony.conf следующие строки:

```text
# Отключаем поиск внешних серверов (закомментируйте или удалите строки pool/server)
# pool 0.pool.ntp.org iburst

# Используем локальные системные часы как источник
local stratum 10

# Разрешаем клиентам синхронизироваться с нами
allow 192.168.1.0/24
```
Что это даёт:

``local stratum 10`` — указывает chrony считать локальные часы эталонными с "уровнем точности" 10 (чем число меньше, тем точнее, 1-2 у GPS, 10 — для локальной сети без внешнего сигнала).

Без этой директивы chrony будет ждать синхронизации с внешним сервером бесконечно.

**Способ 2.** Использовать аппаратные часы (RTC) как источник

Если системные часы сильно уходят, можно заставить chrony читать время с материнской платы:

```text
# Используем RTC (часы на материнской плате) как источник
rtcfile /var/lib/chrony/chrony.rtc
local stratum 10
allow 192.168.1.0/24
```
Дополнительно синхронизируйте системные часы с RTC:

```bash
sudo hwclock --systohc
```
Важные моменты при работе без интернета

> - Проблема
> - Решение

Время на сервере сбито	Вручную установите примерное время: sudo date -s "2026-04-21 15:30:00"

Сервер перезагрузился и показывает 1970 год	Настройте автоматическое считывание RTC при загрузке: sudo hwclock --hctosys

Клиенты не синхронизируются	Проверьте, что клиенты указывают IP вашего сервера в server <IP-адрес> и открыт UDP порт 123

> - Проверка работы

После настройки выполните:

```bash
sudo systemctl restart chronyd
chronyc tracking
```
В выводе вы должны увидеть:

```text
Leap status    : Not synchronised
System time    : 0.000000000 seconds fast of NTP time
Last offset    : +0.000000000 seconds
RMS offset     : 0.000000000 seconds
Reference ID    : 0A0A0A0A (local #10)   # <- это важно
Stratum         : 10                      # <- наш локальный уровень
```
Значение Reference ID: local и Stratum: 10 подтверждают, что сервер работает в автономном режиме.

Ваш компьютер должен брать время с другого локального сервера внутри сети (а не из интернета).

Вот как это настроить в chrony:

1. Настройка клиента (вашего ПК)
Откройте файл /etc/chrony/chrony.conf:

bash
sudo nano /etc/chrony/chrony.conf
Закомментируйте или удалите все строки с pool и server, которые указывают на внешние серверы.

Добавьте строку с IP-адресом вашего локального NTP-сервера:

text
server 192.168.1.50 iburst
192.168.1.50 — замените на реальный IP вашего локального сервера времени

iburst — ускоряет первую синхронизацию (отправляет несколько запросов подряд)

2. Дополнительные параметры (опционально)
text
# Если локальный сервер может пропадать
server 192.168.1.50 iburst offline

# Разрешить chrony работать, даже если нет связи с сервером
local stratum 10
Параметр offline полезен для ноутбуков, которые часто меняют сеть.

3. Перезапустите chrony и проверьте
bash
sudo systemctl restart chronyd
chronyc sources -v
В выводе вы должны увидеть:

text
MS Name/IP address         Stratum Poll Reach LastRx Last sample
========================================================================
^* 192.168.1.50                 3   6   377    12   +0.002s[ +0.002s] +/- 0.015s
^* — означает, что этот сервер выбран основным (звёздочка очень важна)

Stratum — уровень сервера (чем меньше, тем точнее)

4. Если синхронизации нет
Симптом	Что проверить
В chronyc sources нет звёздочки ^*	Сервер недоступен или не отвечает — проверьте, работает ли на нём NTP
Появляется ? вместо IP	Не открыт UDP порт 123 на сервере
Reach равно 0	Сетевая проблема — проверьте ping до сервера
Ручная проверка соединения с сервером:

bash
chronyc -h 192.168.1.50 activity
Если команда зависает — сервер не отвечает.

5. Полная диагностика
bash
# Текущий статус синхронизации
chronyc tracking

# Какие серверы опрашиваются и их состояние
chronyc sources -v

# Подробная статистика по каждому источнику
chronyc sourcestats -v

#### Если не знаешь ip адрес локального сервера времени
Если IP-адрес неизвестен, но вы точно знаете, что в сети есть локальный сервер времени, можно воспользоваться автоматическим поиском. Вот три способа, от самого удобного до ручного:

1. Самый простой способ: multicastclient (рекомендую)
Самый элегантный метод — использовать многоадресную рассылку (multicast). Сервер сам "объявляет" о себе в сети, а клиент просто слушает.

Достаточно добавить в файл /etc/chrony/chrony.conf одну строчку:

text
multicastclient 224.0.1.1
Как это работает: Ваш компьютер автоматически найдет и начнет синхронизироваться с любым NTP-сервером в локальной сети, который вещает на этот адрес (это официальный адрес IANA для NTP) .

Важное условие: Этот способ сработает, только если администраторы уже настроили ваш локальный сервер времени на "вещание" (broadcast или manycastserver). Если нет, этот способ не даст результата.

2. Если у вас есть права администратора: Сканирование сети
Вы можете сами найти сервер, проверив все устройства в сети. Это полезно, если вы не уверены, настроен ли на сервере multicast.

Способ А: Используем ntpdate (быстрая проверка)
Эта команда пытается получить время с конкретного IP и сразу выводит результат. Самый быстрый способ "прощупать" подозрительный адрес.

bash
ntpdate -q 192.168.1.50  # Замените IP на адрес из вашей сети
Если на том конце есть NTP-сервер, вы увидите сообщение с offset и delay. Если нет — команда просто зависнет или выдаст ошибку no server suitable.

Способ Б: Полный перебор (Nmap)
Самый надежный способ, если нужно найти сервер вслепую.

Установите Nmap (если он еще не установлен):

bash
sudo apt install nmap   # Debian/Ubuntu
sudo yum install nmap   # CentOS/RHEL
Запустите сканирование UDP порта 123 в вашей локальной сети (например, 192.168.1.0/24):

bash
sudo nmap -sU -p 123 --script=ntp-info 192.168.1.0/24
Что произойдет: Nmap пройдется по всем устройствам в сети и покажет список тех, у кого открыт 123-й UDP порт и есть NTP-сервер .

3. Ручной метод: Проверка DHCP
Иногда адрес сервера времени передается автоматически при подключении к сети (по DHCP). Проверить это можно так:

bash
grep "ntp-servers" /var/lib/dhcp/dhclient.leases
Если сервер прописан там, вы увидите его IP-адрес. В этом случае можно просто указать его в chrony.conf.

Что делать, когда IP найден?
Как только вы получили IP-адрес (например, 192.168.1.100), просто укажите его в конфигурации /etc/chrony.conf, как мы обсуждали ранее:

text
server 192.168.1.100 iburst
После этого перезапустите chronyd и проверьте статус командой chronyc sources -v. В столбце MS должна появиться звездочка ^*.

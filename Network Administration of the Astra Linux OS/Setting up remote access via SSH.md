### Astra Linux: Настройка удаленного доступа по SSH
#### 1. Исследование алгоритмов Диффи-Хеллмана
**Протокол Диффи-Хеллмана (DH)** — это метод безопасного обмена криптографическими ключами по общедоступному (незащищённому) каналу связи. Он был одним из первых протоколов с открытым ключом и до сих пор широко используется в **SSH, TLS, IPsec** и других протоколах.

Суть проблемы, которую решает ``DH``: при необходимости зашифровать переписку две стороны должны договориться об общем секретном ключе. Если передать ключ по сети открыто, злоумышленник сможет его перехватить. ``DH`` позволяет выработать общий секрет, не передавая сам ключ по сети.

Принцип работы:

- Стороны договариваются об открытых параметрах: большое простое число p и генератор g.
- Каждая сторона генерирует свой закрытый ключ (случайное число): a и b.
- Вычисляются открытые ключи: A = g^a mod p и B = g^b mod p.
- Стороны обмениваются открытыми ключами A и B.
- Каждая сторона вычисляет общий секрет: K = B^a mod p = A^b mod p.

> В SSH протокол Диффи-Хеллмана используется для согласования сессионных ключей шифрования. Современные реализации SSH поддерживают различные варианты DH, включая эфемерный DH (DHE) и DH на эллиптических кривых (ECDH), которые обеспечивают совершенную прямую секретность (Perfect Forward Secrecy).

Проверка поддерживаемых алгоритмов в SSH:
```bash
ssh -Q kex
```
#### 2. Настройка службы sshd и клиента ssh
##### 2.1. Установка пакетов
Пакеты SSH входят в дистрибутивы Astra Linux, но по умолчанию устанавливается только клиент ``(openssh-client)``. Для установки сервера необходимо выполнить:
```bash
sudo apt install ssh
```
При установке пакета ssh устанавливаются и клиент, и сервер. Служба запускается автоматически и включается в автозагрузку.

Проверка состояния службы:
```bash
systemctl status ssh
```
Включение и запуск (при необходимости):
```bash
sudo systemctl enable ssh
sudo systemctl start ssh
```
##### 2.2. Настройка сервера sshd
Конфигурация сервера хранится в файле ``/etc/ssh/sshd_config``. После внесения изменений необходимо перезапустить службу:
```bash
sudo systemctl restart sshd
```
Рекомендуемые меры безопасности:
```bash
# Порт (рекомендуется сменить со стандартного 22 на нестандартный)
Port 2222

# Запрет прямого входа root
PermitRootLogin no

# Аутентификация только по ключам (после настройки ключей)
PubkeyAuthentication yes
PasswordAuthentication no
ChallengeResponseAuthentication no

# Ограничение пользователей, которым разрешён SSH
AllowUsers administrator operator

# Баннер для неавторизованных пользователей
Banner /etc/ssh/ssh_banner
```
Создание баннера:
```bash
sudo nano /etc/ssh/ssh_banner
```
Пример содержимого:
```text
*** ВНИМАНИЕ! Доступ к системе разрешён только авторизованным лицам. ***
*** Все действия протоколируются. Несанкционированный доступ преследуется по закону. ***
```
Проверка прослушиваемого порта:
```bash
sudo ss -tlnp | grep 2222
```
##### 2.3. Настройка клиента ssh
Конфигурация клиента хранится в файле ``/etc/ssh/ssh_config`` (глобальные настройки) или ``~/.ssh/config`` (пользовательские настройки).

Пример пользовательского конфига ``~/.ssh/config``:
```text
Host astra-server
    HostName 192.168.1.50
    Port 2222
    User administrator
    IdentityFile ~/.ssh/id_ed25519_astra
```
После этого подключение упрощается:
```bash
ssh astra-server
```
#### 3. Использование основных команд
##### 3.1. ssh — подключение к удалённому серверу
```bash
# Базовое подключение
ssh user@host

# Подключение на нестандартном порту
ssh -p 2222 user@host

# Подключение с указанием ключа
ssh -i ~/.ssh/id_ed25519 user@host

# Выполнение одной команды на удалённом сервере
ssh user@host "df -h"
```
##### 3.2. scp — копирование файлов
```bash
# Копирование файла на сервер
scp file.txt user@host:/path/to/destination/

# Копирование файла с сервера
scp user@host:/path/to/file.txt ./

# Копирование каталога рекурсивно
scp -r /local/dir user@host:/remote/dir

# Копирование на нестандартном порту
scp -P 2222 file.txt user@host:/path/
```
##### 3.3. sftp — интерактивная передача файлов
```bash
sftp user@host
```
Основные команды внутри ``sftp``:

```text
ls          # список файлов на удалённой машине
lls         # список файлов на локальной машине
cd /path     # переход по удалённому каталогу
lcd /path    # переход по локальному каталогу
get file.txt # скачать файл
put file.txt # загрузить файл
bye         # выход
```
##### 3.4. sshfs — монтирование удалённой файловой системы
SSHFS позволяет смонтировать удалённый каталог через SSH/SFTP как локальную файловую систему. Это удобно для частого редактирования файлов «на месте».

Установка:
```bash
sudo apt install sshfs
```
Монтирование:
```bash
mkdir ~/mnt/server
sshfs user@host:/remote/path ~/mnt/server
```
Монтирование с указанием порта:
```bash
sshfs user@host:/remote/path ~/mnt/server -o port=2222
```
Размонтирование:
```bash
fusermount -u ~/mnt/server
```
Команда fusermount -u используется для размонтирования FUSE-файловых систем, включая SSHFS, от имени обычного пользователя.

#### 4. Настройка аутентификации по ключам
Аутентификация по ключам безопаснее парольной и позволяет подключаться без ввода пароля.

##### 4.1. Генерация ключевой пары
На клиентской машине:
```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_astra -C "admin@workstation"
```
Рекомендуется использовать тип ed25519 — он современнее и быстрее, чем RSA.

##### 4.2. Копирование открытого ключа на сервер
```bash
ssh-copy-id -i ~/.ssh/id_ed25519_astra.pub -p 2222 administrator@192.168.1.50
```
Если ssh-copy-id недоступен, можно вручную добавить содержимое .pub-файла в ~/.ssh/authorized_keys на сервере:
```bash
cat ~/.ssh/id_ed25519_astra.pub | ssh user@host "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```
##### 4.3. Проверка подключения
```bash
ssh -i ~/.ssh/id_ed25519_astra -p 2222 administrator@192.168.1.50
```
После успешной проверки можно отключить парольный вход в sshd_config (параметр PasswordAuthentication no) и перезапустить службу.

##### 4.4. Права доступа
Важно соблюдать права на файлы:
```txt
~/.ssh — 700
~/.ssh/authorized_keys — 600
домашний каталог — 755
```
```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```
#### 5. Настройка перенаправления портов
SSH позволяет создавать туннели для перенаправления трафика. Это используется для безопасного доступа к сервисам, не имеющим шифрования (VNC, базы данных, веб-интерфейсы).

##### 5.1. Локальное перенаправление (-L)
Трафик с локального порта перенаправляется через SSH-сервер к целевому хосту.
```bash
ssh -L 5900:127.0.0.1:5900 user@host
```
После этого можно подключиться к localhost:5900 на клиентской машине, и трафик пойдёт через SSH-туннель к VNC-серверу на удалённой машине.

Пример для базы данных:
```bash
ssh -L 5432:localhost:5432 user@host
# Теперь можно подключиться к PostgreSQL на localhost:5432
```
##### 5.2. Удалённое перенаправление (-R)
Трафик с удалённого порта перенаправляется на локальную машину.
```bash
ssh -R 8080:localhost:80 user@host
Теперь порт 8080 на удалённом сервере будет перенаправлять трафик на порт 80 локальной машины.
```
##### 5.3. Динамическое перенаправление (-D)
Создаёт SOCKS-прокси для динамического перенаправления.
```bash
ssh -D 1080 user@host
После этого можно настроить браузер на использование SOCKS-прокси localhost:1080.
```
#### 6. Практическое решение по всем разделам
Сценарий: Настройка безопасного удалённого доступа к серверу Astra Linux
Исходные данные:
```txt
Сервер Astra Linux: 192.168.1.50
Клиент: рабочая станция администратора
Требуется: доступ по SSH только по ключам, смена порта, туннель для VNC
```
##### Шаг 1. Настройка сервера
```bash
sudo apt install ssh
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.backup
sudo nano /etc/ssh/sshd_config
```
Вносим изменения:
```text
Port 2222
PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
AllowUsers administrator
Banner /etc/ssh/ssh_banner
```
```bash
sudo systemctl restart sshd
sudo ss -tlnp | grep 2222
```
##### Шаг 2. Генерация ключей на клиенте
```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_astra -C "admin@workstation"
ssh-copy-id -i ~/.ssh/id_ed25519_astra.pub -p 2222 administrator@192.168.1.50
```
##### Шаг 3. Проверка подключения
```bash
ssh -i ~/.ssh/id_ed25519_astra -p 2222 administrator@192.168.1.50
```
##### Шаг 4. Настройка VNC через SSH-туннель

На сервере:
```bash
sudo apt install x11vnc
x11vnc -storepasswd ~/.vnc/passwd
x11vnc -display :0 -auth guess -forever -loop -rfbauth ~/.vnc/passwd -rfbport 5900 -localhost
```
На клиенте:
```bash
ssh -i ~/.ssh/id_ed25519_astra -p 2222 -L 5900:127.0.0.1:5900 administrator@192.168.1.50
Затем подключаемся VNC-клиентом к localhost:5900.
```
##### Шаг 5. Монтирование удалённого каталога
```bash
sudo apt install sshfs
mkdir ~/mnt/astra
sshfs administrator@192.168.1.50:/home/administrator ~/mnt/astra -o port=2222
# Работа с файлами...
fusermount -u ~/mnt/astra
```
#### 7. Устранение распространённых проблем
Симптом	                                | Вероятная причина	                         | Решение
--------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------
После отключения паролей невозможно подключиться	 | Ключ не добавлен в authorized_keys или неверные права	 | Проверить права: ~/.ssh — 700, authorized_keys — 600
Connection refused	 | Служба sshd не запущена или порт закрыт	 | systemctl status ssh, проверить порт через ss -tlnp
Permission denied (publickey)	 | Неверный ключ или не тот пользователь	 | Указать ключ явно: ssh -i ~/.ssh/key user@host
SSHFS не монтируется	 | Не установлен sshfs или нет прав на точку монтирования	 | sudo apt install sshfs, проверить владельца точки монтирования

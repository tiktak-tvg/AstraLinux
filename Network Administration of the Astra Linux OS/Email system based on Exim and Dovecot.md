### Система электронной почты на базе Exim и Dovecot в Astra Linux
### 1. Принципы функционирования СЭП
*Система электронной почты (СЭП)* — это комплекс программных средств, обеспечивающих приём, передачу, маршрутизацию, доставку и хранение сообщений электронной почты. Работа СЭП основана на клиент-серверной модели и включает несколько ключевых процессов:

- Отправка сообщения — пользователь формирует письмо в почтовом клиенте (MUA), который передаёт его на сервер исходящей почты по протоколу SMTP.
- Маршрутизация — сервер исходящей почты (MTA) определяет, куда доставить сообщение, используя DNS-записи MX для домена получателя.
- Доставка — MTA передаёт сообщение на сервер получателя, где агент доставки (MDA) раскладывает его в почтовый ящик.
- Получение — получатель забирает почту из своего ящика с помощью почтового клиента по протоколу IMAP.

В защищённом исполнении Astra Linux СЭП дополнительно обеспечивает поддержку классификационных меток (мандатного контекста) для разграничения доступа к почтовым сообщениям в соответствии с уровнями конфиденциальности.

### 2. Компоненты СЭП и их назначение
Защищенный комплекс программ электронной почты в Astra Linux состоит из следующих пакетов:

Компонент	          | Пакет	                | Назначение
------------------- | --------------------- | ----------------------------
MTA (Mail Transfer Agent)	exim4-daemon-heavy	  | Агент передачи сообщений Exim4.   | Обеспечивает приём и отправку почты по SMTP, маршрутизацию, работу с классификационными метками. Пакет exim4-daemon-light не поддерживает работу с метками, отличными от 0:0
MDA (Mail Delivery Agent)	dovecot-imapd	 | Агент доставки сообщений Dovecot.    | Работает только по протоколу IMAP, протокол POP3 отключён
MUA (Mail User Agent)	thunderbird	  | Клиент электронной почты  | Mozilla Thunderbird для получения, создания, отправки и хранения сообщений

Серверная часть использует в качестве почтового хранилища формат ``MailDir`` (в каталоге ``/var/mail/$u``, где ``$u`` — локальная часть адреса). Формат ``mailbox`` не поддерживает работу с классификационными метками, отличными от 0:0.

### 3. Протоколы SMTP/ESMTP и IMAP
#### 3.1. SMTP/ESMTP
*SMTP (Simple Mail Transfer Protocol)* — протокол передачи почтовых сообщений между серверами и от клиента к серверу. Работает поверх TCP, стандартный порт — 25 (для приёма), 587 (для отправки с аутентификацией).

*ESMTP (Extended SMTP)* — расширенная версия ``SMTP``, поддерживающая аутентификацию, шифрование ``(STARTTLS)``, передачу вложений и другие возможности. Именно ``ESMTP`` используется в современных почтовых системах.

#### 3.2. IMAP
*IMAP (Internet Message Access Protocol)* — протокол доступа к почтовым ящикам, позволяющий клиенту работать с сообщениями непосредственно на сервере (просматривать, перемещать, удалять, искать). Стандартный порт — 143, защищённый (IMAPS) — 993.

В защищённом комплексе ``Astra Linux Dovecot`` работает только по протоколу ``IMAP``, протокол ``POP3`` отключён.

#### 3.3. Использование DNS для передачи почтовых сообщений
При отправке почты сервер отправителя выполняет ``DNS-запрос MX-записи (Mail Exchange)`` для домена получателя. 

MX-запись указывает на почтовый сервер, который принимает почту для данного домена. 

Если MX-запись отсутствует, отправитель может попытаться доставить почту напрямую на A-запись домена.

### 4. Установка и настройка защищённого комплекса программ электронной почты
#### 4.1. Предварительные требования
Предполагается, что уже установлен сервер контроллера домена ``FreeIPA`` с именем домена, например ``astra.mta``. Почтовый сервер располагается на отдельном компьютере, введённом в домен, с постоянным IP-адресом (например, ``192.168.32.3 в сети 192.168.32.0/24``).

> Важно: Располагать почтовый сервер непосредственно на доменном контроллере возможно, но не рекомендуется, так как это повышает уязвимость контроллера и может негативно влиять на его производительность.

#### 4.2. Установка пакетов
```bash
sudo apt install exim4-daemon-heavy dovecot-imapd dovecot-gssapi
```
Устанавливаемые пакеты:

*exim4-daemon-heavy* — агент передачи сообщений СЭП (MTA) — Exim4 с поддержкой мандатного контекста;

*dovecot-imapd* — агент доставки сообщений СЭП (MDA) — Dovecot;

*dovecot-gssapi* — модуль поддержки GSSAPI-аутентификации для MDA Dovecot.

#### 4.3. Настройка Dovecot
В файл ``/etc/dovecot/conf.d/10-master.conf`` в секцию ``service auth`` добавляется подсекция для обеспечения взаимодействия с Exim:

```text
unix_listener auth-client {
    mode = 0600
    user = Debian-exim
}
```
В файле ``/etc/dovecot/dovecot.conf`` задаётся список интерфейсов для приёма соединений и устанавливается протокол IMAP:

```text
protocols = imap
listen = 192.168.2.55
```
Для настройки аутентификации через Kerberos (GSSAPI) в файле ``/etc/dovecot/conf.d/10-auth.conf`` устанавливаются параметры:

```text
disable_plaintext_auth = yes
auth_gssapi_hostname = exim1.astra.mta
auth_krb5_keytab = /var/lib/dovecot/dovecot.keytab
auth_mechanisms = gssapi
```
После внесения изменений Dovecot перезапускается:

```bash
sudo systemctl restart dovecot
```
#### 4.4. Настройка Exim4
Для настройки аутентификации в Exim создаётся конфигурационный файл ``/etc/exim4/conf.d/auth/33_exim4-dovecot-kerberos-ipa`` со следующим содержимым:

```text
dovecot_gssapi:
    driver = dovecot
    public_name = GSSAPI
    server_socket = /var/run/dovecot/auth-client
    server_set_id = $auth1
```
Для запрета отправки писем без аутентификации в файл ``/etc/exim4/conf.d/acl/30_exim4-config_check_rcpt`` в начало секции ``acl_check_rcpt`` добавляются строки:

```text
deny message = "Auth required"
    hosts = *:+relay_from_hosts
    !authenticated = *
```
Запуск и включение автозагрузки Exim4:

```bash
sudo systemctl start exim4
sudo systemctl enable exim4
```
#### 4.5. Настройка клиента Thunderbird
Первичное создание учетной записи сервера электронной почты в ``MUA Mozilla Thunderbird`` должно производиться с нулевой классификационной меткой (уровень конфиденциальности 0, категорий нет). Далее для каждой конкретной классификационной метки создание учётной записи необходимо повторить.

При настройке учётной записи выбирается тип сервера входящей почты IMAP. В параметрах сервера и сервера исходящей почты устанавливаются:

- «Защита соединения» — «Нет»;
- «Метод аутентификации» — «Обычный пароль».

### 5. Интеграция СЭП с FreeIPA с поддержкой мандатного управления доступом
#### 5.1. Настройка аутентификации через Kerberos
Для обеспечения совместной работы с ``FreeIPA`` должны быть установлены: ``exim4-daemon-heavy, dovecot-imapd, dovecot-gssapi и thunderbird``.

На контроллере домена ``FreeIPA`` создаются принципалы для служб ``IMAP и SMTP`` и выгружаются ``keytab-файлы``:

```bash
sudo kinit admin
sudo ipa-getkeytab --principal=imap/exim1.astra.mta@ASTRA.MTA \
  --keytab=/var/lib/dovecot/dovecot.keytab
sudo ipa-getkeytab --principal=smtp/exim1.astra.mta@ASTRA.MTA \
  --keytab=/var/lib/dovecot/dovecot.keytab
```
Проверка таблицы ключей:

```bash
sudo klist -k /var/lib/dovecot/dovecot.keytab
```
Выдача прав пользователю dovecot на чтение файла ключа:

```bash
sudo setfacl -m u:dovecot:x /var/lib/dovecot
sudo setfacl -m u:dovecot:r /var/lib/dovecot/dovecot.keytab
```
#### 5.2. Поддержка мандатного управления доступом
При использовании защищённого комплекса программ электронной почты из состава ОС в режиме мандатного управления доступом конфигурационные параметры агента передачи электронной почты ``Exim`` и агента доставки ``Dovecot`` должны учитывать классификационные метки.

Для нормальной работы пользователя с сетевыми службами должна быть явно задана его классификационная метка (диапазон уровней конфиденциальности и категорий конфиденциальности) с помощью соответствующих утилит, даже если ему не доступны уровни и категории выше 0.

``MTA Exim4`` с поддержкой мандатного контекста обеспечивает маркировку почтовых сообщений в соответствии с меткой отправителя, а ``MDA Dovecot`` — доступ к почтовым ящикам с учётом мандатных ограничений пользователя.

#### 5.3. Схема интеграции
```text
┌─────────────────────────────────────────────────────────────┐
│                     Контроллер домена FreeIPA                │
│  • LDAP (389 Directory Server) — хранение учётных записей   │
│  • Kerberos KDC — выдача билетов, аутентификация GSSAPI     │
│  • DNS — MX-записи, разрешение имён                         │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ Kerberos / GSSAPI
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      Почтовый сервер                          │
│  • Exim4 (MTA) — приём/отправка почты, SMTP                 │
│  • Dovecot (MDA) — хранение и доступ к почте, IMAP          │
│  • Мандатный контекст — метки конфиденциальности            │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ IMAP / SMTP
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     Рабочая станция                           │
│  • Mozilla Thunderbird (MUA) — работа с почтой              │
│  • Учётная запись с классификационной меткой                │
└─────────────────────────────────────────────────────────────┘
```

### Прокси-сервер SQUID в Astra Linux
#### 1. Возможности SQUID
**Squid** — это программный пакет, реализующий функцию кэширующего прокси-сервера для протоколов ``HTTP, FTP, Gopher и (при соответствующей настройке) HTTPS``. Разработан как программа с открытым исходным кодом и распространяется в соответствии с ``GNU GPL``.

Основные возможности:

*Кэширование* — сохранение часто запрашиваемых веб-страниц и файлов для ускорения доступа и снижения нагрузки на канал.

*Управление доступом* — гибкая система списков ACL (Access Control Lists) для разграничения доступа к интернет-ресурсам.

*Аутентификация пользователей* — поддержка базовой NCSA-аутентификации, Kerberos, LDAP и других механизмов.

*«Нарезка» трафика* — возможность ограничения полосы пропускания для различных пользователей.

*Взаимодействие с доменными службами* — аутентификация через LDAP позволяет использовать учётные записи Windows Server.

*Работа как единый неблокируемый процесс* — все запросы обрабатываются одним процессом ввода-вывода.

Squid входит в дистрибутивы Astra Linux, но по умолчанию не устанавливается.

#### 2. Установка и минимальная настройка SQUID
##### 2.1. Установка
```bash
sudo apt install squid
```
После установки сервис запускается автоматически, однако для работы требует настройки.

Для установки с поддержкой OpenSSL (например, для перехвата HTTPS-трафика):

```bash
sudo apt install squid-openssl
```
##### 2.2. Минимальная настройка
Параметры настройки пакета squid хранятся в файле /etc/squid/squid.conf. Из важнейших параметров можно отметить:

Параметр	      | Назначение	          | Значение по умолчанию
--------------- | --------------------- | --------------------
http_port	 | Порт для подключения к серверу	 | 3128
http_access	 | Разрешение на доступ к серверу	— (доступ запрещён всем)  | 

> Важно: http_access — это единственный параметр, который требует обязательной настройки, так как по умолчанию доступ запрещён всем.

Простейшая настройка — разрешить доступ всем. Для этого в файл конфигурации добавляется строка:

```text
http_access allow all
```
После изменения параметров для вступления изменений в силу требуется перезапустить сервис:

```bash
sudo systemctl restart squid
```
Перезапуск сервиса с настройками «по умолчанию» занимает около 35 секунд.

#### 3. Общие параметры настройки
Основные параметры в ``/etc/squid/squid.conf``, которые чаще всего требуют настройки:

Параметр	      | Описание
--------------- | ---------------------
http_port 3128	 | Порт, через который осуществляется подключение к серверу
http_access allow/deny	 | Правила доступа к серверу
visible_hostname	  | Имя хоста, отображаемое в сообщениях об ошибках
cache_mem	  | Объём оперативной памяти для кэша (по умолчанию 256 МБ)
cache_dir	  | Каталог и размер дискового кэша
acl	         | Определение списков управления доступом
auth_param	 | Параметры аутентификации
cache_mgr	  | Email администратора кэша
access_log	 | Путь к журналу доступа

Пример базовой конфигурации:

```text
http_port 3128
visible_hostname proxy.localnet
cache_mem 512 MB
cache_dir ufs /var/spool/squid 10000 16 256
acl localnet src 192.168.32.0/24
http_access allow localnet
http_access allow localhost
http_access deny all
```
#### 4. Списки доступа (ACL)
Для управления доступом ``squid`` поддерживает работу со списками управления доступом ``(Access Control Lists, ACL)``.

Основы синтаксиса ACL:

```text
acl имя_списка тип_acl значение1 значение2 ...
http_access allow|deny имя_списка
```
Примеры ACL:

Определение списка портов:

```text
acl Safe_ports port 80 21 443 563 70 210 1025-65535 280 488 591 777
```
Пример применения:

```text
# запретить работу со всеми портами, кроме безопасных
http_access deny !Safe_ports
```
Блокировка определённых сайтов:

```text
acl blocksite1 dstdomain telegram.com
http_access deny blocksite1
```
Блокировка по ключевым словам в URL:

```text
acl blockkeyword1 url_regex telegram
acl blockkeyword2 url_regex google
http_access deny blockkeyword1
http_access deny blockkeyword2
```
Использование внешнего файла для списка блокировки:

```text
acl blocksitelist dstdomain "/etc/squid/blockwebsites.lst"
http_access deny blocksitelist
```
Содержимое файла ``/etc/squid/blockwebsites.lst`` — по одному домену на строку.

Блокировка по IP-адресам:

```text
acl bad_hosts src 10.0.0.5 10.0.0.10
http_access deny bad_hosts
```
Разрешение доступа только для определённой подсети:

```text
acl localnet src 192.168.1.0/24
acl localnet src 10.0.0.0/8
http_access allow localnet
http_access deny all
```
#### 5. Аутентификация пользователей
##### 5.1. Базовая аутентификация NCSA
В простейшем случае хранение паролей осуществляется в текстовом файле, содержащем учётные данные, закодированные в base64. Для обработки этого файла используется дополнительная программа /usr/lib/squid3/basic_ncsa_auth, проверяющая соответствие переданной комбинации «логин:пароль» хранящимся в файле данным.

Настройка конфигурации (файл паролей /etc/squid/users):

```text
auth_param basic program /usr/lib/squid3/basic_ncsa_auth /etc/squid/users
acl lan proxy_auth REQUIRED
http_access allow lan
```
Здесь ``acl lan proxy_auth REQUIRED`` создаёт список доступа, в который включены все прошедшие аутентификацию пользователи, а ``http_access allow lan`` разрешает им доступ к интернету.

Создание файла паролей с помощью утилиты ``htpasswd``:

Утилита ``htpasswd`` входит в состав пакета ``apache2-utils``. Синтаксис команды:

```bash
htpasswd [-c] /создаваемый/файл/паролей имя_пользователя
Параметр -c используется для создания нового файла; изменение существующего файла производится без этого параметра.
```
Установка прав доступа:

```bash
chmod 440 /etc/squid/users
chown proxy:proxy /etc/squid/users
```
Это необходимо, чтобы файл был доступен только пользователю и группе, от имени которой работает ``Squid``.

Важное предупреждение по безопасности:

Базовая аутентификация передаёт учётные данные в кодировке Base64, а не в зашифрованном виде. При использовании обычного HTTP-прокси они могут быть легко восстановлены любым, кто находится на пути следования трафика. NCSA-аутентификацию следует использовать только в доверенной локальной сети или в сочетании с TLS до прокси-сервера.

##### 5.2. Авторизация через Kerberos
Для интеграции с доменом ``FreeIPA в Astra Linux`` настраивается авторизация через ``Kerberos``. В этом случае в файле ``/etc/squid/squid.conf`` комментируются строки:

```text
#http_access allow localnet
#http_access allow localhost
```
И добавляются строки для включения авторизации через Kerberos.

#### 6. Генерация отчётов (cachemgr)
**Cache Manager (cachemgr.cgi)** — это CGI-утилита для отображения статистики о работе прокси-сервера Squid в реальном времени.

Настройка доступа к Cache Manager:

В файле ``/etc/squid/squid.conf`` добавляется ACL для доступа к кэш-менеджеру:

```text
acl manager proto cache_object
acl localhost src 127.0.0.1/32
http_access allow localhost manager
http_access deny manager
```
Использование Cache Manager:

Доступ к отчётам осуществляется через веб-интерфейс по адресу:

```text
http://webserver.example.org/squid/cgi-bin/cachemgr.cgi
```
После подключения можно выбрать сервер ``Squid`` и просмотреть различные статистические отчёты.

Основные отчёты ``Cache Manager`:

Отчёт   	      | Описание
--------------- | ---------------------
info	          | Общая информация о кэше, включая hit rate (процент попаданий)
mem	            | Использование оперативной памяти
disk	          | Использование дискового пространства
squid.conf	    | Текущая конфигурация (без комментариев)
menu	          | Главное меню Cache Manager
shutdown	      | Корректное завершение работы Squid

Для программного доступа к отчётам без входа на сервер используется утилита squidclient:

```bash
squidclient -h localhost mgr:info
squidclient -h localhost mgr:mem
squidclient -h localhost mgr:disk
```
#### 7. Диагностика и поиск неисправностей
##### 7.1. Основные журналы
Squid ведёт два основных журнала:
```txt
/var/log/squid/access.log — журнал доступа (все запросы клиентов)

/var/log/squid/cache.log — журнал работы самого прокси-сервера (ошибки, предупреждения)
```
Для просмотра в реальном времени используется команда tail -f:

```bash
sudo tail -f /var/log/squid/access.log
sudo tail -f /var/log/squid/cache.log
```
##### 7.2. Типичные проблемы
**Proxy Access Denied**

Если клиент получает ошибку ``Proxy Access Denied``, необходимо проверить настройки ``http_access`` и убедиться, что IP-адреса клиентов разрешены. Также следует проверить правильность настройки ACL — ошибка может быть в конфигурации одного из списков доступа.

**Too many open files**

Сообщение об ошибке **Too many open files** указывает на исчерпание файловых дескрипторов. Это может быть вызвано низким лимитом файловых дескрипторов в операционной системе. Существует два способа исчерпания: достижение лимита на процесс или достижение системного лимита на общее количество файловых дескрипторов для всех процессов.

Для решения проблемы необходимо увеличить лимит:

```bash
ulimit -HS -n 65536
```
Также необходимо проверить стартовые скрипты Squid на предмет установки низкого лимита.

**Проблемы с DNS**

Если Squid перестаёт работать через короткое время после запуска, следует проверить наличие неверной записи nameserver в файле ``/etc/resolv.conf`` или отсутствие самого файла.

**Ошибки конфигурации**

При изменении ``squid.conf`` рекомендуется проверять синтаксис перед перезапуском:

```bash
sudo squid -k parse
```
Эта команда проверяет конфигурационный файл на наличие ошибок без применения изменений.

##### 7.3. Проверка состояния службы
```bash
# Проверка статуса службы
sudo systemctl status squid

# Проверка, что Squid работает
sudo squid -k check
```
Если команда возвращает ``Squid Cache: Running``, значит, ``Squid`` работает.

Безопасный перезапуск:

```bash
sudo systemctl restart squid
```
При безопасном перезапуске ``Squid`` запускает новый процесс, сохраняя старый активным до закрытия всех активных соединений.

##### 7.4. Проверка прослушиваемых портов
```bash
sudo ss -tlnp | grep :3128
```
##### 7.5. Дополнительные диагностические команды
```bash
# Просмотр кэша в реальном времени
sudo squidclient -h localhost mgr:info

# Проверка активных соединений
sudo ss -tnp | grep squid

# Мониторинг трафика
sudo iftop -i eth0 -f "port 3128"
```
#### 8. Практическое решение: настройка прокси-сервера с аутентификацией
**Сценарий**
Настроить прокси-сервер ```Squid на Astra Linux для подсети 192.168.32.0/24`` с обязательной аутентификацией пользователей по NCSA и блокировкой нежелательных сайтов.

##### Этап 1. Установка Squid
```bash
sudo apt update
sudo apt install squid apache2-utils
```
##### Этап 2. Создание файла паролей
```bash
sudo htpasswd -c /etc/squid/users user1
sudo htpasswd /etc/squid/users user2
sudo chmod 440 /etc/squid/users
sudo chown proxy:proxy /etc/squid/users
```
##### Этап 3. Создание файла блокировки сайтов
```bash
sudo nano /etc/squid/blockwebsites.lst
```
Содержимое (пример):
```text
telegram.com
facebook.com
twitter.com
```
##### Этап 4. Редактирование конфигурации
```bash
sudo nano /etc/squid/squid.conf
```
Внести следующие изменения:
```text
http_port 3128
visible_hostname proxy.localnet
cache_mem 256 MB
cache_dir ufs /var/spool/squid 5000 16 256

# Аутентификация
auth_param basic program /usr/lib/squid3/basic_ncsa_auth /etc/squid/users
auth_param basic realm "Proxy Authentication"
acl authenticated proxy_auth REQUIRED

# Локальная сеть
acl localnet src 192.168.32.0/24

# Блокировка сайтов
acl blocksitelist dstdomain "/etc/squid/blockwebsites.lst"

# Безопасные порты
acl Safe_ports port 80 21 443 563 70 210 1025-65535 280 488 591 777
acl CONNECT method CONNECT

# Правила доступа
http_access deny !Safe_ports
http_access deny blocksitelist
http_access allow localnet authenticated
http_access allow localhost
http_access deny all
```
##### Этап 5. Проверка и перезапуск
```bash
sudo squid -k parse
sudo systemctl restart squid
sudo systemctl enable squid
```
##### Этап 6. Настройка клиентов
На клиентских машинах в настройках браузера или системы указывается:
```txt
Прокси-сервер: 192.168.32.211

Порт: 3128
```
Имя пользователя / пароль: учётные данные, созданные через htpasswd

##### Этап 7. Диагностика
```bash
# Просмотр журнала доступа
sudo tail -f /var/log/squid/access.log

# Просмотр журнала ошибок
sudo tail -f /var/log/squid/cache.log

# Проверка состояния кэша
sudo squidclient -h localhost mgr:info

# Проверка, что служба работает
sudo systemctl status squid
```
#### 9. Устранение распространённых проблем
Симптом	             | Вероятная причина	             | Решение
-------------------- | ------------------------------- | ---------------------------------------------
Proxy Access Denied	 | Неправильные правила http_access или ACL	 | Проверить squid.conf, убедиться, что IP клиентов разрешены
Too many open files	 | Исчерпаны файловые дескрипторы	 | Увеличить ulimit и проверить стартовые скрипты
Squid не запускается	 | Ошибка в конфигурации	 | Проверить sudo squid -k parse
Аутентификация не работает	 | Неверный путь к basic_ncsa_auth или права на файл	 | Проверить путь /usr/lib/squid3/basic_ncsa_auth и права chmod 440
Клиенты не могут подключиться	 | Порт 3128 закрыт в firewall	 | Открыть порт: sudo ufw allow 3128/tcp
Проблемы с DNS	 | Неверный nameserver в /etc/resolv.conf	 | Проверить файл и корректность записей DNS

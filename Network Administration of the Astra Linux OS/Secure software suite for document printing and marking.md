### Защищенный комплекс программ для печати и маркировки документов в Astra Linux
#### 1. Состав и архитектура системы печати
Защищенный комплекс программ печати и маркировки документов в Astra Linux реализован на базе *CUPS (Common Unix Printing System) версии 2.3.3*. Важно отметить, что версия *CUPS в Astra Linux Common Edition 2.12* не обеспечивает маркировку выводимых на печать документов — для полноценной работы с маркировкой требуется* Astra Linux Special Edition*.

Сервер печати CUPS входит в стандартный дистрибутив *Astra Linux Special Edition РУСБ.10015-01* (начиная с очередного обновления 1.6) и автоматически устанавливается и запускается при инсталляции ОС.

Крупноблочная архитектура CUPS включает следующие компоненты:

Компонент	           | Назначение
-------------------- | ---------------------
Диспетчер печати (cupsd)	 | Служба-демон, обрабатывающая запросы от пользователя и выполняющая запуск служебных программ
Система фильтров	 | Преобразование документов из формата приложения в формат, понятный принтеру (обычно PostScript)
Система передачи данных (бэкенд)	 | Отправка печатаемых данных устройству (через параллельный, последовательный, USB-интерфейс или по сети)

Дополнительно в состав комплекса входят:
```txt
- Пакет parsec-cups — устанавливается по умолчанию при установке ОС и обеспечивает выполнение маркировки документов.
- Утилиты управления:
                     fly-admin-printer (администратор печати),
                     fly-jobviewer (очередь печати),
                     fly-print-station (управление печатью документов с маркировкой),
                     markjob (командная строка для маркировки).
```
```txt
Конфигурационные файлы: 
                     /etc/cups/cupsd.conf (основная конфигурация сервера), 
                     /etc/cups/cups-files.conf (системные группы и файлы), 
                     /etc/cups/marker.template (формат маркеров), 
                     /etc/cups/cups-marker-vars.conf (переменные маркировки).
```
#### 2. Установка и настройка службы CUPS
#### 2.1. Установка
В Astra Linux Special Edition сервер CUPS уже установлен и запущен. Проверить статус можно командой:

```bash
systemctl status cups
```
Если требуется установка вручную (например, в Common Edition), выполняется:

```bash
sudo apt install cups
```
Дополнительно могут потребоваться драйверы и утилиты:

```bash
sudo apt install cups hplip ghostscript printer-driver-gutenprint
```
#### 2.2. Настройка удалённого доступа
Для включения удалённого администрирования сервера печати необходимо отредактировать файл ``/etc/cups/cupsd.conf``. В конфигурационном файле рекомендуется удалить строку ``Port 631 и вставить Listen 0.0.0.0:631``. Значение параметра ``DefaultAuthType`` должно быть ``Basic``.

Альтернативно можно использовать команды cupsctl:

```bash
sudo cupsctl --remote-admin --share-printers --remote-any
sudo cupsctl ServerAlias=*
```
#### 2.3. Основные параметры cupsd.conf

Параметр	           | Назначение
-------------------- | ---------------------
Listen	             | Адрес и порт прослушивания (например, Listen 0.0.0.0:631)
DefaultAuthType	     | Тип аутентификации по умолчанию (Basic или Negotiate для Kerberos)
ServerName	         | Имя хоста сервера печати
MacEnable	           | Включение/отключение механизмов мандатного контроля (on/off)
MacMarkZeroLabel	   | Маркировка документов с нулевой меткой безопасности (on/off)
MacAudit	           | Ведение журнала подсистемы регистрации событий (on/off)

Проверка корректности конфигурации:

```bash
sudo cupsd -t
```
Перезапуск службы:

```bash
sudo systemctl restart cups
```
#### 2.4. Группы пользователей
*lpadmin* — пользователи с правами администрирования сервера печати (настройка принтеров).

*lpmac (или lpmac_ald в домене ALD)* — пользователи с правами маркировки заданий. В Astra Linux Special Edition 1.6 и x.7 группа lpmac создаётся по умолчанию, либо может быть создана командой sudo groupadd lpmac.

В файле ``/etc/cups/cups-files.conf`` в параметре SystemGroup указываются группы администраторов печати. Для работы в домене FreeIPA рекомендуется заменить строку:

```text
SystemGroup lpadmin
```
на:

```text
SystemGroup lpadmin print_admins
```
где ``print_admins`` — доменная группа администраторов печати.

#### 3. Настройка клиента службы печати
Первым шагом как для сервера, так и для клиента является подключение принтера (регистрация в CUPS). Процедура одинакова для сервера и клиента.

#### 3.1. Добавление принтера через графический инструмент
Запустите ``fly-admin-printer («Пуск» → «Панель управления» → «Оборудование» → «Принтеры»)``. Выберите меню ``«Принтер» → «Добавить» → «Далее»``. Система выполнит автоматический поиск доступных принтеров. После завершения поиска выберите нужный принтер из списка. Для совместного использования на сервере включите ``checkbox «Разрешить общий доступ»``. Для редакций Astra Linux SE после добавления принтера убедитесь, что во вкладке MAC выставлены: политика операций ``«default»`` и нулевые минимальные и максимальные уровни заданий.

#### 3.2. Добавление принтера через web-интерфейс
Откройте страницу ``http://localhost:631/admin``, перейдите во вкладку ``«Администрирование»``, нажмите ``«Добавить принтер»``. Если принтер найден автоматически — выберите его из списка. Если нет — выберите протокол в списке ``«Другие сетевые принтеры»``, задайте адрес принтера, параметры, производителя и тип.

#### 3.3. Автоматическое добавление сетевых принтеров
Для автоматизации подключения разделяемых принтеров (включая не поддерживающие DNS-SD/Bonjour) можно использовать пакет cups-browsed.

#### 4. Управление очередями, принтерами и заданиями
Конфигурационный файл сервера CUPS определяет все свойства управления доступом. Очередь печати — механизм, позволяющий буферизовать и организовать задания, посылаемые на принтер. Для этого используется буферный каталог ``/var/spool/cups/``.

Классы принтеров — наборы принтеров. Задания, посланные классу принтеров, направляются к первому доступному принтеру данного класса.

#### 4.1. Управление заданиями
Управление заданиями включает: формирование, передачу серверу печати, мониторинг и управление заданиями в очереди на печать.

Основные команды управления:

Команда 	           | Назначение
-------------------- | ---------------------
lpr -P <принтер> <файл>	 | Отправить файл на печать
lpq -P <принтер>	  | Просмотр очереди печати
lprm -P <принтер> <ID>	 | Удалить задание из очереди
lpstat -t	  | Полная информация о состоянии системы печати
cancel <ID>	 | Отменить задание

#### 4.2. Графические инструменты
**fly-admin-printer** — позволяет администратору печати устанавливать, настраивать и удалять принтеры и классы принтеров, а также настраивать сервер печати и управлять заданиями.

**fly-jobviewer** — упрощённый аналог, доступный из меню «Пуск» → «Системные» → «Очередь печати».

#### 4.3. Ограничение видимости заданий
Для принудительного ограничения видимости пользователями заданий других пользователей в файл /etc/cups/cupsd.conf добавляется соответствующая строка.

#### 5. Маркировка документов
Сервер печати, встроенный в Astra Linux Special Edition, проверяет метку безопасности заданий, отправляемых на печать, и все задания, имеющие ненулевые метки безопасности, задерживает до проведения их маркировки. Маркировка задержанных заданий осуществляется специально назначенным пользователем (пользователями).

#### 5.1. Инструменты маркировки
Для выполнения маркировки задержанных заданий в комплект установки ОС входят:

- Графический инструмент fly-admin-printer — доступен через меню «Пуск» → «Панель управления» → «Оборудование» → «Принтеры»;
- Графический инструмент fly-jobviewer — упрощённый аналог, доступный из меню «Пуск» → «Системные» → «Очередь печати»;
- Инструмент командной строки markjob.

Запуск любого из этих инструментов должен быть осуществлён от пользователя, входящего в группу lpmac.

#### 5.2. Процесс маркировки
При работе с fly-admin-printer:
```txt
Выберите в левой экранной форме нужный принтер.
В правой экранной форме выберите закладку «Задания».
Выберите нужное задание, правой кнопкой мыши вызовите контекстное меню и выберите пункт «Маркировать».
В открывшейся экранной форме заполните необходимые поля и нажмите кнопку «Да».
В списке заданий появится несколько дополнительных заданий, причём и исходное, и дополнительное задания будут помечены как «приостановленные».
Для вывода промаркированного задания на печать выберите исходное задание и нажмите кнопку «Возобновить».
```
При работе с markjob:
```txt
После запуска инструмента на экран выводится список заданий печати и запрашивается ввод нужного номера.
Введите номер задания.
Заполните необходимые реквизиты.
После ввода всех реквизитов маркировка будет выполнена автоматически.
```
#### 5.3. Параметры маркировки

Параметр 	           | Описание
-------------------- | ---------------------
MacEnable	  | Включение механизмов мандатного контроля (on/off)
MacMarkZeroLabel	  | Маркировка документов с нулевой меткой безопасности (on/off)
MacDuplex 	 | Режим печати маркера на обратной стороне (off, marker, fonarik)
MacJournal	 | Включение журнала маркировки (по умолчанию /var/spool/cups/parsec/marking-journal.sqlite)
MacHighIntAdmin	 | Требовать высокую целостность для операций администрирования

Формат маркеров документов задаётся в файле ``/etc/cups/marker.template``.

#### 5.4. Дополнительные атрибуты заданий (x.7+)
В очередном обновлении x.7 изменены наименования дополнительных атрибутов заданий:

Новое наименование	Старое наименование	Описание
Новое наименование   | Старое наименование	            | Описание
-------------------- | -------------------------------- | ---------------------------
mac-job-mac-label	   | mac-job-mac	                    | Метка безопасности задания
mac-job-mac-level-name	 | stepen	                      | Уровень (название текстом)
mac-job-mac-level-reason	  | punkt	                    | Основание для степени секретности
mac-job-user-full-name	 | printuser-fullname	          | Полное имя пользователя, выполнившего маркировку
mac-job-originating-user-full-name	 | user-fullname	  | Полное имя пользователя-исполнителя

Добавлен атрибут mac-marking-session-id (идентификатор сессии).

#### 6. Интеграция службы CUPS и FreeIPA
Настройка службы печати CUPS одинаково выполняется для доменов FreeIPA и ALD.

#### 6.1. Создание доменных групп и пользователей
На контроллере домена (от имени администратора) создаются необходимые группы и пользователи:

```bash
# Получить билет Kerberos администратора
kinit admin

# Создать доменную группу администраторов печати
ipa group-add print_admins

# Создать доменного пользователя — администратора печати
ipa user-add print_admin --first <имя> --last <фамилия>

# Добавить пользователя в группу администраторов печати
ipa group-add-member --users=print_admin print_admins
```
При необходимости выполнения маркировки заданий печати создаётся доменная группа ``lpmac_ald``, и пользователь добавляется в неё:

```bash
ipa group-add lpmac_ald
ipa group-add-member --users=print_admin lpmac_ald
```
Если сервер печати находится на отдельном сервере, для него регистрируется служба HTTP:

```bash
ipa service-add HTTP/printserver.domain.ipa
```
Если сервер печати находится на контроллере домена, эта служба создаётся автоматически.

#### 6.2. Настройка на сервере печати
Получение keytab-файлов для доменных служб:

```bash
# Билет Kerberos администратора домена
sudo kinit admin

# Для службы ipp
sudo ipa-getkeytab -p ipp/printserver.domain.ipa@DOMAIN.IPA -k /etc/krb5.keytab

# Для HTTP-службы (если сервер печати на отдельном сервере)
sudo ipa-getkeytab -p HTTP/printserver.domain.ipa@DOMAIN.IPA -k /etc/krb5.keytab
```
Если сервер печати находится на контроллере домена, для получения копии существующих ключей HTTP-службы обязательно используется ключ -r.

Настройка CUPS для аутентификации Kerberos:

```bash
sudo cupsctl DefaultPolicy=default ServerName=server.my_domain MacEnable=On DefaultAuthType=Negotiate
```
Или путём редактирования ``/etc/cups/cupsd.conf``:

```text
DefaultAuthType Negotiate
DefaultPolicy authenticated
ServerName printserver.domain.ipa
```
Проверка конфигурации и перезапуск:

```bash
sudo cupsd -t
sudo systemctl restart cups
```
#### 6.3. Настройка cups-files.conf
В файле ``/etc/cups/cups-files.conf`` в параметре SystemGroup добавляется доменная группа администраторов печати:

```text
SystemGroup lpadmin print_admins
```
#### 6.4. Схема интеграции
```text
┌─────────────────────────────────────────────────────────────┐
│                     Контроллер домена FreeIPA                │
│  • LDAP — хранение учётных записей и групп                  │
│  • Kerberos KDC — выдача билетов, аутентификация Negotiate  │
│  • Доменные группы: print_admins, lpmac_ald                 │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ Kerberos / Negotiate
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      Сервер печати CUPS                       │
│  • cupsd — диспетчер печати                                 │
│  • Keytab-файлы: ipp/printserver, HTTP/printserver          │
│  • cupsd.conf: DefaultAuthType Negotiate, MacEnable On      │
│  • cups-files.conf: SystemGroup lpadmin print_admins        │
│  • Маркировка: markjob, fly-print-station, группа lpmac     │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ IPP / Kerberos
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     Рабочие станции                           │
│  • fly-admin-printer, fly-jobviewer                         │
│  • Доменные учётные записи с классификационными метками     │
└─────────────────────────────────────────────────────────────┘
```

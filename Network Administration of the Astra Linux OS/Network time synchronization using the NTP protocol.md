### Синхронизация времени по сети с использованием протокола NTP в Astra Linux
#### 1. Управление временем в systemd (timedatectl, systemd-timesyncd)
В современных версиях Astra Linux управление системным временем и его синхронизацией интегрировано в systemd. Ключевыми инструментами являются утилита timedatectl и служба systemd-timesyncd.

Утилита timedatectl позволяет просматривать и изменять текущие настройки времени, часового пояса и состояния службы синхронизации. Для просмотра текущего состояния достаточно выполнить команду без аргументов:

```bash
timedatectl
```
Пример вывода:

```text
Local time: Сб 2025-07-12 10:12:19 MSK
Universal time: Сб 2025-07-12 07:12:19 UTC
RTC time: Сб 2025-07-12 07:12:19
Time zone: Europe/Moscow (MSK, +0300)
System clock synchronized: yes
NTP service: active
RTC in local TZ: no
```
Строка System clock synchronized: yes говорит о том, что системные часы успешно синхронизированы. Параметр NTP service: active подтверждает, что служба синхронизации запущена.

Управление синхронизацией через timedatectl:

```bash
# Включить использование NTP-клиента
sudo timedatectl set-ntp true

# Отключить использование NTP-клиента
sudo timedatectl set-ntp false
```
Служба systemd-timesyncd — это «легковесная» клиентская служба синхронизации времени, интегрированная в systemd. В Astra Linux Special Edition x.8 она представлена отдельным пакетом systemd-timesyncd, в более ранних версиях интегрирована в пакет systemd и установлена всегда.

Важно: systemd-timesyncd — исключительно клиентская служба. Она не может выполнять функции NTP-сервера. Служба автоматически завершает свою работу с ошибкой, если обнаруживает на компьютере другую службу времени (ntp или chrony).

Конфигурация systemd-timesyncd хранится в файлах /etc/systemd/timesyncd.conf и *.conf.d/. Основные параметры:

Параметр	Назначение
NTP=	Список имён основных серверов единого времени (разделённые пробелами)
FallbackNTP=	Список имён резервных серверов единого времени
По умолчанию службы systemd-timesyncd и chrony в Astra Linux настроены на работу с российскими серверами точного времени ВНИИФТРИ и дополнительных настроек не требуют.

Переключение на клиент systemd-timesyncd (если были установлены серверные службы):

```bash
# Удалить серверные службы
sudo apt purge ntp
sudo apt purge chrony

# Включить и запустить клиент
sudo timedatectl set-ntp true
sudo systemctl start systemd-timesyncd

# Проверить результат
timedatectl
```
#### 2. NTP-терминология
Для понимания работы протокола NTP необходимо знать следующие термины:

Термин	Описание
Stratum (уровень)	Число, указывающее уровень удалённости сервера от эталонного источника времени. Stratum 0 — эталонные часы (атомные, GPS). Stratum 1 — серверы, напрямую подключённые к эталонным часам. Stratum 2 — серверы, синхронизирующиеся с stratum 1, и т.д. Максимальный уровень — 15, уровень 16 означает, что часы не синхронизированы
Reference clock	Эталонные часы — источник точного времени (атомные часы, GPS-приёмник, радиоприёмник)
Offset (смещение)	Разница между системным временем и временем эталонного сервера
Drift (дрейф)	Естественное отклонение системных часов, вызванное неидеальностью кварцевого генератора
Jitter (джиттер)	Вариация задержки при передаче пакетов
Poll interval	Интервал опроса сервера (в секундах, увеличивается автоматически)
Reach	Восьмеричное число, показывающее, сколько последних опросов сервера были успешными
Leap second	Дополнительная секунда, добавляемая для синхронизации с астрономическим временем

#### 3. Установка и настройка chrony
Chrony — это современная реализация NTP-клиента и сервера, которая рекомендуется к применению в Astra Linux вместо устаревшего ntpd. Chrony лучше работает в условиях нестабильного сетевого соединения, быстрее синхронизируется и точнее поддерживает время на виртуальных машинах.

##### 3.1. Установка
```bash
sudo apt update
sudo apt install chrony
```
После установки служба chronyd запускается автоматически. Проверка статуса:

```bash
systemctl status chronyd
```
##### 3.2. Структура конфигурации
Основной конфигурационный файл — /etc/chrony/chrony.conf. В нём содержатся подробные комментарии о назначении параметров.

##### 3.3. Режим клиента (по умолчанию)
В режиме клиента служба chronyd может запускаться с настройками по умолчанию без конфигурационного файла, используя заданные по умолчанию серверы ВНИИФТРИ.

Для изменения используемых серверов синхронизации в файле /etc/chrony/chrony.conf указываются имена серверов как значения параметра server или pool:

```text
# Использование пула серверов
pool 0.ru.pool.ntp.org iburst
pool 1.ru.pool.ntp.org iburst

# Или конкретные серверы
server ntp1.vniiftri.ru iburst
server ntp2.vniiftri.ru iburst
```
Параметр iburst указывает chrony отправлять несколько быстрых запросов при запуске для ускорения начальной синхронизации.

##### 3.4. Режим сервера
Для настройки работы chronyd в режиме сервера времени (чтобы служба отвечала клиентам на запросы) необходимо отредактировать или создать конфигурационный файл /etc/chrony/chrony.conf. В нём требуется добавить строку с разрешениями клиентам подключаться к серверу NTP:

```text
allow 192.168.1.0/24
```
#### 4. Настройка NTP-сервера для работы в изолированной сети
В изолированной сети (без доступа в Интернет) один компьютер должен быть настроен в качестве главного (эталонного) сервера времени. Остальные компьютеры (клиенты) будут запрашивать время у эталонного сервера по локальной сети.

Важное замечание: в изолированной сети невозможно получить точное время из внешнего источника, поэтому необходимо сначала вручную установить корректное время на эталонном сервере.

##### 4.1. Настройка эталонного сервера
Откройте конфигурационный файл /etc/chrony/chrony.conf и внесите следующие изменения:

Закомментируйте внешние NTP-серверы, если они указаны:

```text
#server ntp1.vniiftri.ru iburst
#server ntp2.vniiftri.ru iburst
```
Добавьте директивы для работы в изолированной сети:

```text
local stratum 10
manual
```
Разрешите доступ клиентам из локальных подсетей:

```text
allow 192.168.122.0/24
allow 192.168.186.0/24
```
Пояснение директив:

local stratum 10 — параметр позволяет chrony, запущенному в качестве сервера NTP, выглядеть как эталон, даже если он никогда не синхронизировался с реальным эталоном. Значение stratum 10 указывает, что сервер будет работать на локальном уровне и не будет использовать внешние источники для синхронизации времени.

manual — директива позволяет ввести текущее время вручную.

allow <подсеть> — разрешает доступ к эталонному серверу из указанных подсетей.

##### 4.2. Пример полной конфигурации для изолированной сети
```text
# /etc/chrony/chrony.conf

# Использование локальных параметров
local stratum 10
manual

# Разрешение доступа клиентам
allow 192.168.32.0/24

# Дополнительные параметры
driftfile /var/lib/chrony/drift
rtcsync
makestep 1.0 3
```
После изменения конфигурации перезапустите службу:

```bash
sudo systemctl restart chronyd
```
##### 4.3. Установка времени вручную на эталонном сервере
Поскольку в изолированной сети нет внешнего источника точного времени, время на эталонном сервере устанавливается вручную:

```bash
# Установка даты и времени
sudo date -s "2026-09-15 10:00:00"

# Или через timedatectl
sudo timedatectl set-time "2026-09-15 10:00:00"

# Синхронизация аппаратных часов
sudo hwclock --systohc
```
После установки времени chronyd будет использовать его как эталонное для всех клиентов сети.

#### 5. Диагностика NTP-службы (chronyc)
**chronyc** — это командная утилита для управления и диагностики демона chronyd. Она предоставляет набор команд для проверки состояния синхронизации, источников времени и статистики.

##### 5.1. Основные команды диагностики
Проверка общего состояния синхронизации:

```bash
chronyc tracking
```
Пример вывода:

```text
Reference ID    : CB00710F (ntp-server.example.net)
Stratum         : 3
Ref time (UTC)  : Fri Jan 27 12:00:00 2026
System time     : 0.000012345 seconds fast of NTP time
Last offset     : +0.000012345 seconds
RMS offset      : 0.000045678 seconds
Frequency       : 1.234 ppm slow
Residual freq   : +0.000 ppm
Skew            : 0.123 ppm
Root delay      : 0.012345 seconds
Root dispersion : 0.001234 seconds
Update interval : 64.0 seconds
Leap status     : Normal
```
Ключевые показатели:

**Reference ID** — идентификатор или адрес текущего эталонного сервера.

**Stratum** — уровень сервера в иерархии NTP (должен быть больше 0).

**System time** — текущее смещение системных часов.

**Leap status** — статус дополнительной секунды (Normal — норма).

Просмотр источников времени:

```bash
chronyc sources
```
Пример вывода:

```text
MS Name/IP address         Stratum Poll Reach LastRx Last sample
===============================================================================
^* ntp1.vniiftri.ru              1   8   377    10    -10us[  -20us] +/-  5ms
^+ ntp2.vniiftri.ru              1   8   377    12    +15us[  +10us] +/-  6ms
^- ntp3.vniiftri.ru              1   8   377    15    -25us[  -30us] +/-  8ms
```
Индикаторы в первом столбце (MS):
```txt
* — текущий выбранный источник синхронизации.

+ — источник, допустимый для выбора.

- — источник, исключённый из выбора.

? — источник недоступен.
```
Расширенная информация об источниках:

```bash
chronyc sources -v
```
Статистика по источникам:

```bash
chronyc sourcestats
```
Информация о количестве онлайн/офлайн источников:

```bash
chronyc activity
```
##### 5.2. Принудительная синхронизация
```bash
chronyc makestep
```
Эта команда немедленно корректирует системные часы, если смещение превышает заданный порог.

##### 5.3. Другие полезные команды
```bash
# Проверка, запущен ли chronyd
chronyc -n tracking

# Просмотр всех источников, включая неактивные
chronyc -N sources -a

# Добавление нового сервера
chronyc add server ntp.example.com

# Удаление сервера
chronyc delete ntp.example.com

# Сохранение drift-файла
chronyc writepid
```
##### 5.4. Проверка через systemctl
```bash
sudo systemctl status chronyd
sudo journalctl -u chronyd -f
```
#### 6. Настройка NTP-клиента
##### 6.1. Настройка клиента chrony
Для настройки клиента chrony в файле /etc/chrony/chrony.conf укажите адрес эталонного NTP-сервера:

```text
server 192.168.32.211 iburst
Где 192.168.32.211 — IP-адрес эталонного сервера в локальной сети.
```
Если в сети несколько NTP-серверов, можно указать несколько строк:

```text
server 192.168.32.211 iburst
server 192.168.32.212 iburst
```
После изменения конфигурации перезапустите службу:

```bash
sudo systemctl restart chronyd
```
##### 6.2. Настройка клиента systemd-timesyncd
Для использования systemd-timesyncd в качестве клиента необходимо:

Убедиться, что серверные службы (ntp, chrony) удалены:

```bash
sudo apt purge ntp
sudo apt purge chrony
```
Включить и запустить службу:

```bash
sudo timedatectl set-ntp true
sudo systemctl start systemd-timesyncd
```
Настроить параметры в файле /etc/systemd/timesyncd.conf:

```text
[Time]
NTP=192.168.32.211
FallbackNTP=192.168.32.212
```
Перезапустить службу:

```bash
sudo systemctl restart systemd-timesyncd
```
##### 6.3. Проверка настройки клиента
```bash
timedatectl
chronyc tracking
chronyc sources
```
#### 7. Практическое решение: развёртывание NTP-инфраструктуры в изолированной сети
Сценарий
В изолированной сети (без доступа в Интернет) с подсетью ``192.168.32.0/24`` необходимо развернуть NTP-инфраструктуру. Сервер 1``92.168.32.211`` будет эталонным, клиенты — ``192.168.32.100 и 192.168.32.101``.

##### Этап 1. Установка chrony на сервере и клиентах
```bash
sudo apt update
sudo apt install chrony
```
##### Этап 2. Настройка эталонного сервера
Отредактируйте /etc/chrony/chrony.conf:

```text
# Указываем, что сервер работает в изолированной сети
local stratum 10
manual

# Разрешаем доступ клиентам из локальной подсети
allow 192.168.32.0/24

# Дополнительные параметры
driftfile /var/lib/chrony/drift
rtcsync
makestep 1.0 3
```
Установите корректное время вручную:

```bash
sudo timedatectl set-time "2026-09-15 10:00:00"
sudo hwclock --systohc
```
Перезапустите службу:

```bash
sudo systemctl restart chronyd
sudo systemctl enable chronyd
```
Проверьте работу сервера:

```bash
chronyc tracking
chronyc sources
```
Ожидаемый результат: Stratum должен быть равен 10, Reference ID — локальным.

##### Этап 3. Настройка клиентов
На каждом клиенте отредактируйте /etc/chrony/chrony.conf:

```text
server 192.168.32.211 iburst
driftfile /var/lib/chrony/drift
rtcsync
makestep 1.0 3
```
Перезапустите службу:

```bash
sudo systemctl restart chronyd
sudo systemctl enable chronyd
```
##### Этап 4. Проверка синхронизации на клиенте
```bash
chronyc tracking
```
Ожидаемый результат: Reference ID — 192.168.32.211, Stratum — 11 (на единицу больше, чем у сервера).

```bash
chronyc sources
```
Ожидаемый результат: строка с адресом 192.168.32.211 помечена ^* (выбранный источник).

##### Этап 5. Диагностика
Проверка на сервере:

```bash
# Убедиться, что сервер слушает порт 123
sudo ss -ulnp | grep :123

# Просмотр подключённых клиентов
chronyc clients
```
Проверка на клиенте:

```bash
# Детальная информация об источниках
chronyc sources -v

# Статистика по источникам
chronyc sourcestats

# Принудительная синхронизация при необходимости
sudo chronyc makestep
```
Просмотр журналов:

```bash
sudo journalctl -u chronyd -f
```
#### 8. Устранение распространённых проблем
Симптом	                    | Вероятная причина	                    | Решение
--------------------------- | ------------------------------------- | -----------------------------------------
System clock synchronized: no	 | Служба не синхронизирована	 | Проверить chronyc sources, убедиться в доступности сервера
NTP service: inactive	 | Служба chronyd не запущена	 | sudo systemctl start chronyd
chronyc: command not found	 | Не установлен пакет chrony	 | sudo apt install chrony
Клиент не видит сервер	 | Порт 123/UDP закрыт	 | Открыть порт: sudo ufw allow 123/udp
Сервер не отвечает клиентам	 | Не указан allow в конфигурации	 | Добавить allow <подсеть> в chrony.conf
Stratum равен 0	 | Сервер не синхронизирован	 | Проверить, установлено ли время вручную, и активна ли директива local
Конфликт служб времени	 | Одновременно работают ntp и chrony	 | Удалить одну из служб: sudo apt purge ntp

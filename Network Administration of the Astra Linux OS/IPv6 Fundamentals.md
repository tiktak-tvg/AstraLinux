### Основы IPv6 в Astra Linux
#### 1. Введение в IPv6
**IPv6 (Internet Protocol version 6)** — это современная версия протокола IP, разработанная для решения проблемы исчерпания адресного пространства IPv4. Адресное пространство IPv6 обеспечивает 2¹²⁸ уникальных адресов, что значительно превышает число адресов IPv4.

Ключевые преимущества IPv6:

- Огромное адресное пространство (340 ундециллионов адресов);
- Встроенная поддержка автоконфигурации (SLAAC);
- Упрощённый формат заголовка;
- Поддержка мандатного управления доступом через метки безопасности (в Astra Linux SE).

*Особенность Astra Linux:*

В версиях с оперативными обновлениями IPv6 по умолчанию отключён на уровне службы ``networking``. В файле ``/etc/sysctl.d/999-astra.conf`` указана строка ``net.ipv6.conf.all.disable_ipv6 = 1.`` Однако служба NetworkManager может самостоятельно настраивать интерфейсы, перезаписывая эти настройки, поэтому адреса IPv6 у сетевых интерфейсов по умолчанию могут присутствовать.

Проверка наличия адресов IPv6:

```bash
ip a | grep inet6
```
Включение IPv6: Необходимо убедиться, что в файле ``/etc/default/grub`` в строке ``GRUB_CMDLINE_LINUX`` отсутствует параметр ``ipv6.disable=1``, затем обновить конфигурацию загрузчика sudo update-grub и перезагрузить машину.

#### 2. Структура IPv6-адреса
IPv6-адрес имеет длину 128 бит и записывается в шестнадцатеричной системе как 8 групп по 4 шестнадцатеричные цифры, разделённых двоеточиями.

Пример полного адреса:

```text
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```
Сокращённая запись:

- Ведущие нули в группе можно опускать: 2001:db8:85a3:0:0:8a2e:370:7334
- Одну последовательность нулевых групп можно заменить на ::: 2001:db8:85a3::8a2e:370:7334

Структура адреса:

Компонент	               | Размер                       | Назначение
------------------------ | ---------------------------- | ---------------------------
Префикс сети	  | 64 бита (обычно)	  | Идентификатор сети (глобальная маршрутизация)
Идентификатор интерфейса (Interface ID)	 | 64 бита	 | Идентификатор конкретного интерфейса на канале

Interface ID в IPv6-адресах используется для идентификации интерфейсов на канале и должен быть длиной 64 бита, построенным в формате IEEE EUI-64.

#### 3. Типы IPv6-адресов
В IPv6 существует три основных типа адресов: ``unicast, anycast и multicast``.

##### 3.1. Unicast (индивидуальные)
Идентифицируют один интерфейс. Unicast-адреса могут быть:

Тип	                     | Описание
------------------------ | -----------------------------------
Global unicast	 | Глобально уникальные адреса для использования в интернете (диапазон 2000::/3)
Link-local	 | Локальные адреса канала (FE80::/64), используются только в пределах одного сегмента сети
Loopback	 | Адрес ::1, используется узлом для отправки пакета самому себе
Unspecified	 | Адрес ::, используется, когда адрес ещё не назначен
Unique local (ULA)	 | Уникальные локальные адреса (FC00::/7), аналог частных адресов IPv4
Link-local  | адреса (FE80::/64) автоматически назначаются каждому интерфейсу и используются для служебных целей, например для обмена сообщениями протокола NDP.

##### 3.2. Anycast (произвольные)
Идентифицируют набор интерфейсов, обычно принадлежащих разным узлам. Пакет доставляется ближайшему интерфейсу из группы (с точки зрения маршрутизации). Anycast-адреса имеют тот же формат, что и unicast.

##### 3.3. Multicast (групповые)
Идентифицируют группу интерфейсов. Пакеты доставляются всем узлам, входящим в группу. Multicast-адреса начинаются с префикса FF00::/8.

#### 4. Способы получения IPv6-адресов
##### 4.1. SLAAC (Stateless Address Autoconfiguration)
Клиент генерирует свой адрес самостоятельно, используя префикс, объявленный маршрутизатором через Router Advertisement (RA).

##### 4.2. Stateless DHCPv6
Клиент использует SLAAC для получения адреса, но обращается к DHCPv6-серверу за дополнительными параметрами (например, адресами DNS-серверов).

##### 4.3. Stateful DHCPv6
DHCPv6-сервер назначает клиенту адрес и другие параметры (аналог DHCPv4).

##### 4.4. Статическая настройка
Адрес назначается вручную в конфигурации сетевого интерфейса.

Настройка через NetworkManager:

```bash
nmcli con mod "Wired connection 1" ipv6.method manual ipv6.addresses "2001:db8::100/64"
nmcli con up "Wired connection 1"
```
При использовании IPv6-адресов в некоторых протоколах (например, TERA) необходимо указывать scope_id — идентификатор сетевого интерфейса (например, %eth0 или %wlan0).

#### 5. Внедрение меток безопасности в IPv6
В Astra Linux Special Edition для поддержки мандатного управления доступом в сетевые пакеты протокола IPv4 (IPv6) внедряются классификационные метки. Порядок присвоения классификационных меток и их формат соответствует национальному стандарту ГОСТ Р 58256-2018 «Защита информации. Управление потоками информации в информационной системе. Формат классификационных меток».

##### 5.1. Механизм CALIPSO
При передаче информации по протоколу IPv6 классификационные метки размещаются в Опции с типом ``CALIPSO (Common Architecture Label IPv6 Security Option, RFC 5570)`` заголовка ``Hop-by-Hop IP-пакета (RFC 2460)``.

При отсутствии опции ``CALIPSO`` в составе заголовка ``Hop-by-Hop`` считается, что пакет имеет нулевую классификационную метку (нулевой уровень конфиденциальности и нулевой набор неиерархических категорий).

##### 5.2. Структура опции CALIPSO
Поле	                   | Значение
------------------------ | -----------------------------------
TYPE	 | 7 (определяет тип опции — CALIPSO)
LENGTH	 | 12 или 16 байт (0x0C или 0x10)
DOMAIN OF INTERPRETATION	 | 1 (наличие классификационной метки)
COMPARTMENT LENGTH	 | 1 или 2 (32-битных слова)
SENSITIVITY LEVEL	 | Иерархический уровень конфиденциальности (беззнаковое целое, 256 значений)
CHECKSUM	 | Контрольная сумма CRC-16 (RFC 1662)
COMPARTMENT BITMAP	 | Битовая маска неиерархических категорий конфиденциальности (4 или 8 байт)

Контрольная сумма всегда должна быть вычислена при передаче и проверена при приёме.

##### 5.3. Мандатный контроль
Приём сетевых пакетов подчиняется мандатным правилам разграничения доступа (ПРД). Метка безопасности сокета может иметь тип, позволяющий создавать сетевые службы, принимающие соединения с любыми уровнями секретности.

#### 6. Утилиты сетевой диагностики
##### 6.1. ping6 — проверка доступности
Утилита для отправки ICMPv6-эхо-запросов:

```bash
# Проверка доступности узла
ping6 2001:db8::1

# Проверка link-local адреса (обязательно указывать интерфейс)
ping6 fe80::1%eth0

# Ограничение количества пакетов
ping6 -c 4 2001:db8::1
```
##### 6.2. traceroute6 — трассировка маршрута
```bash
# Трассировка маршрута до узла
traceroute6 2001:db8::1

# Трассировка с указанием интерфейса
traceroute6 -i eth0 2001:db8::1
```
##### 6.3. ip -6 — управление сетью
Утилита ip из пакета iproute2 поддерживает IPv6 через флаг -6:

```bash
# Просмотр IPv6-адресов
ip -6 addr show

# Просмотр IPv6-маршрутов
ip -6 route show

# Просмотр соседей (аналог ARP)
ip -6 neigh show

# Добавление IPv6-адреса
ip -6 addr add 2001:db8::100/64 dev eth0
```
##### 6.4. netstat -6 — сетевые соединения
```bash
# Просмотр IPv6-соединений
netstat -6 -tuln

# С указанием процессов
netstat -6 -tulnp
```
##### 6.5. ss — статистика сокетов
Современная замена netstat, рекомендуется к использованию в Red Hat Enterprise Linux 7 и Astra Linux:

```bash
# Все IPv6-сокеты
ss -6 -tuln

# С указанием процессов
ss -6 -tulnp

# Установленные IPv6-соединения
ss -6 -tup
```
##### 6.6. Проверка наличия IPv6 в системе
```bash
# Проверка адресов IPv6
ip a | grep inet6

# Проверка состояния IPv6 в sysctl

sysctl --all | grep net.ipv6.conf.all.disable_ipv6

Значение 1 указывает на то, что IPv6 отключён
```

### Мандатное управление доступом (МУД) в Astra Linux Special Edition 
Это центральный механизм защиты, который, в отличие от дискреционного, не позволяет пользователям произвольно передавать права на свои данные. <br>Система сама, на основе формальных правил и меток безопасности, определяет, кто и к какой информации может получить доступ, что исключает возможность утечки конфиденциальных данных по инициативе пользователя.

#### Уровни и категории конфиденциальности, мандатная целостность
Мандатные атрибуты делятся на две большие группы: конфиденциальность (защита от несанкционированного получения информации) и целостность (защита от несанкционированного изменения информации).

##### Уровни конфиденциальности (иерархические)
Это аналог грифов секретности. Каждому субъекту и объекту присваивается целочисленный уровень от ``0 до 255 (uint8_t)``. По умолчанию в ``Astra Linux Special Edition`` предлагается диапазон от `` 0 до 3``.

Уровень  | Наименование по умолчанию | Пример грифа
-------- | ------------------------- | -----------------
0	 | Уровень_0	 | Общего назначения
1	 | Уровень_1	 | Для служебного пользования (ДСП)
2	 | Уровень_2	 | Секретно
3	 | Уровень_3	 | Совершенно секретно

Количество уровней может быть увеличено до ``255``. Для этого в файле ``/usr/sbin/pdp-init-fs`` параметру ``sysmaclev`` задаётся максимальное значение, после чего требуется перезагрузка.

##### Категории конфиденциальности (неиерархические)
Это 64-битная маска ``(uint64_t)``, позволяющая организовать тематическое разделение доступа. Например, сотрудники одного отдела могут быть допущены к документам своей тематики, но не к документам другого отдела, даже если у них одинаковый уровень конфиденциальности. По умолчанию предлагается набор категорий ``0, 1 и 2``.

##### Мандатная целостность
Это отдельный механизм, который контролирует не кто может читать, а какие процессы могут изменять данные. <br>Модель целостности включает иерархический уровень целостности и неиерархические категории целостности. <br>При включённом режиме Мандатного Контроля Целостности (МКЦ) системному параметру ядра parsec.max_ilev устанавливается значение 63 по умолчанию, что задаёт максимальный уровень целостности. <br>Административные учётные записи получают максимальный уровень целостности.

#### Состав метки безопасности
Метка безопасности (мандатный контекст) — это структура, которая присваивается каждому субъекту (пользователю, процессу) и сущности (файлу, каталогу). Она включает:

- Уровень конфиденциальности (иерархический).
- Набор категорий конфиденциальности (неиерархическая маска).
- Уровень целостности (иерархический, с версии 1.8).
- Набор категорий целостности (неиерархическая маска).
- Дополнительные мандатные атрибуты (флаги).
- Дополнительные мандатные атрибуты (флаги):

*ccnr (Can Create New Regardless)*: Разрешает создавать в каталоге объекты с меткой, меньшей, чем метка самого каталога. Это критически важно для организации разделяемых каталогов, где файлы разного уровня конфиденциальности должны сосуществовать.

Другие флаги (например, для управления наследованием меток) также могут использоваться для тонкой настройки.

#### Определение уровней и категорий конфиденциальности
Настройка выполняется через графическую утилиту ``fly-admin-smc («Политика безопасности»)`` или в консоли.

##### Консольные команды для просмотра и управления:

```bash
# Просмотр текущих уровней конфиденциальности
userlev
# 0 Уровень_0
# 1 Уровень_1
# 2 Уровень_2
# 3 Уровень_3

# Просмотр состояния МКЦ
cat /proc/cmdline | grep "parsec.max_ilev"
# parsec.max_ilev=63  - МКЦ включён
```
Графический путь в *fly-admin-smc*: «Панель Управления» → «Безопасность» → «Политика безопасности» → «Мандатные атрибуты» → «Уровни целостности» (или «Уровни конфиденциальности»).

#### Установка меток и дополнительных атрибутов на файлы и каталоги
Для работы с метками используются утилиты ``pdpl-file (или pdp-flbl) и pdp-ls``.

##### Просмотр меток
```bash
# Просмотр метки файла или каталога
pdp-ls -Md /path/to/file
# Пример вывода:
# drwxr-xr-xm 2 root root Уровень_3:Высокий:Категория_1,Категория_2:ccnr /mydir
```
Формат метки: ``Уровень:Уровень_целостности:Категории:Флаги``.

##### Установка метки
```bash
# Синтаксис: pdpl-file <уровень>:<уровень_целостности>:<маска_категорий>:<флаги> <объект>
# Пример: установить уровень 2, целостность 0, категорию 0x20 (Отдел_кадров) на каталог
sudo pdpl-file 2:0:0x20:0 /Документы/Отдел_кадров/Секретно

# Пример с флагом ccnr для родительского каталога
sudo pdpl-file 4:0:0x20:ccnr /Документы/Отдел_кадров
```
> Важно: Рекурсивная смена метки ``(pdpl-file -R)`` невозможна, если новая метка превышает метку родительского каталога, и у этого каталога нет флага ccnr. Это ограничение модели безопасности.

#### Установка допустимых мандатных уровней учетным записям пользователей
Каждому пользователю в его учётной записи назначается максимальный уровень конфиденциальности и набор разрешённых категорий. При входе в систему пользователь выбирает один из доступных ему уровней (если их несколько).

Настройка выполняется в утилите ``fly-admin-smc``:

- На вкладке «Пользователи» выберите учётную запись.
- В разделе «Мандатные атрибуты» задайте «Максимальный уровень конфиденциальности» и «Максимальная категория конфиденциальности».

#### Назначение PARSEC привилегий учетным записям пользователей
``PARSEC-привилегии`` — это специальные разрешения, которые позволяют процессам выполнять действия, выходящие за рамки обычной мандатной модели (например, изменять метки безопасности файлов, игнорировать ограничения киоска, управлять аудитом).

Они наследуются процессами от родителей. Процессы, запущенные от имени суперпользователя с максимальным уровнем целостности, по умолчанию обладают большинством привилегий.

##### Основные привилегии:

Привилегия                  | Битовая маска             | Описание
-------------------- | ------------------------- | -----------------
PARSEC_CAP_CHMAC	   | 0x00008	 | Позволяет изменять метки безопасности файловых объектов. Ключевая привилегия для администратора МУД.
PARSEC_CAP_SETMAC	   | (не указана)	 | Позволяет изменять метки безопасности процессов.
PARSEC_CAP_AUDIT	   | 0x00002	 | Управление политикой аудита.
PARSEC_CAP_BYPASS_KIOSK	 | 0x08000	 | Позволяет игнорировать ограничения режима «Киоск».

Настройка привилегий также осуществляется в ``fly-admin-smc`` на вкладке управления учётными записями.

#### Практическая работа: Организация совместной работы пользователей с файлами на разных уровнях конфиденциальности
Цель: Создать структуру каталогов для отдела кадров, настроить мандатные метки и дискреционные права так, чтобы пользователь ``hr_user`` с уровнем ``«Секретно»`` и категорией ``«Отдел_кадров»`` мог работать только с документами своего уровня, но не с более высокими или низкими грифами.

##### Шаг 1. Подготовка (от администратора с высоким уровнем целостности)
```bash
# Создаём структуру каталогов
sudo mkdir -p /Документы/Отдел_кадров/Документы_общего_пользования
sudo mkdir /Документы/Отдел_кадров/Для_служебного_пользования
sudo mkdir /Документы/Отдел_кадров/Секретно
sudo mkdir /Документы/Отдел_кадров/Совершенно_секретно
```
##### Шаг 2. Создание категории и пользователя
Откройте ``fly-admin-smc``.

В разделе ``«Мандатные атрибуты»`` создайте новую категорию конфиденциальности с именем Отдел_Кадров (ей будет присвоена маска, например, 0x20).

Создайте нового пользователя:

```bash
sudo adduser hr_user
```
В ``fly-admin-smc`` на вкладке ``«Пользователи»`` для hr_user установите:

- Максимальный уровень конфиденциальности: 2:Секретно.
- Максимальная категория конфиденциальности: 5 Отдел_Кадров (или соответствующее имя).

##### Шаг 3. Назначение мандатных меток на каталоги
Устанавливаем метки, используя маску категории 0x20:

```bash
# Родительский каталог: максимальный уровень 4 с флагом ccnr (разрешает создание файлов с меньшими метками)
sudo pdpl-file 4:0:0x20:ccnr /Документы/Отдел_Кадров

# Дочерние каталоги: уровень соответствует грифу, категория — Отдел_кадров
sudo pdpl-file 0:0:0x20:0 /Документы/Отдел_кадров/Документы_общего_пользования
sudo pdpl-file 1:0:0x20:0 /Документы/Отдел_кадров/Для_служебного_пользования
sudo pdpl-file 2:0:0x20:0 /Документы/Отдел_кадров/Секретно
sudo pdpl-file 3:0:0x20:0 /Документы/Отдел_кадров/Совершенно_секретно
```
##### Шаг 4. Настройка дискреционных прав (ACL)
Чтобы hr_user мог входить в каталоги и создавать файлы:

```bash
# Разрешаем просмотр родительского каталога
sudo setfacl --modify u:hr_user:rx /Документы/

# Даём полные права (rwx) на каталог Отдел_Кадров и наследование для новых файлов
sudo setfacl --recursive --modify u:hr_user:rwx,d:u:hr_user:rwx /Документы/Отдел_Кадров

# Убираем права на запись в сам каталог Отдел_Кадров (чтобы нельзя было создать файл не в подкаталоге)
sudo setfacl --modify u:hr_user:rx /Документы/Отдел_Кадров
```
(Команды адаптированы из практического задания)

##### Шаг 5. Проверка работы
Войдите в систему пользователем hr_user, выбрав при входе уровень «Секретно» и категорию «Отдел_кадров».

Попробуйте создать файл в каталоге Секретно:

```bash
echo "Секретная информация" > /Документы/Отдел_Кадров/Секретно/readme.txt
# Команда выполнится успешно.
```
Попробуйте скопировать этот файл в каталог Для_служебного_пользования (уровень 1):

```bash
cat /Документы/Отдел_Кадров/Секретно/readme.txt > /Документы/Отдел_Кадров/Для_служебного_пользования/readme.txt
# bash: /Документы/Отдел_Кадров/Для_служебного_пользования/readme.txt: Отказано в доступе
```
Доступ будет запрещён, так как мандатная метка пользователя (уровень 2) выше метки каталога назначения (уровень 1), и запись информации с более высоким грифом в контейнер с более низким грифом запрещена.

#### Особенности Astra Linux SE
- Модель Белла-ЛаПадулы: МУД в Astra Linux реализует классическую модель, где ``«no read up» и «no write down»`` строго соблюдаются на уровне ядра.
- Единая точка управления: Утилита ``fly-admin-smc`` — основной инструмент для настройки всех мандатных атрибутов, ``PARSEC-привилегий`` и политик безопасности.
- Флаг ccnr: Без него невозможно создать иерархию каталогов с разными уровнями конфиденциальности. Это ключевой элемент для организации разделяемых ресурсов.
- Аудит: Все действия с мандатными метками и доступом фиксируются подсистемой аудита (auditd), что позволяет расследовать инциденты.
- Замкнутая программная среда (ЗПС): В дополнение к МУД, ЗПС запрещает запуск неподписанных исполняемых файлов, что предотвращает внедрение вредоносного кода.

### Управление программным обеспечением в Linux
Это централизованный процесс установки, обновления и удаления программ, который решает проблему целостности системы. Вместо ручного копирования файлов используются менеджеры пакетов, работающие с программными пакетами и репозиториями.

Astra Linux, будучи производной Debian, использует ту же фундаментальную архитектуру управления ПО: формат пакетов ``.deb``, менеджеры ``dpkg / apt`` 

и структуру репозиториев ``pool/ + dists/``. Однако есть важные особенности, связанные с сертификацией, уровнями целостности и специфическими кодовыми именами дистрибутивов.

#### Компоненты системы управления ПО
Система управления ПО в Astra Linux, как и в Debian/Ubuntu, состоит из нескольких уровней:

Уровень         | Инструмент                    | Назначение
--------------- | ----------------------------- | -------------
Низкий	        | dpkg	                        | Работа с отдельными .deb-файлами: установка, удаление, распаковка. Не управляет зависимостями и репозиториями.
Средний	        | APT	                          | Автоматическое разрешение зависимостей, скачивание пакетов из репозиториев, управление всей системой пакетов.
Высокий	        | apt, apt-get, aptitude, Synaptic	| Фронтенды для APT: командные и графические интерфейсы.

В Astra Linux дополнительно используются штатные инструменты обновления: ``fly-astra-update и astra-update``.

#### Именование и структура пакетов
Программный пакет — это архив, содержащий исполняемые файлы, библиотеки, конфигурации, документацию и скрипты управления установкой.

Стандартное имя бинарного пакета:

```text
<имя>_<версия>-<ревизия>_<архитектура>.deb
<имя> — название программы (например, logrotate).
<версия> — версия программы от разработчика.
<ревизия> — номер ревизии пакета в дистрибутиве.
<архитектура> — целевая архитектура (amd64, arm64, all).
```
Внутри ``.deb-файла`` находится управляющая информация (зависимости, версия, описание) и скрипты (preinst, postinst и т.д.), выполняемые до или после установки.

#### Структура репозитория в Astra Linux

**Репозиторий** — это хранилище .deb-пакетов и индексных файлов, организованное по строгой структуре:

**pool/** — каталог с самими .deb-файлами, organized по первой букве имени исходного пакета.

**dists/** — каталог с метаданными для каждого дистрибутива (индексные файлы Packages.gz и т.д.).

Особенности структуры репозиториев Astra Linux Special Edition x.7 и x.8

Начиная с версии x.7, в Astra Linux Special Edition используется трёхуровневая структура репозиториев:

**Основной репозиторий (main)** — сертифицированный состав, входящий в поставку. Включает только ПО, прошедшее сертификацию.

**Базовый репозиторий (base)** — включает main и средства разработки. Может изменять пакеты, входящие в base, но не входящие в main.

**Расширенный репозиторий (extended)** — дополнительное прикладное и системное ПО, средства разработки, не входящие в сертифицированную поставку.

>[Внимание!]:
> - При подключении расширенного репозитория extended необходимо также подключать базовый репозиторий base.

Компоненты репозитория

**main** — свободно распространяемое ПО.

**contrib** — свободное ПО с зависимостями от несвободного.

**non-free** — несвободное ПО.

Кодовые имена дистрибутивов
Версия Astra Linux	Кодовое имя
Astra Linux Special Edition 1.6	smolensk
Astra Linux Special Edition 1.7	1.7_x86-64
Astra Linux Common Edition	orel
Astra Linux Special Edition 1.8	smolensk / 1.8
Кодовое имя указывается в конфигурации reprepro и в записях sources.list.

#### Менеджеры пакетов: dpkg, apt, aptitude, synaptic
Инструмент	Тип	Уровень	Управление зависимостями	Особенности в Astra Linux
Инструмент          | Тип                | Уровень      | Управление зависимостями  | Особенности в Astra Linux
------------------- | ------------------ | ------------ | ------------------------- | ---------------------------------------------
dpkg	              | Командный	         | Низкий	      |  Нет	                    | Работает только с локальными .deb.
apt	                | Командный	         | Высокий	    |  Да	                      | Штатный инструмент. В Astra Linux используется так же, как в Debian.
apt-get	            | Командный	         | Высокий	    |  Да	                      | Классическая утилита, предсказуемая для скриптов.
aptitude	          | Командный (псевдографический)	    | Высокий	                  | Да (с отслеживанием)	| Запоминает, какие пакеты установлены вручную.
Synaptic	          | Графический (GTK)	 | Высокий	    |  Да	                      | Входит в состав Astra Linux и устанавливается автоматически при установке ОС. Доступен через «Пуск → Панель управления → Программы → Менеджер пакетов Synaptic».

Дополнительно: ``«Редактор репозиториев» (fly-admin-repo)``

В состав Astra Linux входит графическая утилита ``fly-admin-repo («Редактор репозиториев»)``, предназначенная для создания и управления локальными репозиториями. 

Она позволяет:

- создавать, открывать, редактировать и удалять репозитории;
- добавлять и удалять пакеты;
- проверять зависимости;
- подписывать пакеты для замкнутой программной среды (ЗПС);
- публиковать репозитории.

Запуск: «Пуск → Утилиты → Редактор репозиториев» или команда ``fly-admin-repo`` в терминале.

Примеры команд ``apt``

Команда	             | Действие
-------------------- | --------------------------------------------- 
sudo apt update	     | Обновить кэш списка пакетов.
sudo apt upgrade	   | Обновить установленные пакеты.
sudo apt install <пакет>| Установить пакет и зависимости.
sudo apt remove <пакет>	 | Удалить пакет (конфигурации остаются).
sudo apt purge <пакет>	 | Удалить пакет с конфигурациями.
apt search <запрос>	 | Найти пакет.
apt show <пакет>	   | Показать информацию о пакете.

#### Подключение стороннего репозитория
Для подключения стороннего репозитория в Astra Linux необходимо:

##### 1. Установить ключи репозитория
Проверка подлинности репозиториев выполняется с помощью GPG-ключей. Для репозиториев Astra Linux ключи регистрируются автоматически при установке ОС. Для подключения сторонних репозиториев (например, Debian) необходимо установить пакет debian-archive-keyring:

```bash
sudo apt update
sudo apt install debian-archive-keyring
```
##### 2. Добавить описание репозитория
Создайте файл в ``/etc/apt/sources.list.d/``, например ``repos.list``:

```bash
sudo nano /etc/apt/sources.list.d/repos.list
```
> Пример для Astra Linux Special Edition 1.7 (на базе Debian buster):

```text
deb https://deb.debian.org/debian/ buster main contrib non-free
deb https://security.debian.org/debian-security/ buster/updates main contrib non-free
```
##### 3. Управление приоритетами репозиториев
При подключении сторонних репозиториев может потребоваться изменить приоритет репозитория Astra Linux. Для этого удалите или отредактируйте файл:
```txt
/etc/apt/preferences.d/smolensk — для Astra Linux Special Edition.
/etc/apt/preferences.d/orel — для Astra Linux Common Edition.
```
##### 4. Обновить кэш
```bash
sudo apt update
```
> Важно для Astra Linux Special Edition с МКЦ: При включённом мандатном контроле целостности (МКЦ) команды, изменяющие систему, должны выполняться с высоким уровнем целостности. Для этого используйте sudo -s или аналогичные механизмы. Запуск apt от root с недостаточным уровнем целостности может привести к неработоспособности системы.

#### Создание собственного репозитория
Для создания локального репозитория в Astra Linux используется утилита reprepro. Альтернативно можно использовать графический инструмент fly-admin-repo.

Вариант А: Создание репозитория через reprepro (командная строка)
##### Шаг 1. Установка reprepro

```bash
sudo apt install reprepro
```
##### Шаг 2. Создание структуры каталогов

```bash
sudo mkdir -p /opt/myrepo/conf
sudo chown -R $USER:$USER /opt/myrepo
```
##### Шаг 3. Создание конфигурации

Создайте файл /opt/myrepo/conf/distributions:

```text
Origin: Debian
Codename: smolensk
Suite: stable
Version: 1.6.0
Architectures: amd64
Components: main contrib non-free
UDebComponents: main
```
Параметры:

**Codename** — кодовое имя дистрибутива: smolensk, orel или 1.7_x86-64.

**Suite** — ветка дистрибутива: stable, current, unstable.

**Architectures** — архитектура: amd64, i386, source (для исходного кода).

**Components** — компоненты: main, contrib, non-free.

**SignWith** — подпись репозитория (можно не указывать, если не планируете подписывать ключом GPG).

##### Шаг 4. Экспорт репозитория

```bash
sudo reprepro -b /opt/myrepo export
```
##### Шаг 5. Добавление пакета

```bash
# Добавление одного пакета
sudo reprepro -b /opt/myrepo includedeb smolensk /path/to/package.deb

# Добавление всех .deb в каталоге
sudo reprepro -b /opt/myrepo includedeb smolensk /path/to/packages/*.deb

При ошибке No priority given for '<имя_пакета>', skipping используйте опцию -P:
```
```bash
sudo reprepro -P -V -b /opt/myrepo includedeb smolensk /path/to/package.deb
```
##### Вариант Б: Создание репозитория через fly-admin-repo (графический интерфейс)

- Запустите fly-admin-repo через «Пуск → Утилиты → Редактор репозиториев» или командой в терминале.
- Нажмите «Создать репозиторий» (или Ctrl+N).
- Укажите путь к каталогу для локального хранения репозитория.
- Заполните остальные параметры (кодовое имя, архитектура, компоненты).
- Добавьте пакеты в репозиторий через интерфейс программы.
- При необходимости подпишите пакеты для замкнутой программной среды (ЗПС).


#### Практическая работа
Цель: Установить ПО из стандартного репозитория, создать собственный локальный репозиторий с этим пакетом и подключить его к системе в Astra Linux.

##### Шаг 1. Установка ПО из стандартного репозитория
```bash
# Обновляем кэш
sudo apt update
# Устанавливаем утилиту
sudo apt install cowsay
# Проверяем работу
cowsay "Практическая работа в Astra Linux выполнена"
```
##### Шаг 2. Создание собственного репозитория
```bash
# 1. Устанавливаем reprepro
sudo apt install reprepro

# 2. Создаём каталоги
sudo mkdir -p /opt/myrepo/conf
sudo chown -R $USER:$USER /opt/myrepo

# 3. Создаём конфигурацию (кодовое имя для Astra Linux CE — orel)
cat > /opt/myrepo/conf/distributions << EOF
Origin: Debian
Codename: orel
Suite: stable
Version: 2.12
Architectures: amd64
Components: main contrib non-free
UDebComponents: main
EOF

# 4. Экспортируем репозиторий
sudo reprepro -b /opt/myrepo export

# 5. Скачиваем .deb пакет cowsay для добавления в свой репозиторий
cd /tmp
apt-get download cowsay

# 6. Добавляем пакет в репозиторий (для Astra Linux CE используем orel)
sudo reprepro -b /opt/myrepo includedeb orel /tmp/cowsay*.deb
```
> Примечание: Для Astra Linux Special Edition 1.7 используйте кодовое имя 1.7_x86-64, для версии 1.6 — smolensk.

##### Шаг 3. Подключение собственного репозитория
```bash
# 1. Добавляем запись в sources.list.d
echo "deb [trusted=yes] file:///opt/myrepo orel main" | sudo tee /etc/apt/sources.list.d/myrepo.list

# 2. Обновляем кэш APT
sudo apt update
# В выводе должна появиться строка с вашим репозиторием (file:///opt/myrepo)
```
> Примечание: Параметр [trusted=yes] используется для локального репозитория без GPG-подписи. В производственной среде рекомендуется подписывать репозиторий ключом GPG.

##### Шаг 4. Проверка работы собственного репозитория
```bash
# Удаляем пакет, установленный в шаге 1
sudo apt remove cowsay

# Устанавливаем его из нашего локального репозитория
sudo apt install cowsay
# APT должен найти пакет в репозитории file:///opt/myrepo и установить его.
```
##### Альтернатива: создание репозитория через fly-admin-repo

Если предпочитаете графический интерфейс:

- Запустите fly-admin-repo.

- Создайте новый репозиторий, указав путь /opt/myrepo.

- Добавьте .deb-пакет cowsay через интерфейс.

- Опубликуйте репозиторий.

- Подключите его так же, как описано в шаге 3.

#### Ключевые особенности Astra Linux
- Кодовые имена: smolensk (SE 1.6), 1.7_x86-64 (SE 1.7), orel (CE 2.12). Всегда сверяйтесь с документацией для вашей версии.
- Трёхуровневая структура репозиториев в SE x.7+: main, base, extended. При подключении extended обязательно подключайте base.
- Мандатный контроль целостности (МКЦ): В SE с включённым МКЦ все команды, изменяющие систему, выполняйте с высоким уровнем целостности (например, через sudo -s).
- Сторонние репозитории Debian: Подключайте с осторожностью, используя debian-archive-keyring и репозитории, соответствующие версии Debian, на которой основана ваша Astra Linux (например, buster для 1.7). Не рекомендуется подключать репозитории Ubuntu.
- Штатные инструменты обновления: Для оперативных обновлений используйте fly-astra-update / astra-update, а не только apt upgrade.

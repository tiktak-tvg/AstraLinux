### Дискреционное управление доступом в Astra Linux
Это фундаментальный механизм разграничения прав, основанный на классической модели UNIX и расширенный за счёт списков ACL и специальных атрибутов. В отличие от мандатного контроля (МКЦ), который вы рассматривали ранее, дискреционный доступ определяет, какие именно операции (чтение, запись, выполнение) разрешены пользователям и группам.

#### 📦 Индексный дескриптор файла и классы пользователей
Каждый файл или каталог в Astra Linux (как и в любой Linux-системе) имеет индексный дескриптор (inode), который хранит метаданные: владельца (UID), группу-владельца (GID), права доступа, временные метки, размер и указатели на блоки данных. Имя файла в inode не хранится — оно содержится в каталоге, который сопоставляет имя с номером inode.

bash
# Просмотр номера inode
ls -i /etc/passwd

# Полная информация об inode
stat /etc/passwd
Классы пользователей определяются относительно конкретного файла:

Класс	Обозначение	Описание
Владелец (user)	u	Пользователь, создавший файл или назначенный владельцем.
Группа (group)	g	Группа-владелец файла.
Прочие (other)	o	Все остальные пользователи системы.
При обращении к файлу система проверяет совпадение UID/GID процесса с UID/GID файла в строгом порядке: сначала владелец, затем группа, затем прочие — решение принимается на основе первой подходящей записи.

#### 📜 Стандартные права доступа и их интерпретация
Права доступа управляют тремя операциями:

Операция	Буквенный код	Числовой код	Битовая маска
Чтение (read)	r	4	100
Изменение (write)	w	2	010
Исполнение (execute)	x	1	001
Для файлов:

r — чтение содержимого.

w — изменение содержимого.

x — запуск файла как программы.

Для каталогов:

r — просмотр списка файлов (ls).

w — создание, удаление, переименование файлов в каталоге.

x — поиск файлов в каталоге (переход в него, доступ к файлам по имени). Без x каталог бесполезен, даже если есть r.

Полный набор прав записывается тремя группами по три символа:

text
rwxr-xr-x
│││││││││
│││││││└┴┴─ прочие (other)
│││└┴┴───── группа (group)
└┴┴──────── владелец (user)
#### 🔐 Специальные биты защиты
Помимо стандартных девяти битов, существуют три специальных бита, которые устанавливаются в первом разряде восьмеричного числа (например, 4755, 2755, 1777).

SUID (Set User ID) — бит 4xxx
При запуске исполняемого файла процесс получает права пользователя-владельца файла, а не того, кто его запустил. Классический пример — /usr/bin/passwd, который запускается с правами root, чтобы изменить /etc/shadow.

bash
# Установка SUID
chmod u+s /path/to/file
chmod 4755 /path/to/file
> ⚠️ Внимание: SUID на каталогах не действует. В Astra Linux SE использование SUID может быть ограничено политиками безопасности.

SGID (Set Group ID) — бит 2xxx
На исполняемом файле: процесс получает права группы-владельца файла.

На каталоге: все вновь создаваемые файлы наследуют группу каталога, а не группу создателя. Это ключевой механизм для организации общих каталогов.

bash
# Установка SGID на каталог
chmod g+s /path/to/directory
chmod 2775 /path/to/directory
Sticky-бит — бит 1xxx
Применяется только к каталогам. При установке удалять или переименовывать файлы в каталоге может только владелец файла или суперпользователь, даже если у других есть права на запись в этот каталог. Классический пример — /tmp.

bash
# Установка Sticky-бита
chmod +t /path/to/directory
chmod 1777 /path/to/directory
Пример вывода ls -l со специальными битами:

text
-rwSr-Sr--  script.sh    # SUID + SGID установлены
drwxrwsr-x  shared_dir   # SGID на каталоге
drwxrwxrwt  /tmp         # Sticky-бит
#### 🔢 Символьная и числовая формы записи прав доступа
Форма	Пример	Описание
Символьная	rwxr-xr-x	9 символов: 3 группы по 3.
Числовая (восьмеричная)	755	Три цифры: владелец, группа, прочие.
Числовая со спец. битами	4755	Первая цифра — специальные биты.
Битовая маска	111 101 101	Три группы по три бита.
Соответствие числовых значений:

Права	Число	Расчёт
rwx	7	4 + 2 + 1
rw-	6	4 + 2
r-x	5	4 + 1
r--	4	4
-wx	3	2 + 1
-w-	2	2
--x	1	1
---	0	—
#### 🛠️ Команды и инструменты для просмотра и изменения прав доступа
Команда	Назначение	Пример
ls -l	Просмотр прав доступа.	ls -l file.txt
stat	Подробная информация о файле.	stat file.txt
chmod	Изменение прав.	chmod 644 file.txt
chown	Изменение владельца.	sudo chown user:group file.txt
chgrp	Изменение группы.	sudo chgrp developers file.txt
umask	Маска прав для новых файлов.	umask 022
chmod — изменение прав
bash
# Символьная форма
chmod u+x file.txt          # Добавить владельцу право на выполнение
chmod g-w file.txt          # Убрать у группы право на запись
chmod o=r file.txt          # Установить прочим только чтение
chmod a+r file.txt          # Добавить всем право на чтение

# Числовая форма
chmod 755 script.sh         # rwxr-xr-x
chmod 644 document.txt      # rw-r--r--
chmod 600 private.key       # rw-------
chmod 2775 shared_dir       # SGID на каталоге
chmod 1777 /tmp             # Sticky-бит

# Рекурсивно
chmod -R 750 /path/to/dir
chown и chgrp
bash
# Изменение владельца
sudo chown user1 file.txt

# Изменение владельца и группы
sudo chown user1:developers file.txt

# Изменение только группы
sudo chgrp developers file.txt

# Рекурсивно
sudo chown -R user1:developers /path/to/dir
umask — маска прав для новых файлов
umask определяет, какие права отнимаются у новых файлов и каталогов. Базовые права: для файлов — 666, для каталогов — 777.

bash
# Просмотр текущей маски
umask
# 0022

# Расчёт прав для нового файла
# 666 - 022 = 644 (rw-r--r--)

# Установка маски
umask 027    # 640 для файлов, 750 для каталогов
В Astra Linux SE за применение маски отвечает модуль pam_umask.

#### 📋 Списки управления доступом (ACL)
ACL (Access Control Lists) расширяют базовую модель «владелец — группа — прочие», позволяя задавать индивидуальные права для конкретных пользователей и конкретных групп.

Типы ACL
Тип	Описание
Минимальный ACL	Соответствует базовым правам (user::rwx, group::r-x, other::r-x).
Расширенный ACL	Содержит именованные записи для пользователей/групп.
ACL по умолчанию	Наследуется новыми файлами в каталоге.
Утилиты getfacl и setfacl
bash
# Просмотр ACL
getfacl file.txt

# Пример вывода:
# file: file.txt
# owner: user1
# group: developers
# user::rw-
# user:user2:r--          # Именованный пользователь
# group::r--
# mask::r--
# other::---
bash
# Установка ACL
setfacl -m u:user2:r-- file.txt      # Дать user2 право на чтение
setfacl -m g:admins:rwx file.txt     # Дать группе admins полные права
setfacl -m o::- file.txt             # Убрать права у прочих

# Удаление ACL
setfacl -x u:user2 file.txt          # Удалить запись для user2
setfacl -b file.txt                  # Удалить все расширенные ACL

# ACL по умолчанию (для каталогов)
setfacl -d -m u:user2:rwx /shared    # Новые файлы наследуют права
setfacl -d -m g:developers:rwx /shared
Маска ACL
Маска ограничивает максимальные права для именованных пользователей, именованных групп и группы-владельца. Если в маске указано r-x, то даже если пользователю явно дано rwx, он получит только r-x.

bash
# Установка маски
setfacl -m m::r-x file.txt
#### 🏷️ Управление атрибутами файлов
Расширенные атрибуты (xattr) — это пары «ключ:значение», ассоциированные с файловыми объектами. Они поддерживаются в ext2/ext3/ext4, XFS, Btrfs.

Утилиты getfattr и setfattr
bash
# Установка расширенного атрибута
setfattr -n user.author -v "Astra Linux" document.txt

# Просмотр атрибутов
getfattr -d document.txt

# Удаление атрибута
setfattr -x user.author document.txt
Команды chattr и lsattr — управление скрытыми атрибутами ФС
Эти команды работают с атрибутами на уровне файловой системы (ext2/3/4, XFS) и не зависят от прав доступа.

Атрибут	Описание
i (immutable)	Файл нельзя изменить, удалить, переименовать или создать ссылку. Даже root не может, пока не снимет атрибут.
a (append only)	Файл можно только дополнять. Нельзя перезаписать или удалить.
A (no atime)	Не обновлять время доступа.
c (compressed)	Автоматическое сжатие (не для всех ФС).
bash
# Установка атрибута "append only"
sudo chattr +a /var/log/secure.log

# Теперь файл можно только дополнять:
echo "new line" >> /var/log/secure.log    # OK
echo "overwrite" > /var/log/secure.log    # Ошибка!

# Снятие атрибута
sudo chattr -a /var/log/secure.log

# Просмотр атрибутов
lsattr /var/log/secure.log
# ----a--------e---- /var/log/secure.log
#### 💻 Практическая работа
Шаг 1. Поиск файлов с заданными правами доступа
bash
# Поиск файлов с правами 777
find / -type f -perm 777 2>/dev/null

# Поиск файлов с SUID-битом
find / -type f -perm -4000 2>/dev/null

# Поиск файлов с SGID-битом
find / -type f -perm -2000 2>/dev/null

# Поиск файлов, доступных для записи всем
find / -type f -perm -o+w 2>/dev/null

# Поиск файлов без владельца
find / -nouser 2>/dev/null
Шаг 2. Изменение дискреционных прав доступа
bash
# Создаём тестовый файл
touch /tmp/test_perms.txt

# Устанавливаем права 640
chmod 640 /tmp/test_perms.txt
ls -l /tmp/test_perms.txt

# Изменяем владельца
sudo chown user1:developers /tmp/test_perms.txt

# Проверяем
ls -l /tmp/test_perms.txt
Шаг 3. Создание общего каталога через SGID
bash
# Создаём группу и каталог
sudo groupadd project
sudo mkdir /shared_sgid

# Меняем группу-владельца каталога
sudo chgrp project /shared_sgid

# Устанавливаем SGID и права
sudo chmod 2775 /shared_sgid

# Добавляем пользователей в группу
sudo usermod -aG project user1
sudo usermod -aG project user2

# Проверяем: новые файлы в каталоге наследуют группу project
touch /shared_sgid/test.txt
ls -l /shared_sgid/test.txt
# -rw-rw-r-- 1 user1 project ... test.txt
Шаг 4. Создание общего каталога через ACL
bash
# Создаём каталог
sudo mkdir /shared_acl

# Устанавливаем права: владелец — полный доступ, прочие — нет
sudo chmod 700 /shared_acl

# Даём пользователю user1 права на чтение/запись/выполнение
sudo setfacl -m u:user1:rwx /shared_acl

# Даём группе developers права на чтение/выполнение
sudo setfacl -m g:developers:r-x /shared_acl

# Настраиваем ACL по умолчанию для наследования
sudo setfacl -d -m u:user1:rwx /shared_acl
sudo setfacl -d -m g:developers:r-x /shared_acl

# Проверяем ACL
getfacl /shared_acl
Шаг 5. Использование атрибута a (append)
bash
# Создаём файл-журнал
sudo touch /var/log/myapp.log

# Устанавливаем атрибут "только дополнение"
sudo chattr +a /var/log/myapp.log

# Проверяем атрибут
lsattr /var/log/myapp.log

# Попытка перезаписи — должна завершиться ошибкой
echo "new content" > /var/log/myapp.log
# -bash: /var/log/myapp.log: Operation not permitted

# Добавление в конец — работает
echo "log entry" | sudo tee -a /var/log/myapp.log

# Снятие атрибута
sudo chattr -a /var/log/myapp.log
#### 🛡️ Особенности Astra Linux SE
Мандатный контроль (МКЦ): Дискреционные права работают поверх мандатных. Даже если пользователь имеет права rwx на файл, но его уровень целостности ниже уровня файла — доступ будет запрещён.

Графическое управление: Вкладка «Дискреционные атрибуты» в свойствах файла (Файловый менеджер fly-fm) позволяет управлять владельцем, правами, SUID/SGID/Sticky и ACL.

ACL и мандатные метки: ACL в Astra Linux может содержать записи, связанные с мандатными атрибутами (классы доступа S, U, G).

Ограничение SUID: В защищённых конфигурациях SE использование SUID-битов может быть ограничено политиками безопасности. Атрибут i (immutable) часто используется для защиты критичных системных файлов.

/tmp и Sticky-бит: Каталог /tmp в Astra Linux традиционно имеет права 1777 (Sticky-бит), что предотвращает удаление чужих файлов.

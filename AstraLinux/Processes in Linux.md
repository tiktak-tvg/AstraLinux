### Процессы в Linux (Astra Linux)
**Процесс** — это экземпляр выполняемой программы. В Astra Linux, как и в любой Linux-системе, управление процессами — ключевая задача администратора: от мониторинга нагрузки до управления приоритетами и передачи сигналов.

#### 🧠 Общие понятия о программах, процессах и потоках выполнения

Понятие	                | Определение
----------------------- | -----------------------------------------------------
Программа	  | Статический набор инструкций и данных на диске (исполняемый файл).
Процесс	 | Динамический экземпляр программы, загруженный в память и выполняемый ядром. Имеет собственное адресное пространство, PID, права, состояние.
Поток (thread)	 | Единица выполнения внутри процесса. Потоки одного процесса разделяют адресное пространство, но имеют собственный стек и регистры.

Ключевые различия:

- Процессы изолированы друг от друга (разные адресные пространства).
- Потоки внутри одного процесса разделяют память, что упрощает обмен данными, но требует синхронизации.
- В Linux потоки реализованы через механизм LWP (Lightweight Process) и системный вызов clone().

Просмотр потоков:
```bash
# Список процессов с потоками
ps -eLf

# Количество потоков в процессе
cat /proc/<PID>/status | grep Threads

# Дерево потоков
pstree -p <PID>
```
#### 🔄 Жизненный цикл процесса
Процесс проходит несколько состояний:

Состояние               | Обозначение                       | Описание
----------------------- | --------------------------------- | --------------------------------------
Running (R)	            | R	                                | Выполняется или готов к выполнению.
Sleeping (S)	          | S	                                | Ожидает события (прерываемый сон).
Disk sleep (D)	        | D	                                | Непрерываемый сон (ожидание ввода-вывода).
Stopped (T)	            | T	                                | Остановлен сигналом (Ctrl+Z или SIGSTOP).
Zombie (Z)	            | Z	                                | Завершён, но родитель не считал код возврата.
Dead (X)	              | X	                                | Полностью удалён (встречается редко).

Этапы жизненного цикла:

- Создание (fork/exec): родительский процесс создаёт копию через fork(), затем заменяет образ через exec().
- Выполнение: процесс работает, переключаясь между состояниями.
- Завершение: процесс вызывает exit() или получает сигнал.
- Ожидание (wait): родитель считывает код возврата через wait().

Удаление: ядро освобождает ресурсы.

Пример создания процесса:

```bash
# Запуск команды в фоне
sleep 100 &

# PID последнего фонового процесса
echo $!

# Просмотр дерева процессов
pstree -p
```
Зомби-процессы:
```bash
# Поиск зомби
ps aux | awk '$8 ~ /Z/ {print}'

# Причина: родитель не вызвал wait()
# Решение: завершить родительский процесс
kill -9 <PPID>
```
#### 🔗 Виды межпроцессного взаимодействия (IPC)

Механизм                | Описание                          | Пример использования
----------------------- | --------------------------------- | --------------------------------------
Каналы (pipes)	 | Анонимные каналы для связи родственных процессов.    | 	< ls  | grep txt >
Именованные каналы (FIFO)	  | Каналы с именем в ФС, доступны любым процессам.	  | /run/systemd/initctl/fifo
Сигналы	 | Асинхронные уведомления.	 | kill -TERM <PID>
Очереди сообщений	  | Обмен структурированными сообщениями.	 | ipcs -q
Семафоры	 | Синхронизация доступа к ресурсам.	 | ipcs -s
Разделяемая память	 | Общая область памяти для быстрого обмена.	  | ipcs -m
Сокеты	 | Обмен данными через сеть или локально.	  | /run/systemd/journal/socket

Просмотр IPC-объектов:
```bash
# Все IPC-объекты
ipcs -a

# Очереди сообщений
ipcs -q

# Семафоры
ipcs -s

# Разделяемая память
ipcs -m
```
#### 📚 Настройка доступа к общим библиотекам
Общие библиотеки (.so) используются несколькими программами одновременно, что экономит память и упрощает обновление.

Основные пути поиска библиотек:

**/lib, /lib64** — системные библиотеки.

**/usr/lib, /usr/lib64** — библиотеки пользовательских программ.

**/usr/local/lib** — библиотеки, установленные вручную.

Управление путями поиска:

Способ	Описание
/etc/ld.so.conf	Основной конфигурационный файл.
/etc/ld.so.conf.d/	Дополнительные конфигурации.
LD_LIBRARY_PATH	Переменная окружения (временное решение).
ldconfig	Утилита обновления кэша библиотек.

Пример настройки:
```bash
# Добавить путь к библиотекам
echo "/opt/myapp/lib" | sudo tee /etc/ld.so.conf.d/myapp.conf

# Обновить кэш
sudo ldconfig

# Проверить, что библиотека найдена
ldconfig -p | grep mylib

# Просмотр зависимостей программы
ldd /usr/bin/ls
```
> Важно: В Astra Linux SE с включённым МКЦ библиотеки, расположенные в защищённых каталогах, могут быть недоступны процессам с низким уровнем целостности.

#### 📊 Мониторинг процессов

Команда	Назначение	Пример
ps	Снимок процессов.	ps aux
top	Интерактивный монитор.	top
htop	Улучшенный top (требует установки).	htop
pgrep	Поиск PID по имени.	pgrep firefox
pstree	Дерево процессов.	pstree -p
pidstat	Статистика по процессам.	pidstat -p <PID> 1
lsof	Открытые файлы процесса.	lsof -p <PID>
strace	Трассировка системных вызовов.	strace -p <PID>

Основные параметры ps:

Параметр	Действие
a	Процессы всех пользователей.
u	Подробный формат.
x	Включая процессы без терминала.
-e	Все процессы.
-f	Полный формат.
-L	Показать потоки.

Примеры:
```bash
# Все процессы
ps aux

# Процессы конкретного пользователя
ps -u $USER

# Процессы с полным деревом
ps -ef --forest

# Топ-5 процессов по CPU
ps aux --sort=-%cpu | head -6

# Топ-5 процессов по памяти
ps aux --sort=-%mem | head -6

# Потоки процесса
ps -eLf | grep <PID>
```
Интерактивный top:

Клавиша	Действие
P	Сортировка по CPU.
M	Сортировка по памяти.
T	Сортировка по времени.
k	Убить процесс.
r	Изменить приоритет (renice).
1	Показать все ядра CPU.
q	Выход.

Установка htop:

```bash
sudo apt install htop
htop
```
#### ⚖️ Управление приоритетом процесса
В Linux приоритет процесса определяется значением nice (от -20 до +19). Чем меньше значение, тем выше приоритет.

Значение nice	Приоритет
-20	Наивысший (только root).
0	По умолчанию.
+19	Наинизший.

Команды управления:

Команда	Назначение	Пример
nice	Запуск с приоритетом.	nice -n 10 command
renice	Изменение приоритета.	renice -n -5 -p <PID>
ionice	Приоритет ввода-вывода.	ionice -c 2 -n 0 command

Примеры:

```bash
# Запуск с низким приоритетом
nice -n 19 tar -czf backup.tar.gz /home

# Запуск с высоким приоритетом (root)
sudo nice -n -10 ./critical_task

# Изменение приоритета работающего процесса
sudo renice -n -5 -p 1234

# Изменение приоритета всех процессов пользователя
sudo renice -n 10 -u user
```
Классы ionice:

Класс	Описание
1	Real-time (наивысший).
2	Best-effort (по умолчанию).
3	Idle (только при простое).
```bash
# Установка класса best-effort с приоритетом 0
ionice -c 2 -n 0 -p <PID>
```
#### 📡 Сигналы
Сигналы — это асинхронные уведомления, отправляемые процессам.

Основные сигналы:

Номер	Имя	Действие
1	SIGHUP	Перечитать конфигурацию / завершение.
2	SIGINT	Прерывание (Ctrl+C).
3	SIGQUIT	Завершение с дампом (Ctrl+\).
9	SIGKILL	Безусловное убийство (нельзя перехватить).
15	SIGTERM	Мягкое завершение (по умолчанию).
18	SIGCONT	Продолжить выполнение.
19	SIGSTOP	Остановить (нельзя перехватить).
20	SIGTSTP	Остановить (Ctrl+Z).

Команда kill:

```bash
# Мягкое завершение
kill <PID>
kill -TERM <PID>
kill -15 <PID>

# Принудительное завершение
kill -9 <PID>
kill -KILL <PID>

# Перечитать конфигурацию
kill -HUP <PID>

# Список всех сигналов
kill -l
Команда pkill — по имени:

bash
# Завершить все процессы firefox
pkill firefox

# Принудительно
pkill -9 firefox

# По шаблону
pkill -f "python.*script"
Команда killall — по имени:

bash
# Завершить все экземпляры
killall firefox

# С подтверждением
killall -i firefox
```
#### 🗂️ Управление заданиями (jobs)
Задания (jobs) — это процессы, запущенные из текущей оболочки.

Команда	Действие
command &	Запуск в фоне.
Ctrl+Z	Приостановить (перевести в фон).
jobs	Список заданий.
fg %N	Вернуть задание N на передний план.
bg %N	Продолжить задание N в фоне.
kill %N	Убить задание N.
disown %N	Отвязать задание от оболочки.
nohup command &	Запуск, устойчивый к разрыву связи.

Пример:

```bash
# Запуск в фоне
sleep 1000 &
# [1] 12345

# Список заданий
jobs
# [1]+  Running    sleep 1000 &

# Приостановка
Ctrl+Z
# [1]+  Stopped    sleep 1000

# Продолжить в фоне
bg %1

# Вернуть на передний план
fg %1

# Убить
kill %1
```
nohup — для задач, которые должны пережить выход из сессии:

```bash
nohup long_task.sh > task.log 2>&1 &
```
#### 💻 Практическая работа
Цель: Освоить мониторинг процессов и потоков, передачу сигналов, управление приоритетом и заданиями.

##### Шаг 1. Мониторинг процессов и потоков
Просмотрите все процессы:

```bash
ps aux | head -20
```
Найдите процессы пользователя:

```bash
ps -u $USER
```
Просмотрите дерево процессов:

```bash
pstree -p | head -30
```
Запустите фоновый процесс и найдите его PID:

```bash
sleep 500 &
echo "PID: $!"
```
Просмотрите потоки этого процесса:

```bash
ps -eLf | grep sleep
```
Запустите top и отсортируйте по CPU (P), затем по памяти (M), выйдите (q).

Установите и запустите htop:

```bash
sudo apt install htop
htop
```
##### Шаг 2. Передача сигналов процессам
Запустите процесс:

```bash
sleep 1000 &
PID=$!
echo "PID: $PID"
```
Отправьте SIGTERM:

```bash
kill -TERM $PID
```
Убедитесь, что процесс завершён:

```bash
ps -p $PID
```
Запустите процесс снова и убейте его SIGKILL:

```bash
sleep 1000 &
PID=$!
kill -9 $PID
```
Запустите ping и завершите его через Ctrl+C (SIGINT).

Найдите процессы по имени и завершите:

```bash
pkill -f "sleep 1000"
```
##### Шаг 3. Управление приоритетом
Запустите процесс с низким приоритетом:

```bash
nice -n 19 sleep 300 &
PID=$!
ps -o pid,ni,cmd -p $PID
```
Измените приоритет:

```bash
sudo renice -n -5 -p $PID
ps -o pid,ni,cmd -p $PID
```
Запустите процесс с ionice:

```bash
ionice -c 3 sleep 300 &
```
##### Шаг 4. Управление заданиями
Запустите процесс в фоне:

```bash
sleep 1000 &
```
Приостановьте его:

```bash
# Нажмите Ctrl+Z
```
Просмотрите задания:

```bash
jobs
```
Продолжите в фоне:

```bash
bg %1
```
Верните на передний план:

```bash
fg %1
```
Прервите (Ctrl+C).

Запустите с nohup:

```bash
nohup sleep 1000 > /tmp/nohup.log 2>&1 &
disown
```
Проверьте, что процесс работает:

```bash
ps aux | grep sleep
```
##### Шаг 5. Сводный отчёт
Составьте отчёт, содержащий:

- Топ-5 процессов по CPU и по памяти.
- Количество потоков в процессе systemd.
- Список зомби-процессов (если есть).
- Результат отправки SIGTERM и SIGKILL.
- Изменение приоритета через renice.
- Список заданий после Ctrl+Z и bg.

#### 🛡️ Особенности Astra Linux SE
Мандатный контроль доступа (МКЦ): В SE с включённым МКЦ процессы имеют мандатные метки. Процесс с низким уровнем целостности не может отправить сигнал процессу с высоким уровнем или прочитать его информацию в ``/proc``.

Запрет ptrace: В защищённых конфигурациях может быть ограничена трассировка процессов ``(strace, gdb)`` для процессов других пользователей и уровней целостности.

Замкнутая программная среда (ЗПС): В ЗПС запускаться могут только подписанные исполняемые файлы. Это влияет на создание новых процессов — неподписанные бинарники будут заблокированы.

Аудит процессов: Подсистема auditd в Astra Linux SE фиксирует запуск процессов, отправку сигналов и изменения приоритетов. Просмотр: ausearch -m execve, aureport --exec.

Штатные утилиты: Для мониторинга в Astra Linux доступны как стандартные (ps, top, htop), так и специализированные средства (например, fly-admin-process в некоторых версиях).

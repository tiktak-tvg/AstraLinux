### Управление учетными записями пользователей и групп в Astra Linux
**Astra Linux** — многопользовательская операционная система, в которой учётная запись пользователя является ключевым элементом всей системы управления доступом. Управление учётными записями — задача административного характера, поэтому выполняется суперпользователем или пользователем, входящим в группу astra-admin (в этой группе разрешено выполнять команды от имени root через sudo).

#### 📋 Подготовка к созданию учетных записей
Перед созданием учётных записей необходимо понимать типы пользователей и требования к идентификаторам.

Типы пользователей
Тип	Описание	UID	Домашний каталог
Суперпользователь (root)	Полный доступ к системе. По умолчанию пароль не задан, вход заблокирован.	0	/root
Обычные пользователи	Разрешён терминальный вход.	1000–59999	/home/<имя>
Системные пользователи	Для функционирования ОС и служб.	0–99 (ОС), 100–999 (службы)	Различные

Идентификаторы UID и GID
Для идентификации учётных записей используются UID (User ID) и GID (Group ID). Каждый пользователь должен принадлежать как минимум к одной группе — первичной. При создании учётной записи создаётся группа с именем, совпадающим с именем пользователя.

В Astra Linux автоматически создаётся группа astra-admin с GID=1001. Поэтому при создании нового пользователя ему будет присвоен первый свободный UID=1001, а идентификатор его группы будет GID=1002.

Рекомендации по парольной политике
Согласно требованиям безопасности, для учётных записей необходимо задать следующие параметры:

Параметр	Рекомендуемое значение
Минимальная длина пароля	≥ 8 символов
Сложность	Строчные + заглавные буквы + цифры
Максимальный срок действия	90 дней
Максимальное число неудачных попыток	6
Таймаут блокировки	1800 секунд (30 мин)

#### 🗄️ Изучение баз данных локальных учетных записей
Локальные учётные записи хранятся в текстовых файлах в каталоге /etc/:

Файл	Содержимое	Права доступа
/etc/passwd	Учётные записи пользователей	Чтение — всем, запись — root
/etc/shadow	Пароли и атрибуты паролей	Чтение и запись — root, чтение — группа shadow
/etc/group	Учётные записи групп	Чтение — всем, запись — root
/etc/gshadow	Пароли групп	Чтение и запись — root, чтение — группа shadow

Структура файла /etc/passwd
Формат строки: имя:x:UID:GID:GECOS:домашний_каталог:командный_интерпретатор

Пример:

text
localadmin:x:1000:1000:localadmin,,,:/home/localadmin:/bin/bash
Поле	Значение	Описание
Имя пользователя	localadmin	Вводится при входе в систему.
Хеш пароля	x	Указывает, что пароль хранится в /etc/shadow.
UID	1000	Идентификатор пользователя.
GID	1000	Идентификатор первичной группы.
GECOS	localadmin,,,	Дополнительная информация (полное имя и т.д.).
Домашний каталог	/home/localadmin	Домашний каталог пользователя.
Оболочка	/bin/bash	Командный интерпретатор.

Структура файла /etc/shadow
Формат строки: имя:хеш_пароля:дата_последней_смены:мин_срок:макс_срок:предупреждение:неактивность:дата_истечения:зарезервировано

Структура файла /etc/group
Формат строки: имя_группы:пароль:GID:список_пользователей

Просмотр баз данных
bash
# Просмотр всех пользователей
cat /etc/passwd

# Просмотр пользователей с UID >= 1000
awk -F: '$3 >= 1000 {print $1, $3}' /etc/passwd

# Просмотр всех групп
cat /etc/group

# Информация о текущем пользователе
id
#### 🛠️ Использование команд и графических утилит
Команды управления учётными записями
Команда	Назначение	Пример
useradd	Создание учётной записи	sudo useradd -m -s /bin/bash -G sudo newuser
adduser	Интерактивное создание (сценарий)	sudo adduser newuser
usermod	Изменение параметров	sudo usermod -aG groupname username
userdel	Удаление учётной записи	sudo userdel -r username
passwd	Смена пароля	sudo passwd username
chage	Управление сроком действия пароля	sudo chage -M 90 username
groupadd	Создание группы	sudo groupadd groupname
gpasswd	Управление группами	sudo gpasswd -a user group
delgroup	Удаление группы	sudo delgroup groupname

Примеры команд
bash
# Создание пользователя с домашним каталогом и оболочкой bash
sudo useradd -m -s /bin/bash -G astra-admin newuser
sudo passwd newuser

# Создание группы
sudo groupadd students

# Добавление пользователя в группу
sudo usermod -aG students newuser

# Изменение оболочки пользователя
sudo usermod -s /bin/zsh newuser

# Блокировка учётной записи
sudo usermod -L newuser

# Разблокировка
sudo usermod -U newuser

# Удаление пользователя вместе с домашним каталогом
sudo userdel -r newuser

# Удаление группы
sudo delgroup students
Важно: Модификация учётных записей, в частности изменение принадлежности к группам, требует перезагрузки открытой сессии пользователя.

Графические утилиты
fly-admin-smc («Управление политикой безопасности») — основная графическая утилита для администрирования учётных записей. Запуск:

bash
sudo fly-admin-smc
Или через меню: «Пуск» → «Панель управления» → «Безопасность» → «Политика безопасности».

Возможности утилиты:

Управление пользователями, группами и их атрибутами.

Настройка мандатного управления доступом.

Управление привилегиями (полномочиями).

Настройка политики срока действия пароля.

Настройка политики блокировки при неудачных входах.

Параметры протоколирования.


Также используется модуль astra-systemsettings («Параметры системы») → раздел «Пользователи и группы».

#### 🔑 Управление паролями
Команда passwd
bash
# Смена пароля текущего пользователя
passwd

# Смена пароля другого пользователя (root)
sudo passwd username

# Блокировка учётной записи
sudo passwd -l username

# Разблокировка
sudo passwd -u username

# Удаление пароля (вход без пароля)
sudo passwd -d username

# Просмотр статуса пароля
sudo passwd -S username
Команда chage — управление сроком действия пароля
bash
# Просмотр текущих параметров
sudo chage -l username

# Максимальный срок действия пароля — 90 дней
sudo chage -M 90 username

# Минимальный срок между сменами — 0 дней
sudo chage -m 0 username

# Предупреждение за 7 дней до истечения
sudo chage -W 7 username

# Срок действия учётной записи — конкретная дата
sudo chage -E 2026-12-31 username

# Принудительная смена пароля при следующем входе
sudo chage -d 0 username
Политика паролей через /etc/login.defs
bash
# Откройте файл
sudo nano /etc/login.defs

# Установите параметры:
PASS_MAX_DAYS   90      # Максимальный срок действия пароля
PASS_MIN_DAYS   0       # Минимальный срок между сменами
PASS_WARN_AGE   7       # Предупреждение за N дней
LOGIN_RETRIES   6       # Количество неудачных попыток
LOGIN_TIMEOUT   60      # Таймаут входа

Политика паролей через PAM
Файл /etc/pam.d/common-password управляет сложностью паролей. Строка:

text
password requisite pam_cracklib.so minlen=8 dcredit=-1 ucredit=-1 lcredit=-1
Параметр	Описание
minlen=8	Минимальная длина пароля — 8 символов
dcredit=-1	Требуется минимум 1 цифра
ucredit=-1	Требуется минимум 1 заглавная буква
lcredit=-1	Требуется минимум 1 строчная буква
ocredit=-1	Требуется минимум 1 спецсимвол
retry=3	Количество попыток ввода пароля

Для запрета повторного использования последних паролей в строке pam_unix.so добавьте параметр remember=<число_паролей>.

Блокировка при неудачных попытках входа
По умолчанию в Astra Linux для фиксации числа неверных попыток входа применяется PAM-модуль pam_tally (в версиях 1.6 и старше — pam_tally2). Настройка выполняется в файле /etc/pam.d/common-auth:

text
auth requisite pam_faillock.so preauth audit per_user deny=8 fail_interval=900 unlock_time=600
Параметр	Описание
deny=8	Максимальное число попыток
fail_interval=900	Интервал сброса счётчика (секунды)
unlock_time=600	Время блокировки (секунды)

Для сброса счётчика неудачных попыток:

bash
sudo faillock --user <имя_пользователя> --reset

Файлы настройки окружения
Файл	Назначение	Когда выполняется

/etc/bash.bashrc	Общесистемные настройки bash	При интерактивном запуске

#### 🛡️ Управление аутентификацией и авторизацией с помощью PAM
PAM (Pluggable Authentication Modules) — это модульная система аутентификации, позволяющая гибко настраивать способы проверки подлинности пользователей.

Структура конфигурации PAM
Конфигурационные файлы находятся в каталоге /etc/pam.d/. Основные файлы:

Файл	Назначение
common-auth	Аутентификация
common-account	Проверка учётной записи
common-password	Смена пароля
common-session	Управление сессией
login	Вход через консоль
fly-dm	Графический вход (Fly DM)
sudo	Выполнение команд через sudo
Типы управления PAM
Тип	Описание
auth	Аутентификация (проверка пароля).
account	Проверка допустимости входа (срок действия, время).
password	Изменение пароля.
session	Управление сессией (монтирование, логирование).
Основные модули PAM
Модуль	Назначение
pam_unix.so	Стандартная аутентификация через /etc/shadow.
pam_cracklib.so	Проверка сложности пароля.
pam_pwquality.so	Проверка качества пароля (современный аналог cracklib).
pam_faillock.so / pam_tally2.so	Блокировка при неудачных попытках.
pam_parsec_mac.so	Мандатный контроль доступа (Astra Linux).
pam_mkhomedir.so	Автоматическое создание домашнего каталога.
pam_limits.so	Применение ограничений из /etc/security/limits.conf.
pam_access.so	Управление доступом на основе /etc/security/access.conf.

Пример настройки PAM для двухфакторной аутентификации
bash
# Удаление старых профилей
sudo pam-auth-update --remove astra-sss-2fa astra-sss-2fa-try

# Установка нужного PAM-профиля 2ФА
sudo pam-auth-update --enable <имя_профиля>

Пример настройки PAM для аутентификации по ключевым носителям
bash
# Копирование примера конфигурации
sudo cp /usr/share/doc/libpam-pkcs11/examples/pam_pkcs11.conf.example.gz /etc/pam_pkcs11.conf

# Редактирование /etc/pam.d/common-auth
# Добавление модуля pam_pkcs11

Пример настройки PAM для аутентификации через внешний файл паролей
bash
# Редактирование /etc/pam.d/fly-dm
# Добавление строки перед @include common-auth:
auth sufficient pam_exec.so expose_authtok quiet /usr/bin/pam_tdsk --htpasswd /etc/htpasswd

🛡️ Особенности Astra Linux SE
Мандатный контроль доступа (МКЦ): В SE с включённым МКЦ учётные записи имеют мандатные метки (уровень конфиденциальности, категории). Управление этими атрибутами выполняется через fly-admin-smc или astra-systemsettings.

Группа astra-admin: В Astra Linux автоматически создаётся группа astra-admin (GID=1001), которой разрешено выполнять команды от имени root через sudo.

Привилегии (полномочия): Управление полномочиями локальных пользователей осуществляется через fly-admin-smc. Это позволяет гибко разграничивать права администраторов.

Пароль root по умолчанию не задан: Войти в систему с учётной записью root нельзя, пока пароль не будет установлен. Для разблокировки: sudo passwd -u root.

PAM-модуль pam_parsec_mac.so: Специфический модуль Astra Linux для мандатного контроля доступа, интегрированный в PAM-стек.

Аудит действий: Подсистема auditd фиксирует создание, изменение и удаление учётных записей. Просмотр: ausearch -m useradd, aureport --auth.

### Система журналирования 
Система журналирования в Astra Linux SE, как и в других современных Linux-дистрибутивах, представляет собой многоуровневую архитектуру. 

Она сочетает в себе классический демон ``syslog`` для сбора и маршрутизации сообщений и ``systemd-journald`` для централизованного хранения и анализа логов ядра и служб.

#### 📜 Основные системные журнальные файлы
В Astra Linux SE, начиная с очередного обновления 1.7, по умолчанию используется служба syslog-ng, которая заменила собой rsyslog. Основные журнальные файлы, создаваемые системой, находятся в каталоге /var/log/:

Файл                | Назначение                  
------------------- | -----------------------------------------------
/var/log/syslog	 | Основной системный журнал, содержащий сообщения от большинства служб.
/var/log/auth.log	 | Журнал аутентификации и авторизации (вход в систему, sudo).
/var/log/kern.log	 | Сообщения ядра.
/var/log/dpkg.log	 | Журнал установки и удаления пакетов.
/var/log/parsec/kernel.mlog	 | Журнал безопасности подсистемы Parsec (мандатный контроль).

> Важно: В Astra Linux SE с включённым мандатным контролем целостности (МКЦ) для просмотра некоторых защищённых журналов могут потребоваться повышенные привилегии.

#### ⚙️ Настройка службы журналирования syslog-ng
Служба syslog-ng обеспечивает гибкий сбор, фильтрацию и маршрутизацию сообщений. Её основной конфигурационный файл — ``/etc/syslog-ng/syslog-ng.conf``, а дополнительные файлы можно размещать в каталоге ``/etc/syslog-ng/conf.d/``.

#### 🧩 Базовые принципы конфигурации
Конфигурация syslog-ng строится из объектов следующих типов:

**source** — источник сообщений (файл, сокет, удалённый хост).

**destination** — приёмник (файл, удалённый сервер, база данных).

**log** — путь, соединяющий источники и приёмники, с возможностью применения фильтров.

**filter** — правила селекции сообщений.

**parser** — правила анализа и разбора сообщений.

##### Пример конфигурации для отправки сообщений на удалённый сервер:
```bash
syslog-ng
# Определение источника (локальные сообщения)
source s_local {
    system();
    internal();
};

# Определение приёмника (удалённый сервер)
destination d_remote {
    network("192.168.1.100" port(514) transport("udp"));
};

# Определение пути: все сообщения из s_local отправляются в d_remote
log {
    source(s_local);
    destination(d_remote);
};
```
#### 🔧 Управление службой
```bash
# Проверка синтаксиса конфигурации
sudo syslog-ng -s

# Перезапуск службы
sudo systemctl restart syslog-ng

# Проверка статуса
sudo systemctl status syslog-ng
```
#### ⚙️ Настройка службы журналирования systemd-journald
**systemd-journald** — это служба, входящая в состав systemd, которая собирает и хранит журналы в бинарном формате. Её конфигурация находится в файле /etc/systemd/journald.conf.

#### 🔑 Ключевые параметры

Параметр            | Описание                 
------------------- | -----------------------------------------------
Storage	            | Определяет, где хранятся журналы: volatile (в /run/log/journal, теряются при перезагрузке), persistent (в /var/log/journal, сохраняются), auto (по умолчанию, выбирает автоматически).
SystemMaxUse	    | Максимальный размер, который могут занимать журналы на диске.
RuntimeMaxUse	    | Максимальный размер журналов в оперативной памяти.
ForwardToSyslog     | Пересылать ли сообщения в syslog-ng (по умолчанию yes).

##### Пример настройки для постоянного хранения журналов:
```bash
# Редактирование конфигурации
sudo nano /etc/systemd/journald.conf

# Установите:
Storage=persistent

# Создайте каталог для постоянного хранения
sudo mkdir -p /var/log/journal

# Перезапустите службу
sudo systemctl restart systemd-journald
```
#### 🔍 Использование утилиты journalctl
``journalctl`` — это основной инструмент для просмотра и анализа журналов, собранных systemd-journald.

#### 📋 Основные команды

Команда	Действие
Команда             | Действие               
------------------- | -----------------------------------------------
sudo journalctl	    | Просмотр всех журналов с момента последней загрузки.
sudo journalctl -b	 | Журнал текущей загрузки.
sudo journalctl -b -1	 | Журнал предыдущей загрузки.
sudo journalctl -f	 | Режим реального времени (аналог tail -f).
sudo journalctl -u <служба>	 | Журнал конкретной службы (например, -u syslog-ng).
sudo journalctl -p err	 | Фильтр по уровню критичности (от emerg до debug).
sudo journalctl -n 20	 | Последние 20 сообщений.
sudo journalctl --since "2025-01-01" --until "2025-01-02"	 | Фильтр по времени.
sudo journalctl _PID=1234	 | Фильтр по PID процесса.

#### 🎯 Уровни критичности
При фильтрации по опции -p используются следующие уровни:
```
0 — emerg (неработоспособность системы)

1 — alert (требуется немедленное вмешательство)

2 — crit (критическое состояние)

3 — err (ошибки)

4 — warning (предупреждения)

5 — notice (уведомления)

6 — info (информационные)

7 — debug (отладочные)
```
Пример: sudo journalctl -p err -b покажет все ошибки текущей загрузки.

#### 🔄 Ротация журналов при помощи logrotate
Утилита logrotate предназначена для автоматического управления файлами журналов: их сжатия, удаления и архивирования. Она предустановлена в Astra Linux 1.7 и выше.

#### 📁 Конфигурация
Основной конфигурационный файл — ``/etc/logrotate.conf``. Пользовательские настройки для конкретных журналов размещаются в каталоге ``/etc/logrotate.d/``.

Пример конфигурационного файла ``/etc/logrotate.d/kernlog``:

```text
/var/log/parsec/kernel.mlog {
    daily
    missingok
    rotate 7
    compress
    notifempty
    postrotate
        /etc/init.d/parlogd restart > /dev/null
    endscript
}
```
Разбор директив:

**daily** — ежедневная ротация.

**missingok** — не выдавать ошибку, если файл отсутствует.

**rotate 7** — хранить 7 старых копий перед удалением.

**compress** — сжимать старые журналы.

**notifempty** — не ротировать пустой файл.

**postrotate ... endscript** — выполнить команды после ротации (например, перезапустить демон).

#### ▶️ Ручной запуск ротации
```bash
# Проверка конфигурации без выполнения
sudo logrotate -d /etc/logrotate.d/kernlog

# Принудительная ротация
sudo logrotate -f /etc/logrotate.d/kernlog
```
#### 💻 Практическая работа: Настройка syslog-ng, journalctl и logrotate
Цель: Настроить службу syslog-ng для перенаправления сообщений, освоить фильтрацию в journalctl и настроить ротацию журнала.

##### Шаг 1. Настройка syslog-ng
Создайте файл конфигурации для нового приёмника:
```bash
sudo nano /etc/syslog-ng/conf.d/99-my-logs.conf
Добавьте следующий код для сохранения сообщений только от службы cron в отдельный файл:

syslog-ng
source s_local {
    system();
    internal();
};

filter f_cron {
    program("cron");
};

destination d_cron_log {
    file("/var/log/cron.log");
};

log {
    source(s_local);
    filter(f_cron);
    destination(d_cron_log);
};
```
Проверьте синтаксис и перезапустите службу:
```bash
sudo syslog-ng -s
sudo systemctl restart syslog-ng
```
Проверьте, что файл создаётся:
```bash
sudo tail -f /var/log/cron.log
```
##### Шаг 2. Использование journalctl
Просмотрите все ошибки текущей загрузки:
```bash
sudo journalctl -p err -b
```
Просмотрите журнал конкретной службы в реальном времени:
```bash
sudo journalctl -u ssh -f
```
Найдите сообщения за последний час:
```bash
sudo journalctl --since "1 hour ago"
```
##### Шаг 3. Настройка ротации журналов
Создайте конфигурационный файл для ротации созданного ранее журнала:
```bash
sudo nano /etc/logrotate.d/cron-log
```
Добавьте следующее содержимое:
```text
/var/log/cron.log {
    weekly
    missingok
    rotate 4
    compress
    notifempty
}
```
Проверьте конфигурацию и выполните тестовую ротацию:
```bash
sudo logrotate -d /etc/logrotate.d/cron-log
sudo logrotate -f /etc/logrotate.d/cron-log
```
Убедитесь, что появился сжатый файл:
```bash
ls -la /var/log/cron.log*
```
#### ⚠️ Ключевые особенности Astra Linux SE
Смена демона syslog: В Astra Linux SE 1.7 и выше rsyslog больше не используется в основном репозитории. Вместо него применяется syslog-ng.

Мандатный контроль: В Special Edition с включённым МКЦ доступ к журналам и настройка служб журналирования могут требовать высокого уровня целостности.

Специализированные журналы: Для аудита безопасности используются отдельные подсистемы (Parsec, auditd) и утилиты (ausearch, aureport).

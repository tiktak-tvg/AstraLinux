В Astra Linux, как и в других Linux-системах, существует несколько инструментов для автоматизации задач. Они делятся на две основные категории: классические демоны (cron, anacron, atd) и более современные юниты systemd (таймеры, systemd-run).

🕒 Выполнение заданий по расписанию с помощью службы cron
Cron — это классическая системная служба, которая запускает задачи по строгому расписанию. Она работает постоянно, проверяя каждую минуту, не пора ли выполнить какое-либо задание.

Файлы конфигурации:

Пользовательские задания: crontab -e (для конкретного пользователя).

Системные задания: Файл /etc/crontab и каталоги /etc/cron.d/, /etc/cron.hourly/, /etc/cron.daily/ и т.д.

Синтаксис crontab: Каждая строка состоит из пяти полей времени (минуты, часы, день месяца, месяц, день недели) и выполняемой команды. Например, 0 5 * * 1 /usr/bin/backup.sh запустит скрипт backup.sh в 5:00 каждую неделю в понедельник.

Особенности в Astra Linux: Редактирование списка заданий рекомендуется выполнять командой sudo crontab -e. Также управление возможно из графического интерфейса через «Пуск → Панель управления → Система → Планировщик задач».

⏳ Периодическое выполнение заданий с помощью anacron
Anacron — это аналог cron, но с важным отличием: он предназначен для систем, которые не работают круглосуточно (например, ноутбуки или рабочие станции). Anacron не привязан к точному времени. Он проверяет, было ли выполнено задание за последние N дней, и если нет — запускает его при следующем включении компьютера.

Конфигурация: Основной файл — /etc/anacrontab. Формат записи: <период в днях> <задержка в минутах> <идентификатор задания> <команда>.

Особенности в Astra Linux: В Astra Linux Special Edition anacron установлен по умолчанию и имеет приоритет перед cron. Это означает, что стандартные системные задачи (например, обновление locate) выполняются через anacron.

⚙️ Планирование выполнения заданий через systemd
Таймеры systemd — это современная альтернатива cron, встроенная в систему инициализации. Они позволяют запускать службы (.service) по расписанию (аналогично cron) или по определённым событиям (например, после загрузки системы или запуска другой службы).

Преимущества перед cron:

Централизованное управление: Используются те же команды systemctl, что и для других служб.

Гибкое логирование: Для каждого таймера создаётся отдельный журнал, доступный через journalctl.

Событийный запуск: Могут запускаться не только по времени, но и при наступлении системных событий.

Приоритет: Таймеры имеют более высокий приоритет выполнения, чем задания cron.

Структура:

.service юнит: Описывает, что нужно выполнить (команда, скрипт).

.timer юнит: Описывает, когда это нужно выполнить. Содержит секцию [Timer] с параметрами вроде OnCalendar=*-*-* 05:00:00 (аналог cron) или OnBootSec=15min (запуск через 15 минут после загрузки).

Управление: После создания файлов юнитов в /etc/systemd/system/ (или ~/.config/systemd/user/ для пользовательских задач) необходимо выполнить sudo systemctl daemon-reload, а затем включить и запустить таймер: sudo systemctl enable --now my.timer.

⏰ Отложенное выполнение заданий с помощью службы atd
Служба atd управляет очередью заданий, созданных утилитой at. Эта утилита предназначена для выполнения разовых задач в указанное время (например, «выключить компьютер через 30 минут» или «отправить письмо в 18:00»).

Использование:

Установка: sudo apt install at.
Создание задания: echo "command" | at 18:00 или в интерактивном режиме at 10:00 tomorrow.
Просмотр очереди: atq.
Удаление задания: atrm <номер_задания>.
Особенности в Astra Linux SE (МКЦ): При включённом мандатном контроле целостности служба atd по умолчанию работает на высоком уровне целостности. Это означает, что пользователи в сессиях с низким уровнем целостности не могут передавать ей задания. Для решения этой проблемы требуется настроить atd для работы на низком уровне целостности, отредактировав службу через sudo systemctl edit atd и добавив соответствующие параметры.

🚀 Запуск разовых заданий в указанное время через systemd-run
Утилита systemd-run позволяет запускать команды как временные (transient) юниты systemd. Это более легковесный и современный способ выполнения разовых задач, который не требует отдельного демона, как atd.

Запуск задачи в определённое время:

bash
# Запустить команду 'backup.sh' в 22:00
sudo systemd-run --on-calendar="22:00" /path/to/backup.sh
Эта команда создаст временный таймер, который сработает в указанное время и выполнит задачу.

Запуск задачи с ограничениями ресурсов:

bash
# Запустить команду с ограничением использования CPU в 50%
sudo systemd-run --scope -p CPUQuota=50% /path/to/heavy_task
Это позволяет изолировать и контролировать ресурсы, потребляемые задачей.

💻 Практическая работа: Настройка cron и таймеров systemd
Цель: Освоить настройку заданий через cron и создание таймера systemd для автоматического запуска скрипта.

Шаг 1. Настройка задания через cron
Создайте простой скрипт, который будет записывать текущее время в лог-файл:

bash
sudo nano /usr/local/bin/log_time.sh
Содержимое скрипта:

bash
#!/bin/bash
echo "Задание cron выполнено: $(date)" >> /var/log/my_cron_job.log
Сделайте скрипт исполняемым:

bash
sudo chmod +x /usr/local/bin/log_time.sh
Откройте редактор заданий cron для пользователя root (или вашего пользователя):

bash
sudo crontab -e
Добавьте строку, которая будет запускать скрипт каждую минуту (для тестирования):

text
* * * * * /usr/local/bin/log_time.sh
Сохраните и выйдите. Через минуту проверьте лог-файл:

bash
sudo tail -f /var/log/my_cron_job.log
Шаг 2. Создание таймера systemd
Создайте файл службы, которая будет выполнять нашу задачу:

bash
sudo nano /etc/systemd/system/log-time.service
Содержимое:

ini
[Unit]
Description=Запуск скрипта логирования времени

[Service]
Type=oneshot
ExecStart=/usr/local/bin/log_time.sh
Создайте файл таймера, который будет запускать эту службу каждые 2 минуты:

bash
sudo nano /etc/systemd/system/log-time.timer
Содержимое:

ini
[Unit]
Description=Таймер для запуска log-time.service каждые 2 минуты

[Timer]
OnCalendar=*:0/2
Persistent=true

[Install]
WantedBy=timers.target
Активируйте и запустите таймер:

bash
sudo systemctl daemon-reload
sudo systemctl enable --now log-time.timer
Проверьте статус таймера и его следующее срабатывание:

bash
systemctl list-timers --all | grep log-time
Убедитесь, что задача выполняется, проверив лог-файл:

bash
sudo tail -f /var/log/my_cron_job.log
💎 Ключевые особенности Astra Linux SE
Приоритет anacron: В Special Edition anacron используется по умолчанию и имеет приоритет над cron для системных задач.

Мандатный контроль (МКЦ): Для atd и других служб, работающих с заданиями от пользователей, необходимо учитывать уровни целостности. По умолчанию atd может быть недоступен для пользовательских сессий с низким уровнем.

Графический интерфейс: Для управления заданиями cron существует графический модуль «Планировщик задач» в параметрах системы.

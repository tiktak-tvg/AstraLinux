### Архивация и сжатие данных в Astra Linux
**Linux** — это многоуровневый процесс, который требует учёта не только стандартных параметров, но и особенностей мандатного контроля доступа (МКД). 

Ключевой момент: при работе с файлами, имеющими мандатные метки безопасности, стандартные утилиты нужно использовать с особыми опциями, а иногда и с PARSEC-привилегиями.

#### 📦 Сжатие файлов
Сжатие уменьшает размер файлов и часто используется вместе с архивацией. В Astra Linux доступны стандартные утилиты:

Утилита          | Формат                | Пример команды        |     Описание         
---------------- | --------------------- | --------------------- | -------------------
gzip	           | .gz	                 | gzip file.txt	       | Быстрое сжатие, широко распространено.
bzip2	           | .bz2	                 | bzip2 file.txt	       | Лучше сжимает, но медленнее.
xz	             | .xz	                 | xz file.txt	         | Наилучшее сжатие, самый медленный.

##### Примеры:

```bash
# Сжать файл (исходный файл удаляется)
gzip document.txt

# Распаковать
gunzip document.txt.gz

# Сжать с сохранением исходного файла
gzip -k document.txt

# Создать tar-архив и сжать его gzip
tar -czvf archive.tar.gz /path/to/dir

# Сжать с помощью bzip2 или xz
tar -cjvf archive.tar.bz2 /path/to/dir
tar -cJvf archive.tar.xz /path/to/dir

Для распаковки используются соответствующие опции: -xzf (gzip), -xjf (bzip2), -xJf (xz).
```
#### 💽 Клонирование дисков с помощью dd
Утилита dd — это самый простой инструмент для полного копирования дисков или разделов «побитово». Она автоматически устанавливается в системе и не требует настройки.

##### Ключевой синтаксис:

```bash
sudo dd if=<источник> of=<назначение> bs=<размер_блока>

if — входной файл (источник, например /dev/sda1).

of — выходной файл (назначение, например /dev/sdb1 или файл-образ).

bs — размер блока (например, 4096 или 4M), влияет на скорость.
```
##### Примеры использования:

Задача                              | Команда                 
----------------------------------- | ------------------------------------------------------- 
Создать образ раздела	              | sudo dd if=/dev/sda1 of=/media/usb/sda1.img bs=4096
Клонировать раздел на другой диск	  | sudo dd if=/dev/sda1 of=/dev/sdb1 bs=4M status=progress
Восстановить из образа	            | sudo dd if=/media/usb/sda1.img of=/dev/sda1 bs=4M

##### Важные недостатки dd:

- Копирует всё пространство раздела, включая пустое, что создаёт избыточный объём.

- Требует, чтобы копия размещалась на отличном физическом устройстве.

- Для копирования по сети нужны дополнительные средства.

##### Когда dd незаменим:

- Перенос системы на новый диск.

- Создание загрузочных накопителей из ISO-образов.

#### 🏷️ Архивация файлов с учётом меток безопасности
Это ключевое отличие работы в Astra Linux SE. При архивации файлов с мандатными метками необходимо использовать специальные опции, чтобы сохранить расширенные атрибуты (xattr), включая метки безопасности и флаги аудита.

##### Использование tar с метками безопасности
Основной инструмент — tar с опцией --xattrs, которая сохраняет и восстанавливает расширенные атрибуты, включая классификационные метки.

##### Создание архива с сохранением меток:

```bash
sudo tar --xattrs --acls -cvzf /backup/archive.tar.gz /Документы

--xattrs — сохранять расширенные атрибуты (включая мандатные метки).

--acls — сохранять списки контроля доступа (ACL).

-c — создать архив.

-v — подробный вывод.

-z — сжать с помощью gzip.

-f — указать имя файла архива.
```
##### Восстановление с сохранением меток:

```bash
sudo tar --xattrs --acls -xvf /backup/archive.tar.gz -C /
При восстановлении опция --xattrs позволяет корректно применить мандатные метки к файлам.

> ⚠️ Ключевое требование: PARSEC-привилегия
Для восстановления файлов с мандатными метками недостаточно просто использовать --xattrs. Процесс tar должен обладать PARSEC-привилегией PARSEC_CAP_UNSAFE_SETXATTR, которая позволяет изменять мандатные атрибуты файлов.
```
##### Включение привилегии перед восстановлением:

```bash
# Разрешить использование привилегии
echo 1 | sudo tee /parsecfs/unsecure_setxattr

# Выполнить восстановление с привилегией
sudo /usr/sbin/execaps -c 0x1000 -- sudo tar --xattrs --acls -xvf /backup/archive.tar.gz -C /

# Отключить привилегию после восстановления
echo 0 | sudo tee /parsecfs/unsecure_setxattr
/usr/sbin/execaps -c 0x1000 — запускает команду с привилегией PARSEC_CAP_UNSAFE_SETXATTR (код 0x1000).

/parsecfs/unsecure_setxattr — файл, управляющий разрешением на использование этой привилегии.
```
> ⚠️ Важно: Все действия по архивации и восстановлению в Astra Linux SE должны выполняться в сессии суперпользователя с высоким уровнем целостности.

#### 🔄 Синхронизация каталогов и файлов с помощью rsync
**rsync** — это мощный инструмент для синхронизации файлов и каталогов, который поддерживает сохранение мандатных атрибутов при копировании.

##### Основные опции для работы с метками безопасности

Опция                            | Назначение                
-------------------------------- | ------------------------------------------------------- 
-a	                             | Режим архива (сохраняет права, владельцев, временные метки, рекурсивно).
-X / --xattrs	                   | Сохранять расширенные атрибуты (включая мандатные метки).
-A / --acls		                   | Сохранять списки контроля доступа ACL.
-v	                             | Подробный вывод.
-z	                             | Сжатие при передаче.

##### Пример локальной синхронизации с метками:
```bash
sudo rsync -avAX /Документы/ /backup/Документы/
```
##### Пример удалённой синхронизации через SSH:
```bash
sudo rsync -vzrptgoAX /home/ admin@192.168.0.1:/home_bak

В этом примере сохраняются права, владельцы, временные метки, ACL и расширенные атрибуты.
```
> ⚠️ Требование PARSEC-привилегии для rsync
Как и для tar, для корректного сохранения мандатных атрибутов удалённому экземпляру rsync должна быть предоставлена привилегия PARSEC_CAP_UNSAFE_SETXATTR.

##### Пример синхронизации с привилегией:
```bash
echo 1 | sudo tee /parsecfs/unsecure_setxattr
sudo /usr/sbin/execaps -c 0x1000 -- sudo rsync -avAX /source/ /destination/
echo 0 | sudo tee /parsecfs/unsecure_setxattr
```
##### Рекомендации по безопасности
- Не используйте sudo в удалённых вызовах rsync — это небезопасно.
- Используйте опцию -M --fake-super для безопасного сохранения атрибутов через SSH.
- Для службы rsyncd (rsync.service) используйте только в доверенной сети, так как она не применяет защитное преобразование данных.

#### 💻 Практическая работа
Цель: Освоить dd, tar с сохранением меток безопасности и rsync для работы с файлами, имеющими мандатные метки.

##### Шаг 1. Создание тестовой структуры с метками
```bash
# Создаём каталоги
sudo mkdir -p /source/Отдел_кадров
sudo mkdir -p /backup

# Устанавливаем мандатные метки
sudo pdpl-file 2:0:0x20:ccnr /source/Отдел_кадров
sudo pdpl-file 1:0:0x20:0 /source/Отдел_кадров/Документ1.txt

# Создаём тестовые файлы
echo "Секретный документ" | sudo tee /source/Отдел_кадров/Документ1.txt
echo "Ещё один документ" | sudo tee /source/Отдел_кадров/Документ2.txt

# Проверяем метки
pdp-ls -Md /source/Отдел_кадров/
```
##### Шаг 2. Использование dd для клонирования
```bash
# Создаём образ раздела (пример для /dev/sdb1)
# ВНИМАНИЕ: замените /dev/sdb1 на ваш тестовый раздел
sudo dd if=/dev/sdb1 of=/backup/sdb1.img bs=4096 status=progress

# Проверяем размер образа
ls -lh /backup/sdb1.img

# Восстанавливаем из образа (на тестовый раздел)
sudo dd if=/backup/sdb1.img of=/dev/sdb1 bs=4096 status=progress
```
##### Шаг 3. Архивация с tar и сохранением меток
```bash
# Создаём архив с сохранением мандатных меток
sudo tar --xattrs --acls -cvzf /backup/source_backup.tar.gz /source

# Проверяем содержимое архива
sudo tar -tzvf /backup/source_backup.tar.gz

# Восстанавливаем с сохранением меток (с PARSEC-привилегией)
echo 1 | sudo tee /parsecfs/unsecure_setxattr
sudo /usr/sbin/execaps -c 0x1000 -- sudo tar --xattrs --acls -xvf /backup/source_backup.tar.gz -C /
echo 0 | sudo tee /parsecfs/unsecure_setxattr

# Проверяем восстановленные метки
pdp-ls -Md /source/
```
##### Шаг 4. Синхронизация с rsync и метками
```bash
# Синхронизируем каталог с сохранением меток
echo 1 | sudo tee /parsecfs/unsecure_setxattr
sudo /usr/sbin/execaps -c 0x1000 -- sudo rsync -avAX /source/ /backup/source_rsync/
echo 0 | sudo tee /parsecfs/unsecure_setxattr

# Проверяем метки в синхронизированном каталоге
pdp-ls -Md /backup/source_rsync/

# Удалённая синхронизация (пример)
# sudo rsync -vzrptgoAX /source/ user@remote:/backup/source/
```
##### Шаг 5. Проверка результатов
```bash
# Сравниваем содержимое
diff -r /source /backup/source_rsync

# Проверяем метки на всех файлах
find /backup/source_rsync -exec pdp-ls -Md {} \;
```
#### 🛡️ Особенности Astra Linux SE
Привилегия PARSEC_CAP_UNSAFE_SETXATTR: Без неё восстановление мандатных меток невозможно. Привилегия управляется через файл /parsecfs/unsecure_setxattr и утилиту execaps.

Уровень целостности: Все операции должны выполняться в сессии с высоким уровнем целостности.

Рекурсивная смена меток: В Astra Linux SE невозможна рекурсивная смена мандатных меток на поддереве файловой системы.

Графический инструмент: Для резервного копирования доступен luckyBackup, который также поддерживает сохранение мандатных атрибутов.

BACULA: В состав дистрибутива входит комплекс резервного копирования BACULA для более сложных сценариев.

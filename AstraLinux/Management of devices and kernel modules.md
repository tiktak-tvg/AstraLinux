### Управление устройствами и модулями ядра в Linux
#### 1. Псевдофайловая система sysfs
*sysfs* — это псевдофайловая система, предоставляющая интерфейс к структурам данных ядра. Файлы и каталоги в sysfs позволяют видеть структуры kobject, определённые внутри ядра, и отображают информацию об устройствах, модулях ядра, файловых системах и других компонентах. Обычно sysfs автоматически монтируется в каталог /sys. Многие файлы доступны только для чтения, но некоторые позволяют изменять переменные ядра.

Основные каталоги /sys:

Каталог      | Назначение
------------ | -------------
/sys/block	 | Символьные ссылки на каждое блочное устройство
/sys/bus	   | Подкаталоги по типам шин ядра (с подкаталогами devices и drivers)
/sys/class	 | Классы устройств: терминалы, сетевые, блочные, звуковые и т. д.
/sys/devices |	Реальная иерархия всех устройств системы

#### 2. Менеджер устройств systemd-udevd
``systemd-udevd`` — это демон, который прослушивает uevents ядра. Для каждого события он выполняет соответствующие инструкции, указанные в правилах ``udev``. Демон запускается как системная служба ``systemd-udevd.service`` и взаимодействует с ядром через сокеты ``systemd-udevd-control.socket`` и ``systemd-udevd-kernel.socket``. Поведение демона настраивается через ``udev.conf``, параметры командной строки и может изменяться динамически с помощью ``udevadm control``.

#### 3. Правила udev
Правила udev хранятся в файлах `` .rules`` в каталогах ``/lib/udev/rules.d/``, ``/run/udev/rules.d/`` и ``/etc/udev/rules.d/``. Каталоги обрабатываются в указанном порядке, файлы сортируются по алфавиту. Файл с одинаковым именем в ``/etc/udev/rules.d/`` переопределяет файлы в других каталогах.

Синтаксис правил состоит из пар ``«ключ — оператор — значение»``:

Оператор     | Описание
------------ | -------------
=	           | Присвоить значение (перезаписывает)
+=	         | 	Добавить значение в список
:=	         | 	Присвоить значение, которое нельзя изменить дальше
==	         | 	Проверить равенство
!=	         | 	Проверить неравенство

Пример правила для изменения группы устройства:

```text
SUBSYSTEM=="tty", KERNEL=="tty8", GROUP="root"
```
#### 4. Утилита udevadm
``udevadm`` — инструмент управления udev, позволяющий контролировать поведение ``systemd-udevd``, запрашивать события ядра, управлять очередью событий и отлаживать правила.

Основные команды:

Команда         | Назначение
--------------- | -------------
udevadm info	  | Запрос информации об устройстве из базы udev
udevadm trigger	| Принудительная генерация событий для устройств
udevadm monitor	| Мониторинг uevents ядра и событий udev в реальном времени
udevadm test	  | Тестирование правил для устройства без их применения
udevadm control	| Управление демоном (например, --reload-rules)
udevadm settle	| Ожидание завершения обработки всех событий

Получение информации об устройстве:

```bash
udevadm info -a -p /sys/class/net/eth0
```
Ключ ``-a`` выводит все атрибуты устройства и всех его родительских устройств в цепочке до корня ``sysfs`` — эти атрибуты можно использовать в правилах udev.

#### 5. Разграничение доступа к подключаемым устройствам
Правила udev позволяют управлять правами доступа к устройствам через директивы OWNER, GROUP и MODE. Например, для предоставления доступа группе:

```text
KERNEL=="ttyUSB[0-9]*", GROUP="dialout", MODE="0660"
```
Для блокировки нежелательных USB-устройств можно использовать атрибут ``authorized`` в ``sysfs``. Правило разрешает определённые классы устройств (по bInterfaceClass), а для остальных выполняется скрипт, записывающий 0 в ``/sys/bus/usb/devices/.../authorized``.

6. Управление модулями ядра
*Модули ядра* — это код, который можно загружать и выгружать без перезагрузки системы.

Основные утилиты:

Утилита         | Назначение
--------------- | -------------
lsmod	          | Вывод всех загруженных модулей в виде таблицы
modinfo	        | Информация о модуле: файл, описание, авторы, лицензия, параметры
modprobe	      | Загрузка/выгрузка модулей с автоматическим разрешением зависимостей
insmod	        | Загрузка модуля (без разрешения зависимостей)
rmmod	          | Выгрузка модуля

Загрузка модуля с параметрами:

```bash
sudo modprobe название_модуля параметр=значение
```
Чёрный список модулей создаётся в ``/etc/modprobe.d/``:

```bash
echo "blacklist название_модуля" | sudo tee /etc/modprobe.d/blacklist.conf
```
#### Практическая работа
**Задание 1.** Создание правила udev для изменения группы устройства

Цель: изменить группу устройства ``/dev/tty8 с tty на root``, затем отменить изменения.

##### Шаг 1. Создайте файл правила:

```bash
echo 'SUBSYSTEM=="tty", KERNEL=="tty8", GROUP="root"' | sudo tee /etc/udev/rules.d/10-tty8.rules
```
##### Шаг 2. Проверьте правило без применения:

```bash
udevadm test /devices/virtual/tty/tty8
```
##### Шаг 3. Примените правило:

```bash
udevadm trigger /sys/devices/virtual/tty/tty8
```
##### Шаг 4. Проверьте результат:

```bash
ls -l /dev/tty8
Ожидаемый вывод: crw------- 1 root root 4, 8 ... /dev/tty8
```
##### Шаг 5. Отмените изменения:

```bash
sudo rm /etc/udev/rules.d/10-tty8.rules
sudo chown :tty /dev/tty8
```
**Задание 2.** Получение информации об устройстве через ``sysfs`` и ``udevadm``

Цель: определить путь к сетевому устройству ``eth0`` в ``/sys`` и вывести все его атрибуты.

##### Шаг 1. Найдите ссылку на устройство:

```bash
ls -l /sys/class/net/
```
Пример вывода:

```text
eth0 -> ../../devices/pci0000:00/0000:00:03.0/net/eth0
lo -> ../../devices/virtual/net/lo
```
##### Шаг 2. Выведите все атрибуты устройства:

```bash
udevadm info -a -p /sys/devices/pci0000:00/0000:00:03.0/net/eth0
```
Команда выведет атрибуты самого устройства и всех родительских устройств в цепочке ``sysfs`` — эти атрибуты можно использовать для написания правил udev.

**Задание 3.** Управление модулями ядра

Цель: выгрузить модуль ``intel_rapl_msr``, добавить его в чёрный список, перезагрузить систему и убедиться, что он не загружен, затем отменить изменения.

##### Шаг 1. Выгрузите модуль:

```bash
sudo modprobe -r intel_rapl_msr
```
##### Шаг 2. Добавьте модуль в чёрный список:

```bash
echo "blacklist intel_rapl_msr" | sudo tee /etc/modprobe.d/blacklist-rapl.conf
```
##### Шаг 3. Перезагрузите систему:

```bash
sudo reboot
```
##### Шаг 4. После перезагрузки проверьте, что модуль не загружен:

```bash
lsmod | grep intel_rapl_msr
```
Если команда не выводит ничего — модуль успешно заблокирован.

##### Шаг 5. Отмените изменения:

```bash
sudo rm /etc/modprobe.d/blacklist-rapl.conf
sudo modprobe intel_rapl_msr
```
**Задание 4** (дополнительное). Создание правила udev для монтирования USB-накопителя

Цель: настроить автоматическое монтирование USB-накопителя при подключении.

##### Шаг 1. Создайте файл правила:

```bash
sudo nano /etc/udev/rules.d/99-usb-mount.rules
```
Содержимое:

```text
KERNEL=="sd[a-z][0-9]", SUBSYSTEMS=="usb", ACTION=="add", RUN+="/bin/systemctl start usb-mount@%k.service"
KERNEL=="sd[a-z][0-9]", SUBSYSTEMS=="usb", ACTION=="remove", RUN+="/bin/systemctl stop usb-mount@%k.service"
```
Здесь ``%k`` — переменная ``udev``, которая подставляет имя устройства (например, ``sdb1``). При подключении устройства будет запущена служба ``usb-mount@sdb1.service``.

##### Шаг 2. Перезагрузите правила udev:

```bash
sudo udevadm control --reload-rules
```
##### Шаг 3. Проверьте работу правила, подключив USB-накопитель:

```bash
udevadm monitor --property
```
В выводе вы увидите событие add для устройства sdb1 и запуск соответствующей службы.

Ключевые команды для запоминания
```bash
# Просмотр информации об устройстве
udevadm info -a -p /sys/class/block/sda

# Мониторинг событий в реальном времени
udevadm monitor --udev

# Перезагрузка правил udev
udevadm control --reload-rules

# Загрузка модуля
sudo modprobe <module_name>

# Выгрузка модуля
sudo modprobe -r <module_name>

# Просмотр загруженных модулей
lsmod

# Информация о модуле
modinfo <module_name>
```

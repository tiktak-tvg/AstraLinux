### Управление файловыми системами в Astra Linux
Astra Linux, как и любой Linux-дистрибутив, использует единую модель работы с дисковыми устройствами: физический носитель → таблица разделов → файловая система → точка монтирования. Однако в Astra Linux есть важные особенности, связанные с сертификацией, мандатным контролем доступа и штатными графическими утилитами.

#### 🏗️ Архитектура подсистемы хранения данных
Подсистема хранения в Astra Linux построена по многоуровневому принципу:

**Физическое устройство** — жёсткий диск (HDD), твердотельный накопитель (SSD), USB-накопитель, оптический привод, виртуальный диск (например, /dev/vda в виртуальных машинах).

**Таблица разделов** — структура, описывающая разбиение носителя на логические области. Поддерживаются MBR (классическая) и GPT (современная, требуется для UEFI-загрузки).

**Файловая система** — способ организации данных на разделе (ext4, xfs, btrfs и др.).

**Точка монтирования** — каталог в едином дереве файловой системы, через который становится доступно содержимое раздела.

Astra Linux активно использует ``LVM (Logical Volume Manager)`` для гибкого управления дисковым пространством. 

При стандартной установке ОС создаются:

**/dev/vda1** — загрузочный раздел (/boot) с ФС ext2, не управляемый LVM (обязательное требование к загрузочным разделам).

**/dev/vda2** — физический том LVM (PV), на котором размещается группа томов (VG) с логическими томами (LV):

**/dev/VG/lv_root** — корневой раздел (/), ФС ext4.

**/dev/VG/lv_home** — домашний каталог (/home), ФС ext4.

Получить актуальную конфигурацию дисков и файловых систем можно командами:

```bash
# Состав дисков и дисковых разделов
lsblk

# Наличие свободного места
sudo parted /dev/vda print free
```
#### 🏷️ Именование файлов дисковых устройств
В Linux все устройства представлены файлами в каталоге /dev. Имена присваиваются ядром через подсистему udev по порядку обнаружения устройств.

Устройство          | Имя                    | Пример
------------------- | ---------------------- | -------------------------
SATA/SCSI/USB-диск 	| /dev/sdX	             | /dev/sda, /dev/sdb
Раздел на диске	    | /dev/sdXN	             | /dev/sda1, /dev/sdb2
Виртуальный диск (VirtIO)| /dev/vdX	         | /dev/vda
NVMe-накопитель	    | /dev/nvmeXnY	         | /dev/nvme0n1p1
Оптический привод	  | /dev/srX	             | /dev/sr0
LVM-том	            | /dev/mapper/ или /dev/VG/LV| /dev/mapper/VG-lv_root

Важно: Имена /dev/sdX не гарантируют постоянство. При подключении нового устройства порядок может измениться. Для стабильной идентификации используйте UUID раздела (получить: blkid /dev/sda1) или метки файловой системы.

#### 📂 Поддерживаемые типы файловых систем в Astra Linux
Согласно эксплуатационной документации Astra Linux Special Edition, для работы с конфиденциальной информацией на дисковых разделах должны использоваться файловые системы ext2/ext3/ext4, поддерживающие расширенные (в том числе мандатные) атрибуты и обеспечивающие гарантированное уничтожение информации.

Полный список поддерживаемых ФС:

Файловая система     | Поддержка в Astra Linux   | Назначение
-------------------- | ------------------------- | ------------------------------------------------------------------------
ext2	               | ✅ Все версии	           | Загрузочный раздел /boot, неприхотливые системы
ext3	               | ✅ Все версии	           | Журналируемая ФС (устаревшая)
ext4	               | ✅ Все версии	           | Основная ФС для корня, /home, данных
xfs	                 | ✅ Начиная с SE 1.7       | 	Высокопроизводительная ФС для больших объёмов
btrfs	               | ✅ SE 1.5+ (с ограничениями)| Снапшоты, сжатие, SSD-оптимизация
vfat (FAT32)	       | ✅	                       | Съёмные носители (USB-флешки)
ntfs	               | ✅ (только полуавтоматическое монтирование в сессиях с нулевой меткой)| Съёмные носители, созданные в Windows
iso9660 / udf	       | ✅	                       | Оптические диски (CD/DVD/BD)

Особенности файловых систем семейства ext

**ext2** не поддерживает журналирование, поэтому используется только для /boot — небольшого раздела, редко изменяемого.

**ext3** добавляет журналирование, но уступает ext4 по производительности и функциональности.

**ext4** — стандартная ФС для Astra Linux. Поддерживает:

- Журналирование (защита от сбоев).

- Расширенные атрибуты (включая мандатные метки безопасности).

- TRIM для SSD (автоматическое управление износом).

- Онлайн-расширение (resize2fs).

- Резервные копии супер блока для восстановления.

Другие ФС: ``xfs, btrfs, ISO9660, UDF``

**XFS** — высокопроизводительная журналируемая ФС, хорошо подходит для SSD и больших файлов. В Astra Linux SE x.7 поддерживается в дополнение к ext2/ext3/ext4. 
Расширяется только онлайн, через ``xfs_growfs``.

**BTRFS** — современная ФС с поддержкой снапшотов, сжатия и контроля целостности. 
Для SSD рекомендуется включать опции ``ssd, nossd или ssd_spread``. В Astra Linux применяется с ограничениями (не для всех сценариев).

**ISO9660 / UDF** — ФС для оптических дисков. UDF используется для DVD/BD и позволяет до записывать данные.

#### ⚙️ Создание разделов
**MBR vs GPT**

**MBR** — классическая таблица разделов. Поддерживает до 4 первичных разделов, максимальный объём диска — 2 ТБ. Для работы с MBR используется fdisk.

**GPT** — современная таблица разделов. Поддерживает до 128 разделов, диски объёмом более 2 ТБ, требуется для UEFI-загрузки. 
Для работы с GPT используется gdisk или parted. fdisk не умеет работать с GPT.

Инструменты разметки

Утилита      | Уровень          | Работа с GPT  |  Интерактивность 
------------ | --------------   | ------------- | ---------------------------
fdisk	       | Низкий	          | ❌	          | Текстовое меню
gdisk	       | Низкий	          | ✅	          | Текстовое меню
parted	     | Средний	        | ✅	          | Командный / интерактивный
gparted	     | Графический	    | ✅	          | Визуальный (Live-CD)

Пример создания разделов через gdisk (GPT)
```bash
# Установка gdisk
sudo apt install gdisk

# Запуск разметки диска /dev/sda
sudo gdisk /dev/sda
```
В интерактивном режиме:

**n** — создать новый раздел.

**t** — изменить тип раздела (например, ef00 для EFI System, 8300 для Linux filesystem, 8200 для swap).

**w** — записать изменения на диск.

⚠️ Внимание: Разметка диска уничтожает все данные на нём. Перед началом работы убедитесь, что выбрано правильное устройство.

#### 💾 Создание файловых систем (форматирование)
После создания раздела необходимо создать на нём файловую систему. Форматирование — это процесс записи специальных отметок на носитель, которые используются для разделения дорожек и секторов.

Команды создания ФС

Команда                      | Файловая система       
---------------------------- | ----------------------------
sudo mkfs.ext4 /dev/sda1	   | ext4
sudo mkfs.ext3 /dev/sda1	   | ext3
sudo mkfs.ext2 /dev/sda1	   | ext2
sudo mkfs.xfs /dev/sda1	     | xfs
sudo mkfs.btrfs /dev/sda1	   | btrfs
sudo mkfs.vfat -F 32 /dev/sda1  | vfat (FAT32)

Пример: создание ext4 с меткой
```bash
sudo mkfs.ext4 -L DATA /dev/sda1
```
После создания ФС можно получить её UUID:
```bash
sudo blkid /dev/sda1
```
Примечание: Для создания ФС ext4 на USB-накопителе в Astra Linux используется стандартная команда mkfs.ext4 $DEVICE.

#### 🔗 Монтирование файловых систем
Ручное монтирование

Ручное монтирование выполняется командой mount. 

В Astra Linux Special Edition ручное монтирование непривилегированными пользователями запрещено — доступно только суперпользователю.

```bash
# Создать точку монтирования
sudo mkdir -p /mnt/data

# Смонтировать раздел
sudo mount /dev/sda1 /mnt/data

# Смонтировать с опциями
sudo mount -o rw,noexec /dev/sda1 /mnt/data

# Просмотреть примонтированные ФС
mount | grep sda1
```
Автоматическое монтирование при загрузке

Для автоматического монтирования при загрузке системы используется файл /etc/fstab. 

Формат записи:

```text
<устройство> <точка_монтирования> <тип_ФС> <опции> <dump> <pass>
```


 Поле                   | Описание      
----------------------- | ----------------------------
<устройство>	           | UUID, LABEL или путь к устройству
<точка_монтирования>	   | Каталог, куда монтируется ФС
<тип_ФС>	               | ext4, xfs, vfat и т.д. (или auto)
<опции>	            |  Параметры монтирования (см. ниже)
dump        |  0 — не резервировать, 1 — резервировать
<pass>          |  Порядок проверки fsck (0 — не проверять, 1 — корень, 2 — остальные)


Пример записи в /etc/fstab
```text
# Корневой раздел
UUID=cb7a7da2-70d6-4e67-86b7-76a503466577 / ext4 errors=remount-ro 0 1

# Домашний раздел
UUID=12345678-1234-1234-1234-123456789abc /home ext4 defaults 0 2

# Данные
UUID=abcdef01-2345-6789-abcd-ef0123456789 /mnt/data ext4 defaults,noatime 0 2

# swap
UUID=87654321-4321-4321-4321-cba987654321 none swap sw 0 0
```
Параметры монтирования

Параметр                | Описание      
----------------------- | ----------------------------
defaults	              | rw,suid,dev,exec,auto,nouser,async
noatime	                | Не обновлять время доступа (снижает нагрузку на диск)
nodev	                  | Запретить интерпретацию файлов устройств
noexec	                | Запретить выполнение бинарных файлов
nosuid	                | Игнорировать биты SUID/SGID
ro	                    | Только чтение
rw	                    | Чтение и запись
user	                  | Разрешить монтирование непривилегированному пользователю
noauto	                | Не монтировать автоматически при загрузке
errors=remount-ro	      | При ошибках перемонтировать в режим «только чтение»

Особенности Astra Linux: /etc/fstab.pdac

В Astra Linux Special Edition используется дополнительный файл — /etc/fstab.pdac, который управляет монтированием съёмных устройств с учётом мандатного контроля доступа.

Содержимое /etc/fstab.pdac по умолчанию:

```text
# USB flash
/dev/*fat /run/user/*/media/* auto owner,group,noauto,nodev,noexec,iocharset=utf8,defaults 0 0
/dev/*ntfs* /run/user/*/media/* auto owner,group,noauto,nodev,noexec,iocharset=utf8,defaults 0 0
/dev/sd*ext* /run/user/*/media/* auto owner,group,nodev,noexec,noauto,defaults 0 0

# CD/DVD/BD
/dev/s*udf /run/user/*/media/* udf owner,group,nodev,noexec,noauto,defaults 0 0
/dev/s*iso9660 /run/user/*/media/* iso9660 owner,group,nodev,noexec,noauto,defaults 0 0

# Other
/dev/sd* /run/user/*/media/* auto owner,group,nodev,noexec,noauto,iocharset=utf8,defaults 0 0
```
⚠️ Важно: Правило по умолчанию для неучтённых устройств (/dev/sd*) содержит параметр iocharset, который несовместим с ФС ext2/ext3/ext4/xfs. При обнаружении такого раздела запрос на монтирование выдаётся, но попытка завершается ошибкой. Для корректной работы с ext4 на съёмных носителях в файл /etc/fstab.pdac необходимо добавить строку с правильными параметрами.

Для монтирования NVMe-накопителей следует использовать таблицу /etc/fstab.

Полуавтоматическое монтирование

В Astra Linux существует механизм полуавтоматического монтирования, который позволяет непривилегированным пользователям подключать съёмные носители через графическую утилиту (в разных версиях — fly-admin-reflex или astra-fly-reflex).

#### 🧰 Утилиты для работы с файловыми системами
Информация о дисковом пространстве
```bash
# Свободное место на примонтированных ФС
df -h

# Занятое место каталогами
du -sh /home/user/*

# Информация о блочных устройствах
lsblk

# UUID и типы ФС
blkid
```
Проверка и восстановление ФС

Команда              | Назначение      
-------------------- | ----------------------------
sudo fsck /dev/sda1	 | Проверка и восстановление ФС
sudo e2fsck -f /dev/sda1	 | Принудительная проверка ext2/3/4
sudo xfs_repair /dev/sda1	 | Восстановление XFS
sudo btrfs check /dev/sda1	 | Проверка BTRFS

Управление параметрами ext2/3/4

Команда              | Назначение      
-------------------- | ----------------------------
sudo tune2fs -L LABEL /dev/sda1	| Установить метку ФС
sudo tune2fs -m 1 /dev/sda1	 | Установить процент зарезервированного пространства
sudo resize2fs /dev/sda1	  | Расширить/сжать ФС ext4
sudo dumpe2fs /dev/sda1	 | Показать параметры суперблока

Утилиты для XFS и BTRFS
```bash
# XFS: расширение онлайн (ФС должна быть примонтирована)
sudo xfs_growfs /mnt/data

# BTRFS: проверка и балансировка
sudo btrfs filesystem df /mnt/data
sudo btrfs balance start /mnt/data
```
Графические утилиты
GParted — мощный графический редактор разделов (доступен через Live-CD или установку пакета gparted).

Baobab («Анализатор использования дисков») — визуализация занятого пространства. Доступен в меню «Пуск → Системные → Анализатор использования дисков».

astra-systemsettings — модуль «Устройства и правила» для настройки контроля подключения устройств.

#### 💻 Практическая работа: 
Разметка диска, создание ФС, автоматическое монтирование
Цель: Создать раздел на дополнительном диске, отформатировать его в ext4, настроить автоматическое монтирование при загрузке.

⚠️ Внимание: Все операции выполняются на дополнительном диске (например, /dev/sdb или /dev/vdb). Не используйте диск, на котором установлена ОС.

Шаг 1. Просмотр текущей конфигурации
bash
# Список всех блочных устройств
lsblk

# Информация о свободном месте
sudo parted /dev/sdb print free
Шаг 2. Создание раздела
bash
# Установка gdisk (если не установлен)
sudo apt install gdisk

# Запуск разметки
sudo gdisk /dev/sdb
В интерактивном режиме:

text
Command (? for help): n          # Новый раздел
Partition number: 1              # Номер раздела
First sector: (Enter)            # По умолчанию
Last sector: (Enter)             # Весь диск
Hex code or GUID: 8300           # Linux filesystem

Command (? for help): w          # Записать изменения
Do you want to proceed? (Y/N): Y
Шаг 3. Создание файловой системы
bash
# Форматирование раздела в ext4 с меткой DATA
sudo mkfs.ext4 -L DATA /dev/sdb1

# Получение UUID раздела
sudo blkid /dev/sdb1
Пример вывода:

text
/dev/sdb1: LABEL="DATA" UUID="a1b2c3d4-e5f6-7890-abcd-ef1234567890" TYPE="ext4"
Шаг 4. Ручное монтирование (проверка)
bash
# Создание точки монтирования
sudo mkdir -p /mnt/data

# Монтирование
sudo mount /dev/sdb1 /mnt/data

# Проверка
df -h /mnt/data

# Создание тестового файла
echo "Astra Linux test" | sudo tee /mnt/data/test.txt

# Размонтирование
sudo umount /mnt/data
Шаг 5. Настройка автоматического монтирования
bash
# Резервная копия fstab
sudo cp /etc/fstab /etc/fstab.bak

# Добавление записи в /etc/fstab (используя UUID)
echo "UUID=a1b2c3d4-e5f6-7890-abcd-ef1234567890 /mnt/data ext4 defaults,noatime 0 2" | sudo tee -a /etc/fstab
Проверка синтаксиса /etc/fstab:

bash
# Проверить, что все ФС могут быть смонтированы
sudo mount -a

# Если ошибок нет — проверка успешна
df -h /mnt/data
Шаг 6. Перезагрузка и проверка
bash
sudo reboot
После загрузки:

bash
# Проверить, что раздел смонтирован автоматически
mount | grep sdb1
df -h /mnt/data
Шаг 7. Проверка файла
bash
cat /mnt/data/test.txt
# Должно вывести: Astra Linux test
Альтернатива: настройка через /etc/fstab.pdac (для съёмных носителей)
Если диск будет использоваться как съёмный, добавьте правило в /etc/fstab.pdac:

bash
# Для ext4 на съёмном носителе (замените UUID)
echo "UUID=a1b2c3d4-e5f6-7890-abcd-ef1234567890 /run/user/1000/media/data auto user,noauto,nodev,noexec 0 0" | sudo tee -a /etc/fstab.pdac
⚠️ Ключевые особенности Astra Linux
Мандатный контроль целостности (МКЦ): В SE с включённым МКЦ операции с дисками и ФС должны выполняться с высоким уровнем целостности (через sudo -s или аналогичные механизмы).

Только сертифицированные ФС: Для работы с конфиденциальной информацией на учтённых носителях допускаются только ext2/ext3/ext4 (и xfs с SE 1.7). Использование других ФС может нарушить требования сертификации.

Гарантированное уничтожение: ФС ext2/3/4 обеспечивают гарантированное стирание информации, что критично для защищённых систем.

/etc/fstab.pdac: Дополнительный файл монтирования, учитывающий мандатные метки и правила для съёмных устройств.

Запрет ручного монтирования: В SE непривилегированные пользователи не могут выполнять mount вручную — только через полуавтоматическое монтирование или с правами суперпользователя.

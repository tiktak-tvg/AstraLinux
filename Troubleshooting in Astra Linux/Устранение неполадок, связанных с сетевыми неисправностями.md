### Устранение неполадок, связанных с сетевыми неисправностями в Astra Linux
#### 1. Выявление аппаратных проблем в работе сетевых интерфейсов и сетевых соединений
Аппаратные проблемы проявляются в отсутствии линка, ошибках передачи, потерях пакетов, падении скорости.

##### 1.1. Проверка состояния интерфейса
```bash
# Просмотр всех интерфейсов и их состояния
ip link show

# Проверка конкретного интерфейса
ip link show eth0

# Статистика по интерфейсу (ошибки, дропы)
ip -s link show eth0

# Подробная статистика с ошибками
ip -s -s link show eth0
```
Пример вывода:

```text
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
    link/ether 52:54:00:36:8f:d1 brd ff:ff:ff:ff:ff:ff
    RX: bytes  packets  errors  dropped overrun mcast
    15234567   12345    0       2       0       145
    TX: bytes  packets  errors  dropped carrier collsns
    8765432    9876     3       0       0       0
```
Интерпретация:
- state UP — интерфейс активен, state DOWN — не активен
- LOWER_UP — есть физический линк (кабель подключён)
- errors — ошибки передачи (растут — проблема с кабелем/картой)
- dropped — потерянные пакеты (высокое значение — перегрузка)
- overrun — переполнение буфера
- carrier — проблемы с несущей (кабель/порт коммутатора)

##### 1.2. Проверка драйвера и устройства
```bash
# Определить модель сетевой карты
lspci | grep -i ethernet
lspci -k | grep -A 3 -i ethernet

# Проверить загрузку драйвера
lsmod | grep -i e1000
dmesg | grep -i eth0
dmesg | grep -i -E "error|fail" | grep -i net

# Проверить настройки скорости и дуплекса
sudo ethtool eth0
sudo ethtool -S eth0
```
Пример вывода ethtool:

```text
Settings for eth0:
    Supported ports: [ TP ]
    Speed: 1000Mb/s
    Duplex: Full
    Auto-negotiation: on
    Link detected: yes
Если Link detected: no — проблема с кабелем или портом коммутатора.
```
##### 1.3. Диагностика потерь и задержек
```bash
# Проверка потерь на шлюз
ping -c 100 -i 0.2 192.168.1.1

# Проверка через конкретный интерфейс
ping -I eth0 -c 10 8.8.8.8

# Проверка с большим размером пакета (проверка MTU)
ping -M do -s 1472 -c 4 8.8.8.8

# Проверка фрагментации (поиск оптимального MTU)
ping -M do -s 1400 -c 4 8.8.8.8
```
Если пакеты теряются на шлюзе — проблема в кабеле, коммутаторе или карте. Если после шлюза — проблема в провайдере или дальше.

##### 1.4. Пример комплексной диагностики
```bash
# 1. Проверка линка
ip link show eth0 | grep -E "state|LOWER"

# 2. Проверка ошибок
ip -s link show eth0 | grep -A 3 "RX:"

# 3. Проверка драйвера
dmesg | tail -30 | grep -i eth

# 4. Проверка ethtool
sudo ethtool eth0 | grep -E "Speed|Duplex|Link"

# 5. Проверка потерь
ping -c 20 -i 0.2 192.168.1.1
```
#### 2. Устранение ошибок в настройках сетевых интерфейсов
##### 2.1. Проверка текущей конфигурации
```bash

ip a

ip -4 a

# Просмотр маршрутов

ip n

# Статус устройств в NetworkManager
nmcli device status

# Список подключений
nmcli connection show

# Детали конкретного подключения
nmcli connection show "Wired connection 1"

# Информация об устройстве
nmcli device show eth0
```
##### 2.2. Типичные ошибки и их решение
Ошибка: интерфейс в состоянии DOWN

```bash
# Поднять интерфейс
sudo ip link set eth0 up

# Проверить
ip link show eth0
```
Ошибка: отсутствует IP-адрес

```bash
# Назначить статический IP
sudo ip addr add 192.168.1.100/24 dev eth0

# Или через nmcli
sudo nmcli con mod "Wired connection 1" ipv4.addresses 192.168.1.100/24
sudo nmcli con mod "Wired connection 1" ipv4.gateway 192.168.1.1
sudo nmcli con mod "Wired connection 1" ipv4.dns "8.8.8.8 8.8.4.4"
sudo nmcli con mod "Wired connection 1" ipv4.method manual
sudo nmcli con up "Wired connection 1"
```
Ошибка: конфликт IP-адресов

```bash
# Проверка ARP-таблицы на дубликаты
ip n | awk '{print $1}' | sort | uniq -d

# Обнаружение дубликата IP через arping
sudo arping -I eth0 -c 3 192.168.1.100

# Или через nmap
sudo nmap -sn 192.168.1.0/24
```
Ошибка: неверный MTU

```bash
# Проверка текущего MTU
ip link show eth0 | grep mtu

# Изменение MTU
sudo ip link set eth0 mtu 1400

# Постоянно через nmcli
sudo nmcli con mod "Wired connection 1" 802-3-ethernet.mtu 1400
sudo nmcli con up "Wired connection 1"
```

#### 3. Устранение ошибок в настройке маршрутизации
##### 3.1. Проверка таблицы маршрутизации
```bash
# Просмотр всех маршрутов
ip r

# Маршрут по умолчанию
ip r show default

# Маршруты для конкретной сети
ip r show 10.0.0.0/8

# Кэш маршрутизации
ip r show cache
```
Пример вывода:

```text
default via 192.168.1.1 dev eth0 proto static metric 100
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.100 metric 100
10.0.0.0/8 via 192.168.1.254 dev eth0
```
##### 3.2. Типичные ошибки
Ошибка: отсутствует маршрут по умолчанию

```bash
# Добавить маршрут
sudo ip route add default via 192.168.1.1

# Постоянно через nmcli
sudo nmcli con mod "Wired connection 1" ipv4.gateway 192.168.1.1
sudo nmcli con up "Wired connection 1"
```
Ошибка: неверный маршрут

```bash
# Удалить неверный маршрут
sudo ip route del 10.0.0.0/8 via 192.168.1.254

# Добавить правильный
sudo ip route add 10.0.0.0/8 via 192.168.1.253
```
Ошибка: несколько маршрутов по умолчанию

```bash
# Просмотр всех default-маршрутов
ip r | grep default

# Удаление лишнего
sudo ip route del default via 192.168.1.100
```
##### 3.3. Диагностика маршрута
```bash
# Трассировка маршрута
traceroute 8.8.8.8

# Без резолвинга имён (быстрее)
traceroute -n 8.8.8.8

# С указанием конкретного интерфейса
traceroute -i eth0 8.8.8.8

# Трассировка по TCP (если ICMP блокируется)
sudo traceroute -T -p 443 ya.ru

# Трассировка с большим числом запросов
traceroute -q 3 -m 20 8.8.8.8
```
Пример вывода:

```text
traceroute to 8.8.8.8 (8.8.8.8), 30 hops max, 60 byte packets
 1  192.168.1.1 (192.168.1.1)  0.512 ms  0.489 ms  0.470 ms
 2  10.0.0.1 (10.0.0.1)  5.123 ms  5.089 ms  5.045 ms
 3  * * *
 4  8.8.8.8 (8.8.8.8)  15.234 ms  15.201 ms  15.156 ms
* * * — узел не отвечает на ICMP (не обязательно проблема).
```

```bash

#### 4. Устранение ошибок, связанных со службой доменных имен DNS
##### 4.1. Проверка конфигурации DNS
```bash
# Просмотр /etc/resolv.conf
cat /etc/resolv.conf

# Проверка через resolvectl
resolvectl status

# Проверка настройки NetworkManager
nmcli device show eth0 | grep -i dns
nmcli connection show "Wired connection 1" | grep -i dns
```
Пример /etc/resolv.conf:

```text
nameserver 8.8.8.8
nameserver 8.8.4.4
search example.com
```
##### 4.2. Диагностика с помощью dig
```bash
# Проверка A-записи
dig ya.ru

# Короткий ответ
dig +short ya.ru

# Запрос через конкретный сервер
dig @8.8.8.8 ya.ru

# Обратный запрос
dig -x 8.8.8.8

# MX-запись
dig ya.ru MX

# NS-запись
dig ya.ru NS

# TXT-запись
dig ya.ru TXT

# Трассировка DNS
dig +trace ya.ru

# Только ответ
dig +noall +answer ya.ru

# Проверка DNSSEC
dig +dnssec ya.ru
```
Интерпретация: если dig @8.8.8.8 ya.ru работает, а dig ya.ru — нет, проблема в локальном DNS-сервере.

##### 4.3. Диагностика с помощью nslookup
```bash
# Простой запрос
nslookup ya.ru

# Через конкретный сервер
nslookup ya.ru 8.8.8.8

# Обратный запрос
nslookup 8.8.8.8

# Интерактивный режим
nslookup
> server 8.8.8.8
> set type=MX
> ya.ru
> exit
```
##### 4.4. Типичные проблемы DNS
Проблема: неверный DNS-сервер

```bash
# Проверка доступности DNS-сервера
ping -c 3 8.8.8.8
nc -zv 8.8.8.8 53

# Изменение DNS через nmcli
sudo nmcli con mod "Wired connection 1" ipv4.dns "8.8.8.8,8.8.4.4"
sudo nmcli con mod "Wired connection 1" ipv4.ignore-auto-dns yes
sudo nmcli con up "Wired connection 1"
```
Проблема: медленный резолвинг

```bash
# Проверка времени ответа
dig ya.ru | grep "Query time"

# Проверка systemd-resolved
systemctl status systemd-resolved
journalctl -u systemd-resolved -n 50
```
Проблема: DNS-сервер не отвечает

bash
# Проверка порта 53
sudo ss -ulnp | grep :53
sudo ss -tlnp | grep :53

# Захват DNS-трафика
sudo tcpdump -i eth0 -n port 53
```
#### 5. Выявление и устранение ошибок, связанных с недоступностью сетевых служб
##### 5.1. Проверка слушающих портов
```bash
# Все слушающие порты
ss -tlnp

# UDP-порты
ss -ulnp

# Все соединения
ss -tan

# Установленные соединения
ss -tn state established

# Сводка
ss -s

# По конкретному порту
ss -tnp '( sport = :22 or dport = :22 )'

# По процессу
ss -tnp | grep nginx
```
Пример вывода:

```text
State   Recv-Q  Send-Q  Local Address:Port   Peer Address:Port  Process
LISTEN  0       128     0.0.0.0:22           0.0.0.0:*          users:(("sshd",pid=1234,fd=3))
LISTEN  0       511     0.0.0.0:80           0.0.0.0:*          users:(("nginx",pid=2345,fd=6))
```
##### 5.2. Проверка через netstat (устаревший)
```bash
# Слушающие порты
netstat -tulnp

# Все соединения
netstat -tan

# Маршруты
netstat -rn

# Статистика интерфейсов
netstat -i

# Статистика протоколов
netstat -s
```
##### 5.3. Проверка доступности службы через nmap
```bash
# Проверка конкретного порта
nmap -p 80,443 192.168.1.1

# Быстрое сканирование топ-100 портов
nmap 192.168.1.1

# Определение версий служб
nmap -sV 192.168.1.1

# TCP SYN-сканирование (нужен root)
sudo nmap -sS 192.168.1.1

# UDP-сканирование
sudo nmap -sU 192.168.1.1

# Определение ОС
sudo nmap -O 192.168.1.1

# Все порты
nmap -p- 192.168.1.1

# С NSE-скриптами
nmap --script http-title 192.168.1.1
nmap --script vuln 192.168.1.1
```
Пример вывода:

```text
PORT    STATE SERVICE  VERSION
22/tcp  open  ssh      OpenSSH 8.9p1
80/tcp  open  http     nginx 1.18.0
443/tcp open  ssl/http nginx 1.18.0
```
##### 5.4. Проверка через tcpdump
```bash
# Захват трафика на конкретный порт
sudo tcpdump -i eth0 port 80

# По хосту
sudo tcpdump -i eth0 host 192.168.1.1

# Только SYN-пакеты (попытки подключения)
sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0'

# Захват с записью в файл
sudo tcpdump -i eth0 -w /tmp/capture.pcap port 80

# Чтение из файла
sudo tcpdump -r /tmp/capture.pcap -n

# Без резолвинга имён
sudo tcpdump -i eth0 -nn

# Показать содержимое в ASCII
sudo tcpdump -i eth0 -A port 80

# Показать содержимое в HEX+ASCII
sudo tcpdump -i eth0 -X port 80

# Ограничить количество пакетов
sudo tcpdump -i eth0 -c 100
```
Пример вывода:

```text
14:30:15.123456 IP 192.168.1.100.54321 > 192.168.1.1.80: Flags [S], seq 1234567890, win 64240, options [mss 1460,sackOK,TS val 12345 ecr 0,nop,wscale 7], length 0
14:30:15.123789 IP 192.168.1.1.80 > 192.168.1.100.54321: Flags [S.], seq 987654321, ack 1234567891, win 65535, options [mss 1460,nop,wscale 8], length 0
14:30:15.124012 IP 192.168.1.100.54321 > 192.168.1.1.80: Flags [.], ack 1, win 502, length 0
```
Интерпретация:
- Flags [S] — SYN (попытка подключения)
- Flags [S.] — SYN-ACK (сервер отвечает)
- Flags [.] — ACK (подключение установлено)
- Flags [F] — FIN (закрытие соединения)
- Flags [R] — RST (сброс соединения — порт закрыт или служба не отвечает)

##### 5.5. Проверка через Wireshark (графический анализ)
Wireshark — графическая утилита для глубокого анализа пакетов. Установка:

```bash
sudo apt install wireshark
sudo usermod -aG wireshark $USER
```
Использование:

Запустите Wireshark: sudo wireshark.

Выберите интерфейс для захвата.

Примените фильтры:

Фильтр                  | Описание                      
----------------------- | ----------------------------- 
ip.addr == 192.168.1.1	 | Пакеты с конкретным адресом
tcp.port == 80	 | TCP-трафик порта 80
udp.port == 53	 | DNS-трафик
http	 | HTTP-трафик
tcp.flags.syn == 1	 | Только SYN-пакеты
tcp.flags.reset == 1	 | Только RST-пакеты
icmp	 | ICMP-трафик

Анализ: Statistics → Conversations, Statistics → Protocol Hierarchy, Follow → TCP Stream.

Преимущества: визуальный анализ, декодирование протоколов, восстановление потоков, статистика.

##### 5.6. Комплексный пример диагностики недоступности веб-службы
Симптом: сайт http://example.com не открывается.

```bash
# 1. Проверка доступности хоста
ping -c 4 example.com

# 2. Проверка DNS
dig +short example.com
nslookup example.com

# 3. Проверка маршрута
traceroute -n example.com

# 4. Проверка порта 80
nc -zv example.com 80
nmap -p 80,443 example.com

# 5. Проверка HTTP-запроса
curl -v http://example.com
curl -I http://example.com

# 6. Захват трафика
sudo tcpdump -i eth0 -n host example.com and port 80 -c 20

# 7. Проверка через Wireshark (если нужно)
sudo wireshark
# Фильтр: ip.addr == <IP example.com> && tcp.port == 80
```
Возможные причины:

Симптом                 | Причина                       | Решение
----------------------- | ----------------------------- | -------------------------
ping не проходит	 | Проблема с сетью/маршрутом	 | Проверить ip r, traceroute
ping проходит, DNS не резолвит	 | Проблема с DNS	 | Проверить /etc/resolv.conf, dig @8.8.8.8
DNS работает, порт закрыт	 | Служба не запущена или firewall	 | Проверить ss -tlnp, nmap, iptables -L
Порт открыт, HTTP не отвечает	 | Проблема на стороне сервера	 | Захватить трафик, проверить логи сервера
RST-пакеты в tcpdump	 | Firewall блокирует	 | Проверить правила firewall

#### 7. Комплексный пример: полная диагностика сетевой проблемы
Симптом: пользователь не может открыть корпоративный сайт.

```bash
# Шаг 1. Проверка интерфейса
ip a
ip link show eth0 | grep -E "state|LOWER"
ip -s link show eth0 | grep -A 3 "RX:"

# Шаг 2. Проверка IP и маршрутов
ip r
ping -c 4 192.168.1.1  # шлюз

# Шаг 3. Проверка внешнего адреса
ping -c 4 8.8.8.8

# Шаг 4. Проверка DNS
cat /etc/resolv.conf
dig +short corporate.example.com
dig @8.8.8.8 corporate.example.com

# Шаг 5. Проверка маршрута
traceroute -n corporate.example.com

# Шаг 6. Проверка порта
nc -zv corporate.example.com 443
nmap -p 443 corporate.example.com

# Шаг 7. Проверка HTTP(S)
curl -v https://corporate.example.com
curl -I https://corporate.example.com

# Шаг 8. Захват трафика
sudo tcpdump -i eth0 -n host corporate.example.com and port 443 -c 30

# Шаг 9. Проверка firewall
sudo iptables -L -n | grep -E "443|DROP|REJECT"
sudo ufw status

# Шаг 10. Проверка служб
ss -tnp | grep -E ":443|:80"
```
Алгоритм локализации:
- Нет линка → кабель, порт, драйвер.
- Нет IP → DHCP или статическая настройка.
- Нет маршрута → ip r, шлюз, таблица маршрутизации.
- Нет DNS → /etc/resolv.conf, DNS-сервер.
- Порт закрыт → firewall, служба.

Служба не отвечает → tcpdump, логи сервера.

RST-пакеты → firewall или служба не слушает порт.

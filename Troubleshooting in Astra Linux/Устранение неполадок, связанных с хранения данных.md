#### Восстановление разделов диска и таблицы разделов
Для восстановления потерянных или повреждённых разделов используется утилита testdisk. Она анализирует информацию на блочном устройстве и пытается найти известные структуры данных, такие как дисковые разделы. Пакет testdisk не входит в стандартную установку и требует отдельной инсталляции.

Пошаговый пример:
- Установка: sudo apt install testdisk
- Запуск: sudo testdisk /dev/sdX (где /dev/sdX — ваш проблемный диск).
- Выбор диска: В интерфейсе выберите нужный диск и нажмите Proceed.
- Тип таблицы разделов: Обычно testdisk определяет его автоматически (Intel для MBR, EFI GPT для GPT).
- Анализ: Выберите Analyse для анализа текущей структуры разделов.
- Поиск разделов: Для поиска потерянных разделов выберите Quick Search.
- Сохранение: Если разделы найдены, выберите Write, чтобы записать новую таблицу разделов на диск.

#### Исправление отказа монтирования корневой файловой системы
Отказ монтирования корневой ФС часто связан с её повреждением. Для исправления необходимо загрузиться в режиме восстановления с установочного диска Astra Linux.

Порядок действий:
- Загрузка: Выберите режим восстановления при загрузке с установочного носителя.
- Определение раздела: Найдите раздел с корневой ФС (например, /dev/sda1).

Проверка ФС: Выполните команду fsck для этого раздела. Важно: проверяемая ФС не должна быть смонтирована.

```bash
fsck -f -c /dev/sda1
```
Опция -f запускает принудительную проверку, -c ищет сбойные блоки.

Автоматическое исправление: Для автоматического исправления ошибок без запросов используйте опцию -p:

```bash
fsck -p /dev/sda1
```
Настройка автоматической проверки: Чтобы система проверяла корневую ФС при каждой загрузке, в файле /etc/fstab в строке для этой ФС укажите в последнем поле значение 1.

#### Исправление отказа монтирования некорневых ФС (/usr, /home и др.)
Проблемы с монтированием некорневых ФС могут быть вызваны ошибками в файловой системе или неверными записями в /etc/fstab.

Диагностика и решение:
- Проверка ФС: Если система загружается, но ФС не монтируется, попробуйте сначала размонтировать её (sudo umount /dev/sdb1), а затем проверить с помощью fsck.
- Проверка /etc/fstab: Убедитесь, что синтаксис строки для этой ФС корректен. В последнем поле должен стоять 0 (не проверять) или 2 (проверять после корневой).
- Режим восстановления: Если система не загружается, войдите в режим восстановления, найдите проблемный раздел и проверьте его с помощью fsck. После исправления можно вручную смонтировать раздел в нужную точку (mount /dev/sdb1 /usr) и продолжить работу.

#### Решение проблем с логическими томами (LVM)
LVM (Logical Volume Manager) позволяет гибко управлять дисковым пространством. Проблемы могут возникать при повреждении метаданных или сбоях в зеркалах.

Восстановление зеркала: Если вы используете RAID на базе LVM, для запуска процедуры восстановления (sync) зеркала можно использовать команду:

```bash
sudo lvchange --syncaction repair <VG>/<LV>
```
Проверить статус можно командой ``sudo lvs -o +raid_sync_action,raid_mismatch_count``.

Восстановление конфигурации: В случае потери конфигурации группы томов (VG) можно попытаться восстановить её из резервной копии метаданных с помощью команды vgcfgrestore.

#### Решение проблем с нехваткой места
Для диагностики используются две основные команды: df (Disk Free) и du (Disk Used).

``df -h``: Показывает свободное место на всех смонтированных файловых системах в удобном формате.

```bash
df -h
```
``du -sh /path/to/dir``: Показывает суммарный размер, занимаемый указанным каталогом, что помогает найти «пожирателей» дискового пространства.

```bash
sudo du -sh /var/* | sort -rh | head -10
```
Эта команда выведет топ-10 самых больших каталогов в /var.

#### Замена неисправного дискового устройства
При замене диска необходимо перенести на него все данные со старого. Для клонирования дисков используется утилита dd.

Пример клонирования:

```bash
sudo dd if=/dev/sdX of=/dev/sdY bs=64K conv=noerror,sync
```
- if= — исходный (неисправный) диск.
- of= — целевой (новый) диск.
- bs=64K — размер блока для ускорения копирования.
- conv=noerror,sync — продолжать копирование при ошибках чтения и синхронизировать данные.

> Важно: Этот метод создаёт точную побайтовую копию, включая таблицу разделов и загрузочный сектор.

#### Решение проблем с потерей/удалением файлов и каталогов
Для восстановления удалённых файлов используется утилита photorec, входящая в пакет testdisk.

Пример использования:
- Установка: sudo apt install testdisk
- Запуск: sudo photorec /dev/sdXY (где /dev/sdXY — раздел, с которого нужно восстановить данные).
- Выбор файлов: В интерфейсе выберите типы файлов для восстановления (File Opt) и режим поиска (Free для удалённых файлов).
- Сохранение: Выберите каталог для сохранения восстановленных файлов. Важно: никогда не сохраняйте восстановленные файлы на тот же диск, с которого они были удалены.

#### Выявление причин и обстоятельств потери данных
Для выяснения причин потери данных необходимо проанализировать системные журналы. Используйте journalctl для просмотра сообщений ядра и служб, а также проверяйте логи приложений в /var/log/.
- Ошибки файловой системы: journalctl -k | grep -i error или dmesg | grep -i error.
- Действия пользователей: Проверьте историю команд (history) и логи аутентификации (/var/log/auth.log).
- Аппаратные сбои: smartctl -a /dev/sda для проверки SMART-атрибутов диска.

#### Восстановление файлов и принятие мер по предотвращению дальнейшей утери данных
Восстановление: Помимо photorec, для восстановления файлов на ext3/ext4 можно использовать ext4magic. Она показала высокую эффективность в Astra Linux.

Пример:

```bash
sudo ext4magic -m /dev/sdXY
```
Эта команда восстановит все удалённые файлы с раздела ``/dev/sdXY`` в подкаталог ``RECOVERED``.

Предотвращение потери данных: Лучший способ — регулярное резервное копирование. В Astra Linux для этого доступны следующие инструменты:

``rsync``: Для локального и удалённого копирования с минимальными затратами трафика.

```bash
rsync -a --xattrs --acls /home/user/ /backup/user/
```
Ключ --xattrs позволяет сохранять классификационные метки (мандатные атрибуты), что критически важно для Astra Linux Special Edition.

tar: Для создания архивов. Также поддерживает сохранение расширенных атрибутов с ключом --xattrs.

```bash
tar --xattrs -czf /backup/home_backup.tar.gz /home/user/
```

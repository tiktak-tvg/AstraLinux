### Устранение неполадок, связанных с установкой и обновлением ПО в Astra Linux
#### 1. Проверка целостности установленного программного обеспечения
В Astra Linux для контроля целостности ПО используются средства динамического и регламентного контроля. Основные инструменты — утилита gostsum (подсчёт контрольных сумм по ГОСТ) и программа afick (Another File Integrity Checker).

##### 1.1. Утилита gostsum
**gostsum** — утилита для подсчёта контрольных сумм файлов с использованием алгоритмов ГОСТ. По умолчанию применяется ГОСТ Р 34.11-2012 с длиной хэш-кода 256 бит.

Проверка контрольных сумм файлов в deb-пакете:

Функционал проверки контрольных сумм файлов в deb-пакетах добавлен в программу gostsum начиная с версии 2.2.0. Для проверки используется опция -e или --deb, которая включает режим работы с .deb-пакетом: для каждого файла из указанного пакета будут напечатаны контрольные суммы.

```bash
# Проверка контрольных сумм файлов в deb-пакете
gostsum -e cabextract_1.6-1_amd64.deb
```
Пример вывода:

```text
#deb : cabextract_1.6-1_amd64.deb
cffddad20f64bb9460691f981cf1de0d74d3573400ffb05de6beb89a2050cc10  /usr/bin/cabextract
79973e9c413a85ded2cd4676fb85d230f2c91d5c2c89db4d095941bfa7ec02db  /usr/share/apps/konqueror/servicemenus/cabextract.desktop
```
Проверка целостности установочного диска:

Эталонные значения контрольных сумм указаны в файле gostsums.txt, расположенном в корневом каталоге технологического установочного диска. Для проведения контроля целостности необходимо смонтировать установочный диск и выполнить команду:

```bash
sh ./integrity-check ./gostsums.txt
```
Проверка целостности внеочередных обновлений:

Контроль целостности внеочередных обновлений ОС осуществляется с помощью контрольных сумм, рассчитанных с использованием программ gostsum (для файлов) и gostsum_from_deb (для deb-пакетов).

Особенность Astra Linux SE 3.8.1: перед первым выполнением проверки целостности файлов ОС с помощью инструмента gostsum следует установить пакет gostsums-templates:

```bash
sudo apt install gostsums-templates
```
##### 1.2. Программа afick
*afick* — программа регламентного контроля целостности файловой системы. Позволяет отслеживать изменения в файлах, правах доступа, расширенных атрибутах и метках безопасности.

Построение начальной базы данных объектов (эталонных значений):

```bash
sudo afick -i
```
Запуск программы контроля целостности в режиме проверки:

```bash
sudo afick -k
```
Пример проверки работы механизма контроля целостности:
- Построить начальную БД: sudo afick -i
- Сделать резервную копию изменяемого файла: sudo cp /sbin/blkid /sbin/blkid.bak
- Внести намеренные изменения: echo asdf | sudo tee -a /sbin/blkid и sudo chmod 700 /sbin/sysctl
- Запустить проверку: sudo afick -k
- Результат считается положительным, если выведена информация об изменении файла /sbin/blkid и об изменении прав доступа у файла /sbin/sysctl.
- Восстановить исходное состояние файлов: sudo cp /sbin/blkid.bak /sbin/blkid.
- Настройка регламентного контроля выполняется в конфигурационном файле /etc/afick.conf. В него добавляются пути к контролируемым файлам и каталогам. После изменения конфигурации необходимо повторно инициализировать средство контроля целостности: sudo afick -i.

#### 2. Восстановление целостности программных пакетов
##### 2.1. Диагностика состояния пакетов
```bash
# Проверка целостности зависимостей
sudo apt-get check

# Просмотр списка установленных пакетов
dpkg -l

# Поиск пакетов в состоянии, отличном от "ii" (installed)
dpkg -l | awk '$1 != "ii" {print}'

# Проверка конкретного пакета
dpkg -s <имя_пакета>
```
##### 2.2. Пошаговый алгоритм восстановления
При повреждении пакетной базы или прерванных операциях используется следующий алгоритм:

```bash
# Шаг 1. Завершить прерванные операции
sudo dpkg --configure -a

# Шаг 2. Попытка автоматического исправления зависимостей
sudo apt install -f

# Шаг 3. Обновление списка пакетов
sudo apt update

# Шаг 4. Повторная попытка обновления
sudo apt full-upgrade
```
> Важно: в Astra Linux запрещено использовать apt upgrade для полного обновления системы. Эта команда обновляет пакеты, но не удаляет устаревшие версии, что создаёт конфликты версий и нарушает целостность. Вместо этого применяется apt full-upgrade или специальная утилита astra-update.

##### 2.3. Переустановка повреждённого пакета
```bash
# Переустановка конкретного пакета
sudo apt install --reinstall <имя_пакета>

# Переустановка с принудительной настройкой (игнорирование отсутствующих конфигов)
sudo apt install --reinstall -o Dpkg::Options::="--force-confmiss" <имя_пакета>
```
##### 2.4. Восстановление базы данных dpkg
При серьёзном повреждении базы данных dpkg можно выполнить следующие действия:

```bash
# Резервная копия текущей базы
sudo mv /var/lib/dpkg/info /var/lib/dpkg/info_old

# Создание новой базы
sudo mkdir /var/lib/dpkg/info

# Обновление и исправление
sudo apt-get update && sudo apt-get -f install
```
##### 2.5. Очистка кэша пакетов
```bash
# Просмотр размера кэша
sudo du -ch /var/cache/apt/archives

# Очистка кэша
sudo apt clean

# Удаление только устаревших пакетов из кэша
sudo apt autoclean
```
#### 3. Устранение проблем, возникающих при установке обновлений системы
##### 3.1. Типичные проблемы и их решения
Проблема: недостаточно места в разделе /boot

```bash
# Проверка свободного места
df -h /boot

# Очистка старых ядер
sudo apt autoremove --purge

# Удаление конкретного старого ядра
sudo apt purge linux-image-<старая_версия>
```
Проблема: недоступны пакеты при установке

```bash
# Проверить и при необходимости исправить /etc/apt/sources.list
sudo nano /etc/apt/sources.list

# Обновить список пакетов
sudo apt update
```
Проблема: ошибка контроля целостности при обновлении

При мажорном обновлении может возникнуть ошибка контроля целостности. Для устранения необходимо после обновления переустановить пакеты.

##### 3.2. Использование штатных инструментов обновления
Для установки обновлений рекомендуется использовать fly-astra-update и astra-update:

```bash
# Графический инструмент обновления
fly-astra-update

# Командный вариант
sudo astra-update -A -r
```
#### 4. Решение проблем с установленным ПО
##### 4.1. Диагностика служб: systemctl
**systemctl** — основной инструмент управления службами в systemd.

```bash
# Статус конкретной службы
systemctl status apache2

# Список всех служб
systemctl list-units --type=service

# Список упавших служб
systemctl --failed

# Перезапуск службы
sudo systemctl restart apache2

# Включение автозагрузки
sudo systemctl enable apache2

# Просмотр зависимостей службы
systemctl list-dependencies apache2

# Остановка службы
sudo systemctl stop apache2

# Проверка, включена ли служба в автозагрузку
systemctl is-enabled apache2
```
##### 4.2. Анализ журналов: journalctl
**journalctl** — утилита для работы с журналом systemd.

```bash
# Все сообщения
journalctl

# Сообщения конкретной службы
journalctl -u apache2

# Ошибки текущей загрузки
journalctl -p err -b

# Последние N сообщений (аналог tail)
journalctl -n 50

# Отслеживание в реальном времени (аналог tail -f)
journalctl -f

# За период
journalctl --since "1 hour ago"
journalctl --since today

# Поиск ошибок в логах с применением grep
sudo journalctl --since "1 hour ago" | grep err

# Фильтрация по полям (например, по UID или PID)
journalctl _UID=1000
journalctl _PID=1234

# Вывод в расширенном формате (список полей и их значений)
journalctl -o verbose

# Список полей, используемых в сообщениях
journalctl -N

# Список возможных значений для указанного поля
journalctl -F _SYSTEMD_UNIT
```
Пример поиска ошибок в логах:

```bash
localadmin@astra:~$ sudo journalctl --since "1 hour ago" | grep err
авг 07 17:34:07 astra spice-vdagent[2195]: error message: Cannot invoke method...
```
##### 4.3. Управление ресурсами: ulimit
**ulimit** — управление ограничениями на использование ресурсов.

```bash
# Просмотр всех текущих лимитов
ulimit -a

# Ограничение потребления виртуальной памяти
ulimit -v 512000

# Увеличение лимита открытых файлов
ulimit -n 65536

# Размер дампа ядра
ulimit -c unlimited

# Ограничение размера файла
ulimit -f 50000000
```
Настройка лимитов выполняется в файле /etc/security/limits.conf:

```text
# /etc/security/limits.conf
* hard core 0
* hard fsize 50000000
* hard nproc 1000
root hard nofile 500000
root soft nofile 50000
```
Включение/выключение ограничений выполняется инструментом astra-ulimits-control, настройка производится путём внесения изменений в файл /etc/security/limits.conf.

##### 4.4. Настройка параметров ядра: sysctl
**sysctl** — настройка параметров ядра.

```bash
# Просмотр всех параметров
sysctl -a

# Просмотр конкретного параметра
sysctl fs.suid_dumpable

# Изменение параметра на лету
sudo sysctl -w kernel.sysrq=0

# Применение настроек из /etc/sysctl.conf
sudo sysctl -p

# Применение настроек из директории /etc/sysctl.d/
sudo sysctl --system
```
Рекомендуемые настройки безопасности в /etc/sysctl.conf:

```text
kernel.sysrq = 0
fs.suid_dumpable = 0
kernel.randomize_va_space = 2
net.ipv4.ip_forward = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0
net.ipv6.conf.all.disable_ipv6 = 1
```
Пример настройки для core-дампов:

```bash
# Разрешить core-дампы для suid-программ
sudo sysctl -w fs.suid_dumpable=1

# Сохранить настройку в файл
echo "fs.suid_dumpable=1" | sudo tee /etc/sysctl.d/fs_suid_dumpable.conf
sudo sysctl -p --system
```
##### 4.5. Управление временными файлами: systemd-tmpfiles
**systemd-tmpfiles** — создание, удаление и очистка временных файлов и каталогов.

```bash
# Создание временных файлов согласно правилам
sudo systemd-tmpfiles --create

# Очистка временных файлов (с возрастом)
sudo systemd-tmpfiles --clean

# Удаление временных файлов
sudo systemd-tmpfiles --remove

# Комбинированная операция (используется при загрузке)
sudo systemd-tmpfiles --remove --create

# Статус таймера очистки
systemctl status systemd-tmpfiles-clean.timer
```
Пример создания правила для каталога с нужными правами:

```bash
sudo nano /etc/tmpfiles.d/tmp-cache.conf
```
Содержимое:

```text
# Тип  Путь              Режим  Пользователь  Группа  Возраст
d      /var/cache/myapp  0755   myapp         myapp   10d
```
Затем применить правило:

```bash
sudo systemd-tmpfiles --create
```
> Важно: systemd-tmpfiles пытается избегать изменения времени доступа и модификации каталогов, которые он проверяет. При запуске от имени непривилегированного пользователя каталоги, проверяемые на предмет очистки, могут получить обновлённое время доступа, что может помешать их очистке.

##### 4.6. Анализ сессий пользователей: last
**last** — утилита для отображения списка всех пользователей, осуществивших вход и выход с момента создания файла /var/log/wtmp.

```bash
# Последние входы
last

# Последние 10 записей
last -n 10

# Входы конкретного пользователя
last username

# Перезагрузки системы
last reboot

# Ограничение по времени (последние 30 минут)
last -s -30m

# Отображение с полными именами
last --fullnames

# История неудачных попыток входа
lastb
```
Пример вывода:

```text
johnney  pts/1        Mon Aug 14 20:42   still logged in
johnney  pts/0        Mon Aug 14 19:59   still logged in
wtmp begins Tue Aug 1 09:...
```

#### 6. Комплексный пример диагностики
Симптом: после обновления системы не запускается веб-сервер.

```bash
# 1. Проверить статус службы
systemctl status apache2

# 2. Посмотреть журнал службы
journalctl -u apache2 -n 50

# 3. Проверить целостность пакета apache2
dpkg -s apache2

# 4. Проверить зависимости
sudo apt-get check

# 5. Восстановить пакет
sudo apt-get install --reinstall apache2

# 6. Проверить параметры ядра
sysctl -a | grep -i net

# 7. Проверить лимиты
ulimit -a

# 8. Перезапустить службу
sudo systemctl restart apache2

# 9. Убедиться в успехе
systemctl status apache2
```

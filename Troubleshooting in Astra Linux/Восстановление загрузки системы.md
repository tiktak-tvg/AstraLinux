### Восстановление загрузки Astra Linux — это многоэтапный процесс, который зависит от стадии, на которой возникла проблема. Ниже приведены основные сценарии и инструменты для их решения.

#### Восстановление нормальной загрузки системы на начальных стадиях
На начальных стадиях, когда ядро или загрузчик не могут быть загружены, основным инструментом является режим восстановления с установочного диска Astra Linux.

Порядок входа в режим восстановления:
- Загрузитесь с установочного диска (USB или DVD), выбрав его в BIOS/UEFI.
- В меню установщика выберите «Режим восстановления».
- Пройдите первичную настройку (язык, раскладка, имя компьютера, часовой пояс).
- Система предложит выбрать корневой раздел. Обычно это /dev/sda1 для MBR или /dev/sda2 для GPT.
- После монтирования раздела вам будет предложено запустить оболочку. Согласитесь.
- Для получения полного доступа к системе выполните команду chroot /target. Теперь вы можете выполнять команды от имени root в контексте вашей установленной системы.

#### Исправление проблем с MBR- или EFI-разделом
Повреждение таблицы разделов или загрузочной записи — частая причина проблем.

**Для MBR (Legacy BIOS):**
- Используйте утилиту testdisk. Она позволяет найти потерянные разделы и восстановить MBR.
- Установите testdisk, если он не установлен: sudo apt install testdisk.
- Запустите его от имени root: sudo testdisk.
- Выберите диск, на котором находится ваша ОС.
- Выберите тип таблицы разделов (обычно Intel для MBR).
- Выберите «Analyse» для анализа текущей структуры и поиска потерянных разделов.
- Если разделы не найдены, выберите «Quick Search» для быстрого сканирования.
- После обнаружения разделов вы можете записать новую таблицу, выбрав пункт «Write».
- Для записи стандартного кода MBR выберите пункт [ MBR Code ] Write TestDisk MBR code to first sector.

**Для EFI (UEFI):**
- Проблемы обычно связаны с отсутствием или повреждением загрузочной записи в EFI-разделе.
- Загрузитесь в режим восстановления.
- В среде chroot установите пакеты для EFI: sudo apt install grub-efi efibootmgr.
- Выполните переустановку загрузчика, указав EFI-раздел. Команда для Astra Linux:

```bash
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=astralinux
```
Для совместимости можно скопировать загрузчик в стандартное место:

```bash
cp /boot/efi/EFI/astralinux/grubx64.efi /boot/efi/EFI/Boot/bootx64.efi
```
#### Исправление проблем с загрузчиком GRUB2
Если GRUB2 не отображается или выдает ошибки, его необходимо переустановить и обновить конфигурацию.

Порядок действий (в среде chroot):

- Проверьте и установите нужный пакет GRUB. Для Legacy BIOS — grub-pc, для EFI — grub-efi-amd64.
- Переустановите загрузчик на диск. Для Legacy BIOS:

```bash
grub-install /dev/sda
```
Для EFI (команда указана выше).

Обновите конфигурацию GRUB, чтобы он нашел все операционные системы:

```bash
update-grub
```
Для NVMe-дисков используйте соответствующее имя устройства, например /dev/nvme0n1.

#### Исправление проблем, связанных с ядром ОС
Если ядро не загружается, возможно, поврежден его образ initrd (initial ramdisk) или сами файлы ядра.

Восстановление через update-initramfs:

В среде chroot проверьте наличие ядер в каталоге /boot.

Пере генерируйте initrd для конкретного ядра. Сначала узнайте точную версию:

```bash
ls /boot/vmlinuz-*
```
Выполните команду, подставив нужную версию (например, 5.15.0-70-generic):

```bash
update-initramfs -u -k 5.15.0-70-generic
```
Для пересоздания initrd для всех установленных ядер используйте опцию -k all:

```bash
update-initramfs -u -k all
```
#### Восстановление загрузки и запуска системных служб
На заключительных стадиях загрузки система может «зависать» из-за проблем со службами.

Диагностика и исправление:

- Загрузитесь в режиме восстановления. В этом режиме запускается минимальный набор служб.
- Проверьте статус служб. После входа в chroot выполните:

```bash
systemctl --failed
```
Эта команда покажет список служб, которые не смогли запуститься.

- Проанализируйте логи. Для диагностики проблемы конкретной службы используйте journalctl:

```bash
journalctl -u <имя_службы> -b
```
Исправьте проблему. Это может быть ошибка в конфигурационном файле, отсутствие зависимости или конфликт. После исправления перезапустите службу или перезагрузите систему.

### Логическое резервное копирование и восстановление в PostgreSQL (Astra Linux Special Edition)
#### 1. Логическое резервное копирование
Логическое резервное копирование — это метод создания резервных копий, при котором данные выгружаются из базы данных в виде SQL-скриптов или архивных файлов, содержащих команды для воссоздания объектов БД. В отличие от физического резервного копирования (копирование файлов кластера), логическое резервное копирование оперирует на уровне объектов базы данных (таблиц, схем, ролей) и позволяет:
- Восстанавливать отдельные объекты, а не весь кластер;
- Переносить данные между разными версиями PostgreSQL и разными архитектурами;
- Создавать резервные копии с минимальным влиянием на работу сервера (без остановки кластера).
- Основные инструменты логического резервного копирования:

Инструмент                  | Назначение
--------------------------- | ----------------------------------------------
COPY / \copy	            | Копирование данных между таблицами и файлами
pg_dump	                    | Выгрузка одной базы данных
pg_dumpall	                | Выгрузка всего кластера (все БД + глобальные объекты)
pg_restore	                | Восстановление из архивных форматов (custom, tar, directory)

#### 2. Работа команд COPY и \copy
Команда *COPY* — это SQL-команда PostgreSQL, позволяющая копировать данные между таблицей и файлом или стандартным вводом/выводом. Она выполняется на стороне сервера, поэтому файлы должны быть доступны пользователю, от имени которого работает сервер PostgreSQL.

Синтаксис COPY:

```sql
-- Экспорт данных из таблицы в файл
COPY table_name TO '/path/to/file.csv' WITH (FORMAT csv, HEADER);

-- Импорт данных из файла в таблицу
COPY table_name FROM '/path/to/file.csv' WITH (FORMAT csv, HEADER);
```
Различие между COPY и \copy:

Характеристика          | COPY                              | \copy
----------------------- | --------------------------------- | -----------------------------------------
Где выполняется         | На сервере	                    | На клиенте (psql)
Доступ к файлам	        | Файлы должны быть на сервере	    | Файлы на клиентской машине
Права	                | Требуются права суперпользователя или членство в роли pg_read_server_files/pg_write_server_files	 | Достаточно прав пользователя ОС
Синтаксис	            | SQL-команда	                    | Мета-команда psql

*\copy* — это мета-команда psql, которая эмулирует COPY, но читает и записывает файлы на клиентской машине, где запущен psql. Это удобно, когда сервер недоступен для прямой записи файлов.

Примеры \copy:

```sql
-- Экспорт данных из таблицы в CSV-файл на клиенте
\copy (SELECT * FROM employees) TO '/home/user/employees.csv' WITH (FORMAT csv, HEADER)

-- Импорт данных из CSV-файла в таблицу
\copy employees FROM '/home/user/employees.csv' WITH (FORMAT csv, HEADER)
```
#### 3. Работа с утилитами pg_dump и pg_restore
##### 3.1. pg_dump
pg_dump — утилита для выгрузки одной базы данных. Она создаёт согласованный снимок данных на момент начала выгрузки, не блокируя другие операции с БД.

Основные форматы вывода:

Формат                       | Опция                 | Описание
---------------------------- | --------------------- | -------------------------------------
plain -Fp (по умолчанию)     | Текстовый SQL-скрипт. | Восстанавливается через psql
custom -Fc	                 | Сжатый архив, поддерживает выборочное восстановление и параллельную выгрузку.  | Восстанавливается через pg_restore
tar	-Ft	                     | tar-архив, совместим с directory-форматом.                                 | Не поддерживает сжатие
directory -Fd	             | Каталог с отдельными файлами для каждой таблицы и файлом оглавления.  | Поддерживает параллельную выгрузку

- Формат plain создаёт текстовый файл с SQL-командами, который можно просмотреть и отредактировать вручную. Это поведение по умолчанию.
- Формат custom является наиболее гибким: он сжат по умолчанию, позволяет выбирать и переупорядочивать объекты при восстановлении, а также поддерживает параллельную выгрузку.
- Формат directory создаёт каталог с одним файлом на каждую таблицу и большим объектом, а также файл оглавления (Table of Contents), читаемый pg_restore. Этот формат сжат по умолчанию с помощью gzip и поддерживает параллельную выгрузку.
- Формат tar совместим с directory-форматом, но не поддерживает сжатие и не позволяет изменять порядок элементов при восстановлении.

Примеры *pg_dump*:

```bash
# Выгрузка БД в формате plain (SQL-скрипт)
pg_dump -d mydb -f mydb_backup.sql

# Выгрузка в формате custom
pg_dump -d mydb -Fc -f mydb_backup.dump

# Выгрузка в формате tar
pg_dump -d mydb -Ft -f mydb_backup.tar

# Выгрузка в формате directory с параллелизмом
pg_dump -d mydb -Fd -j 4 -f mydb_backup_dir

# Выгрузка только данных (без схемы)
pg_dump -d mydb -a -f mydb_data.sql

# Выгрузка только схемы (без данных)
pg_dump -d mydb -s -f mydb_schema.sql

# Выгрузка конкретной таблицы
pg_dump -d mydb -t employees -f employees_backup.sql
```
##### 3.2. pg_restore
*pg_restore* — утилита для восстановления базы данных из архивов, созданных pg_dump в форматах custom, tar или directory. Для формата plain pg_restore не применяется — используется psql.

Примеры pg_restore:

```bash
# Восстановление из custom-формата
pg_restore -d mydb -U postgres mydb_backup.dump

# Восстановление из tar-формата
pg_restore -d mydb -U postgres --format=t mydb_backup.tar

# Восстановление из directory-формата с параллелизмом
pg_restore -d mydb -j 4 mydb_backup_dir

# Просмотр содержимого архива без восстановления
pg_restore -l mydb_backup.dump

# Восстановление только конкретной таблицы
pg_restore -d mydb -t employees mydb_backup.dump

# Восстановление с удалением существующих объектов
pg_restore -d mydb --clean mydb_backup.dump
```
> Важно: pg_restore не может восстанавливать из plain-формата. Для этого используется psql.

Восстановление из plain-формата:

```bash
psql -d mydb -f mydb_backup.sql
```
#### 4. Работа с утилитой pg_dumpall
pg_dumpall — утилита для выгрузки всего кластера PostgreSQL: всех баз данных и глобальных объектов (роли, табличные пространства, права доступа к параметрам конфигурации).

Особенности:
- Вызывает pg_dump для каждой базы данных в кластере;
- Сохраняет глобальные объекты, которые pg_dump не выгружает (роли, табличные пространства);
- Требует прав суперпользователя для полной выгрузки;
- Результат записывается в стандартный вывод или файл.

Примеры:

```bash
# Выгрузка всего кластера в SQL-скрипт
pg_dumpall -U postgres > all_cluster_backup.sql

# Выгрузка только глобальных объектов (роли, табличные пространства)
pg_dumpall -g -U postgres > globals.sql

# Выгрузка с указанием файла
pg_dumpall -U postgres -f all_cluster.sql

# Восстановление всего кластера
psql -U postgres -f all_cluster.sql
```
#### 5. Практическая работа
##### 5.1. Создание пользователя для выполнения резервного копирования
```bash
# Подключиться как postgres
sudo -u postgres psql
```
```sql
-- Создать роль с правами резервного копирования
CREATE ROLE backup_user WITH LOGIN PASSWORD 'BackupPass123!';
GRANT CONNECT ON DATABASE postgres TO backup_user;
GRANT pg_read_all_data TO backup_user;

-- Выйти
\q
```
##### 5.2. Создание базы данных и таблицы
```bash
# Подключиться как postgres
sudo -u postgres psql
```
```sql
-- Создать тестовую БД
CREATE DATABASE backup_test;

-- Подключиться к ней
\c backup_test

-- Создать таблицу
CREATE TABLE employees (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    position VARCHAR(100),
    salary NUMERIC(10,2)
);

-- Заполнить данными
INSERT INTO employees (name, position, salary) VALUES
    ('Иванов Иван', 'Инженер', 75000.00),
    ('Петрова Мария', 'Бухгалтер', 65000.00),
    ('Сидоров Алексей', 'Менеджер', 90000.00);
```
##### 5.3. Выгрузка и загрузка информации через команду \copy
Экспорт данных:

```bash
# Экспорт таблицы в CSV-файл на клиенте
sudo -u postgres psql -d backup_test -c "\copy employees TO '/tmp/employees.csv' WITH (FORMAT csv, HEADER)"
```
Импорт данных:

```bash
# Создать пустую таблицу для импорта
sudo -u postgres psql -d backup_test -c "CREATE TABLE employees_copy (LIKE employees INCLUDING ALL);"

# Импорт данных из CSV
sudo -u postgres psql -d backup_test -c "\copy employees_copy FROM '/tmp/employees.csv' WITH (FORMAT csv, HEADER)"

# Проверить
sudo -u postgres psql -d backup_test -c "SELECT * FROM employees_copy;"
```
##### 5.4. Создание резервной копии таблицы с помощью pg_dump в формате plain
```bash
# Выгрузка только таблицы employees в формате plain
sudo -u postgres pg_dump -d backup_test -t employees -f /tmp/employees_plain.sql

# Проверить содержимое файла
head -50 /tmp/employees_plain.sql
```
##### 5.5. Создание резервной копии БД с помощью pg_dump в различных форматах
Формат plain (SQL-файл):

```bash
sudo -u postgres pg_dump -d backup_test -f /tmp/backup_test_plain.sql
```
Формат custom:

```bash
sudo -u postgres pg_dump -d backup_test -Fc -f /tmp/backup_test_custom.dump
```
Формат tar:

```bash
sudo -u postgres pg_dump -d backup_test -Ft -f /tmp/backup_test.tar
```
Формат directory:

```bash
sudo -u postgres pg_dump -d backup_test -Fd -j 2 -f /tmp/backup_test_dir
```
Проверка созданных файлов:

```bash
ls -la /tmp/backup_test_plain.sql /tmp/backup_test_custom.dump /tmp/backup_test.tar /tmp/backup_test_dir/
```
##### 5.6. Восстановление данных таблицы из резервной копии в формате plain
##### Шаг 1. Создать новую базу данных для восстановления:

```bash
sudo -u postgres psql -c "CREATE DATABASE restore_test;"
```
##### Шаг 2. Восстановить данные из plain-файла:

```bash
# Восстановление всей БД из plain-файла
psql -d restore_test -f /tmp/backup_test_plain.sql
```
##### Шаг 3. Проверить восстановленные данные:

```bash
sudo -u postgres psql -d restore_test -c "SELECT * FROM employees;"
```
Ожидаемый результат:

```text
 id |     name       | position  |  salary
----+----------------+-----------+----------
  1 | Иванов Иван    | Инженер   | 75000.00
  2 | Петрова Мария  | Бухгалтер | 65000.00
  3 | Сидоров Алексей| Менеджер  | 90000.00
```
##### 5.7. Восстановление из других форматов (дополнительно)
Из custom-формата:

```bash
sudo -u postgres psql -c "CREATE DATABASE restore_custom;"
pg_restore -d restore_custom -U postgres /tmp/backup_test_custom.dump
```
Из tar-формата:

```bash
sudo -u postgres psql -c "CREATE DATABASE restore_tar;"
pg_restore -d restore_tar -U postgres /tmp/backup_test.tar
```
Из directory-формата:

```bash
sudo -u postgres psql -c "CREATE DATABASE restore_dir;"
pg_restore -d restore_dir -U postgres /tmp/backup_test_dir
```
##### 5.8. Полная сводка команд практической работы
```bash
# 1. Создание пользователя
sudo -u postgres psql -c "CREATE ROLE backup_user WITH LOGIN PASSWORD 'BackupPass123!';"
sudo -u postgres psql -c "GRANT pg_read_all_data TO backup_user;"

# 2. Создание БД и таблицы
sudo -u postgres psql -c "CREATE DATABASE backup_test;"
sudo -u postgres psql -d backup_test -c "CREATE TABLE employees (id SERIAL PRIMARY KEY, name VARCHAR(100), position VARCHAR(100), salary NUMERIC(10,2));"
sudo -u postgres psql -d backup_test -c "INSERT INTO employees (name, position, salary) VALUES ('Иванов Иван', 'Инженер', 75000.00), ('Петрова Мария', 'Бухгалтер', 65000.00), ('Сидоров Алексей', 'Менеджер', 90000.00);"

# 3. \copy экспорт/импорт
sudo -u postgres psql -d backup_test -c "\copy employees TO '/tmp/employees.csv' WITH (FORMAT csv, HEADER)"
sudo -u postgres psql -d backup_test -c "CREATE TABLE employees_copy (LIKE employees INCLUDING ALL);"
sudo -u postgres psql -d backup_test -c "\copy employees_copy FROM '/tmp/employees.csv' WITH (FORMAT csv, HEADER)"

# 4. pg_dump таблицы (plain)
sudo -u postgres pg_dump -d backup_test -t employees -f /tmp/employees_plain.sql

# 5. pg_dump БД (все форматы)
sudo -u postgres pg_dump -d backup_test -f /tmp/backup_test_plain.sql
sudo -u postgres pg_dump -d backup_test -Fc -f /tmp/backup_test_custom.dump
sudo -u postgres pg_dump -d backup_test -Ft -f /tmp/backup_test.tar
sudo -u postgres pg_dump -d backup_test -Fd -j 2 -f /tmp/backup_test_dir

# 6. Восстановление из plain
sudo -u postgres psql -c "CREATE DATABASE restore_test;"
psql -d restore_test -f /tmp/backup_test_plain.sql
sudo -u postgres psql -d restore_test -c "SELECT * FROM employees;"
```

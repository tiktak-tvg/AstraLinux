### Журналирование и аудит доступа к данным в PostgreSQL (Astra Linux Special Edition)
#### 1. Регистрация событий в СУБД PostgreSQL в журнале сообщений
PostgreSQL в составе Astra Linux Special Edition использует встроенную подсистему журналирования, которая позволяет регистрировать диагностические сообщения, события подключения, выполнения запросов и ошибки доступа.

Основные параметры журналирования в postgresql.conf:

Параметр	Описание	Рекомендуемое значение
logging_collector	Включение сбора журналов	on
log_destination	Назначение журналов (stderr, csvlog, syslog)	csvlog или syslog
log_directory	Каталог для файлов журнала	pg_log
log_filename	Шаблон имени файла	postgresql-%Y-%m-%d_%H%M%S.log
log_connections	Регистрация подключений	on
log_disconnections	Регистрация отключений	on
log_statement	Какие SQL-запросы регистрировать (none, ddl, mod, all)	all или ddl
log_line_prefix	Префикс строки журнала	%m|%a|%d|%p|%r|%i|%u| %e

#### 2. Настройка журнала сообщений: размещение, формат, данные, ротация
##### 2.1. Размещение и формат
В Astra Linux Special Edition начиная с обновления x.8 журналы диагностических сообщений определяются параметром ac_audit_destination. Поддерживаются два значения:

syslog — запись в системный журнал (управляется службой syslog-ng);

logfile — запись в журнал PostgreSQL (файлы в каталоге, указанном в log_directory).

Устаревшие значения parsec и all более не поддерживаются. При необходимости перенаправления диагностических сообщений в другие журналы следует использовать возможности службы syslog-ng.

##### 2.2. Какие данные и когда вносить в журнал
Тип события	Параметр	Когда регистрируется
Подключение	log_connections	При каждом подключении к серверу
Отключение	log_disconnections	При завершении сеанса
SQL-запросы	log_statement	В зависимости от значения: all — все, ddl — только DDL, mod — DDL + DML
Длительные запросы	log_min_duration_statement	Если запрос выполняется дольше указанного времени (в мс)
Ошибки доступа	log_min_error_statement	При ошибках с уровнем не ниже указанного

##### 2.3. Ротация журналов
PostgreSQL не выполняет автоматическую ротацию журналов. Для этого используется системная утилита logrotate. Типичная конфигурация /etc/logrotate.d/postgresql:

```text
/var/log/postgresql/*.log {
    weekly
    rotate 4
    compress
    delaycompress
    notifempty
    missingok
    create 640 postgres postgres
}
```
#### 3. Анализ журнала сообщений
##### 3.1. Просмотр текущего состояния настроек
```sql
-- Подключиться к PostgreSQL
sudo -u postgres psql

-- Просмотреть текущие настройки журналирования
SHOW logging_collector;
SHOW log_destination;
SHOW log_directory;
SHOW log_connections;
SHOW log_statement;
SHOW ac_audit_destination;
SHOW ac_audit_mode;
```
##### 3.2. Просмотр журнала сообщений
```bash
# Просмотр журнала PostgreSQL в каталоге данных
sudo tail -f /var/log/postgresql/postgresql-15-main.log

# Если журнал направлен в syslog
sudo journalctl -u postgresql -f
```
##### 3.3. Просмотр записи о подключении
После подключения к кластеру БД в журнале появится запись вида:

```text
2026-09-19 10:15:32.123 MSK [12345] LOG: connection received: host=[local]
2026-09-19 10:15:32.456 MSK [12345] LOG: connection authorized: user=postgres database=postgres
```
#### 4. Работа с pgBadger для анализа журналов
pgBadger — это быстрый анализатор журналов PostgreSQL, который создаёт подробные HTML-отчёты с графиками. Инструмент автоматически определяет формат журнала (syslog, stderr, csvlog, jsonlog).

##### 4.1. Установка
```bash
sudo apt install pgbadger
```
##### 4.2. Базовое использование
```bash
# Генерация HTML-отчёта из файла журнала
pgbadger /var/log/postgresql/postgresql-15-main.log -o /var/www/html/pgbadger_report.html

# Анализ с указанием формата
pgbadger -f stderr /var/log/postgresql/postgresql-15-main.log -o report.html

# Инкрементальный режим (отчёты по дням)
pgbadger -I -O /var/www/pg_reports/ /var/log/postgresql/postgresql-15-main.log
```
##### 4.3. Полезные опции
Опция	Описание
-f FORMAT	Указать формат журнала (syslog, stderr, csv, jsonlog)
-o FILE	Выходной файл
-I	Инкрементальный режим
-O DIR	Каталог для выходных файлов
--exclude-appname "pg_dump"	Исключить записи от указанного приложения
--begin DATETIME	Начало периода анализа
--end DATETIME	Конец периода анализа

##### 4.4. Возможности отчётов
pgBadger предоставляет информацию о:

наиболее частых и медленных запросах;

распределении запросов по времени;

ошибках и предупреждениях;

статистике подключений и отключений;

использовании блокировок;

временных файлах и других событиях.

#### 5. Расширенные возможности аудита в СУБД PostgreSQL в дистрибутиве Astra Linux Special Edition
В Astra Linux Special Edition подсистема регистрации событий доработанного PostgreSQL интегрирована в централизованную систему аудита ОС. В библиотеках подсистемы безопасности PARSEC реализован программный интерфейс для регистрации событий с использованием службы регистрации событий безопасности ОС.

##### 5.1. Параметры аудита Astra Linux
Параметр	Описание	Допустимые значения
ac_audit_mode	Режим аудита	default (устаревшее: internal)
ac_audit_destination	Назначение журнала	syslog, logfile
ac_session_audit	Маска аудита сеанса	Формат {УСПЕХ:ОТКАЗ}
ac_ignore_socket_maclabel	Игнорирование мандатных меток сокетов	true / false

##### 5.2. Управление маской аудита
Маска аудита может быть задана с помощью языка SQL:

```sql
-- Установить маску аудита для конкретной роли в базе данных
ALTER ROLE testuser IN DATABASE testdb SET ac_session_audit TO '{ace,read,write}';

-- Установить маску аудита для всей базы данных
ALTER DATABASE testdb SET ac_session_audit TO '{ace,read,write}';
```
##### 5.3. Регистрация событий в журнале аудита
События аудита регистрируются в централизованном журнале аудита ОС /var/log/audit через службу audited.

#### 6. Генерация событий средствами PostgreSQL
PostgreSQL может генерировать события аудита с помощью стандартных механизмов и расширения pgAudit.

##### 6.1. Стандартная генерация событий
Стандартные параметры журналирования позволяют генерировать события:

```sql
-- Генерация события подключения
-- Автоматически регистрируется при log_connections = on

-- Генерация события выполнения запроса
-- Автоматически регистрируется при log_statement = 'all'

-- Генерация события ошибки доступа
SELECT * FROM secret_table;  -- При отсутствии прав генерируется ошибка
```
##### 6.2. Расширение pgAudit
pgAudit — расширение, обеспечивающее детальное журналирование сеансов и объектов.

Установка:

```bash
sudo apt install postgresql-15-pgaudit
```
Настройка в postgresql.conf:

```text
shared_preload_libraries = 'pgaudit'
pgaudit.log = 'ROLE, DDL, MISC, FUNCTION'
pgaudit.log_parameter = on
```
Активация расширения:

```sql
CREATE EXTENSION pgaudit;
```
Настройка аудита сеанса:

```sql
-- Установить уровень аудита для роли
ALTER ROLE admin SET pgaudit.log = 'all';

-- Установить уровень аудита для базы данных
ALTER DATABASE mydb SET pgaudit.log = 'ddl, role';
```
Пример вывода pgAudit:

```text
AUDIT: SESSION,33,1,FUNCTION,DO,,,"DO $$ BEGIN EXECUTE 'CREATE TABLE import' || 'ant_table (id INT)'; END $$;"
AUDIT: SESSION,33,2,DDL,CREATE TABLE,TABLE,public.inportant_table,CREATE TABLE inportant_table
```
pgAudit показывает не только текст запроса, но и полное квалифицированное имя созданного объекта, что упрощает поиск в журналах.

#### 7. Практическая работа
##### 7.1. Просмотр текущего состояния настроек
```bash
sudo -u postgres psql -c "SHOW logging_collector;"
sudo -u postgres psql -c "SHOW log_destination;"
sudo -u postgres psql -c "SHOW log_connections;"
sudo -u postgres psql -c "SHOW log_statement;"
sudo -u postgres psql -c "SHOW ac_audit_destination;"
```
##### 7.2. Просмотр журнала сообщений
```bash
# Просмотр последних строк журнала
sudo tail -50 /var/log/postgresql/postgresql-15-main.log

# Или через journalctl
sudo journalctl -u postgresql -n 50
```
##### 7.3. Подключение к кластеру БД и просмотр записи о подключении
```bash
# Подключиться к кластеру main
sudo -u postgres psql -p 5432

# Выполнить простой запрос
SELECT current_user, current_database();

# Выйти
\q

# Просмотреть запись о подключении в журнале
sudo grep "connection authorized" /var/log/postgresql/postgresql-15-main.log | tail -5
```
##### 7.4. Изменение настроек аудита и фиксация запросов
##### Шаг 1. Изменить параметры в postgresql.conf:

```bash
sudo nano /etc/postgresql/15/main/postgresql.conf
```
Установить:

```text
logging_collector = on
log_destination = 'csvlog'
log_connections = on
log_disconnections = on
log_statement = 'all'
log_line_prefix = '%m|%a|%d|%p|%r|%i|%u| %e '
```
##### Шаг 2. Перезапустить кластер:

```bash
sudo pg_ctlcluster 15 main restart
```
##### Шаг 3. Выполнить запросы и проверить журнал:

```bash
sudo -u postgres psql -c "CREATE TABLE audit_test (id serial, data text);"
sudo -u postgres psql -c "INSERT INTO audit_test (data) VALUES ('test');"
sudo -u postgres psql -c "SELECT * FROM audit_test;"

# Просмотреть журнал
sudo tail -20 /var/log/postgresql/postgresql-15-main.csv
```
##### 7.5. Использование расширенного аудита СУБД PostgreSQL в Astra Linux Special Edition
##### Шаг 1. Проверить параметры аудита:

```bash
sudo -u postgres psql -c "SHOW ac_audit_mode;"
sudo -u postgres psql -c "SHOW ac_audit_destination;"
sudo -u postgres psql -c "SHOW ac_session_audit;"
```
##### Шаг 2. Настроить маску аудита:

```sql
-- Установить маску аудита для роли
ALTER ROLE audit_user IN DATABASE testdb SET ac_session_audit TO '{ace,read,write}';
```
##### Шаг 3. Проверить запись в журнале аудита ОС:

```bash
sudo tail -20 /var/log/audit/audit.log | grep postgres
```
##### 7.6. Генерация событий средствами PostgreSQL
Установка и настройка pgAudit:

```bash
# Установить расширение
sudo apt install postgresql-15-pgaudit

# Настроить postgresql.conf
sudo nano /etc/postgresql/15/main/postgresql.conf
```
Добавить:

```text
shared_preload_libraries = 'pgaudit'
pgaudit.log = 'ROLE, DDL, MISC, FUNCTION'
pgaudit.log_parameter = on
```
```bash
# Перезапустить кластер
sudo pg_ctlcluster 15 main restart

# Активировать расширение
sudo -u postgres psql -c "CREATE EXTENSION pgaudit;"
```
Генерация событий:

```bash
# Создать таблицу (DDL-событие)
sudo -u postgres psql -c "CREATE TABLE pgaudit_test (id serial, data text);"

# Создать роль (ROLE-событие)
sudo -u postgres psql -c "CREATE ROLE test_audit_user LOGIN PASSWORD 'pass';"

# Просмотреть журнал аудита pgAudit
sudo grep "AUDIT:" /var/log/postgresql/postgresql-15-main.log | tail -10
```
Ожидаемый вывод:

```text
AUDIT: SESSION,1,1,DDL,CREATE TABLE,TABLE,public.pgaudit_test,"CREATE TABLE pgaudit_test (id serial, data text);"
AUDIT: SESSION,1,1,ROLE,CREATE ROLE,,, "CREATE ROLE test_audit_user LOGIN PASSWORD 'pass';"
```

### Подключение и аутентификация в СУБД PostgreSQL (Astra Linux Special Edition)
#### 1. Этапы подключения к СУБД
Процесс подключения клиента к серверу PostgreSQL состоит из нескольких последовательных этапов:

- Этап 1. Установка TCP-соединения. Клиентское приложение (psql, pgAdmin, прикладная программа) устанавливает соединение с сервером PostgreSQL по указанному адресу и порту (по умолчанию localhost:5432 для локальных подключений или IP-адрес:порт для удалённых). Если соединение устанавливается через доменный сокет UNIX, TCP-соединение не используется.
- Этап 2. Проверка соответствия правилам pg_hba.conf. Сервер последовательно просматривает записи в файле pg_hba.conf и находит первую запись, соответствующую параметрам подключения (тип подключения, база данных, пользователь, адрес клиента). Записи читаются последовательно, порядок записей имеет решающее значение.
- Этап 3. Аутентификация. В соответствии с найденным правилом сервер применяет указанный метод аутентификации (peer, md5, scram-sha-256, gss, pam и др.). Если метод требует пароля, клиент передаёт его серверу.
- Этап 4. Авторизация (проверка мандатных прав). При включённом мандатном управлении доступом (МРД) сервер проверяет классификационную метку пользователя и назначает мандатные права доступа. Если метка не назначена, возникает ошибка авторизации: error obtaining MAC configuration for user.
- Этап 5. Установка соединения. После успешной аутентификации и авторизации клиент получает доступ к базе данных с учётом предоставленных прав.

#### 2. Аутентификация в СУБД PostgreSQL из дистрибутива Astra Linux Special Edition
Astra Linux Special Edition поставляет защищённую версию PostgreSQL, доработанную для взаимодействия с комплексом средств защиты информации (КСЗ). Основные особенности:

- Поддержка мандатного управления доступом (МРД). Сервер СУБД проверяет классификационные метки входящих соединений и передаёт только информацию с меткой не выше метки входящего соединения. Для включения этой проверки параметр ac_ignore_socket_maclabel в файле postgresql.conf устанавливается в значение false.
- Интеграция с доменом ALD/FreeIPA. Поддерживается аутентификация через Kerberos (GSSAPI) с использованием keytab-файлов.
- Расширенный синтаксис pg_hba.conf. Добавлена опция ignore_socket_maclabel, которая указывается после метода аутентификации и позволяет более гибко управлять проверкой мандатных меток.
- Настройки аутентификации хранятся в файле /etc/postgresql/<номер_версии>/<имя_кластера>/pg_hba.conf, где <номер_версии> — 9.6, 11 или 14 в зависимости от версии Astra Linux, а <имя_кластера> по умолчанию — main.

#### 3. Обеспечение доступа PostgreSQL к данным о мандатных метках пользователей
При включённом МРД серверу PostgreSQL (служебному пользователю postgres) необходим доступ к базе данных мандатных меток пользователей. Без этого возникает ошибка авторизации.

Для предоставления доступа необходимо:

Назначить классификационную метку пользователю ОС с помощью утилиты pdpl-user:

```bash
sudo pdpl-user -l 0:0 $USER
```
Предоставить служебному пользователю postgres право на чтение метки пользователя из базы macdb:

```bash
sudo setfacl -m u:postgres:r /etc/parsec/macdb/`id -u`
```
Эти действия выполняются для текущего пользователя, который будет подключаться к СУБД.

Важно: если пользователь СУБД не зарегистрирован в ОС на стороне сервера СУБД, все его мандатные атрибуты имеют нулевое значение. Для работы с включённым МРД имя роли в PostgreSQL должно совпадать с именем пользователя ОС, иначе роль не сможет получить авторизацию.

#### 4. Конфигурационный файл pg_hba.conf
##### 4.1. Порядок обработки
Записи в файле pg_hba.conf читаются последовательно, сверху вниз. Для каждого входящего соединения сервер находит первую запись, которая соответствует типу подключения, базе данных, пользователю и адресу клиента. Если ни одна запись не соответствует, соединение отклоняется.

Рекомендация: в начале файла размещаются записи с более строгими параметрами соответствия (конкретные адреса, пользователи), а в конце — с более общими (например, all all). Это предотвращает случайное «перехватывание» соединений слишком широкими правилами.

##### 4.2. Структура записей
Каждая запись представляет собой строку, содержащую несколько полей, разделённых пробелами или табуляцией. Пустые строки и текст после символа # игнорируются. Записи не переносятся на следующую строку.

Общий формат записи:

```text
тип_подключения  база_данных  пользователь  [адрес]  метод_аутентификации  [параметры]
```
##### 4.3. Возможные значения полей
Поле	Возможные значения	Описание
Тип подключения	local, host, hostssl, hostnossl, hostgssenc, hostnogssenc	local — доменный сокет UNIX; host — TCP/IP (IPv4 или IPv6); hostssl — только SSL-соединения; hostnossl — только без SSL
База данных	all, sameuser, samerole, конкретное имя, список имён через запятую	all — любая база; sameuser — база с именем пользователя; конкретное имя — указанная БД
Пользователь	all, конкретное имя роли, список имён через запятую, +группа	all — любой пользователь; +группа — все члены группы
Адрес (для host-записей)	CIDR-нота (например, 192.168.0.0/24), IP-адрес с маской, all, samehost, samenet	Определяет диапазон IP-адресов клиентов
Метод аутентификации	trust, reject, peer, ident, md5, password, scram-sha-256, gss, sspi, pam, ldap, radius, cert	Определяет способ проверки подлинности
Параметры (опционально)	map=имя, clientcert=1, include_realm=0, krb_server_keyfile=путь и др.	Дополнительные настройки для выбранного метода

##### 4.4. Настройка «по умолчанию» после установки
После установки PostgreSQL в Astra Linux файл pg_hba.conf обычно содержит следующие записи:

```text
local   all   postgres   peer
local   all   all        peer
host    all   all        0.0.0.0/0   md5
```
Это означает: локальные подключения пользователя postgres и всех остальных пользователей — через peer (по системному имени); внешние подключения — через md5.

#### 5. Методы аутентификации в PostgreSQL
Метод	                  | Описание	                        | Применимость
----------------------- | --------------------------------- | -----------------------------
trust	 | Безусловное разрешение подключения без проверки пароля	 | Не рекомендуется для production
reject	 | Безусловный отказ в подключении	 | Для явного запрета
peer	 | Проверка по имени пользователя ОС (только для локальных подключений)	 | Локальные подключения
ident	 | Проверка через ident-сервер (только TCP/IP); при указании для local используется peer	 | TCP/IP-подключения
md5	 | Пароль с MD5-хэшированием	 | Внешние подключения
scram-sha-256	 | Пароль с SCRAM-SHA-256 (более безопасный, чем md5)	 | Рекомендуется для новых систем
password	 | Пароль передаётся в открытом виде	 | Только при SSL-соединении
gss	 | Аутентификация через GSSAPI (Kerberos)	 | В домене ALD/FreeIPA
sspi	 | Аутентификация через SSPI (Windows)	 | Windows-среда
pam	 | Аутентификация через PAM	 | Локальные подключения
ldap	 | Аутентификация через LDAP-сервер	 | Корпоративная среда
cert	 | Аутентификация по SSL-сертификату	 | Требует SSL

> Важно: доступность методов аутентификации по паролю зависит от того, как пароли пользователей зашифрованы на сервере. Если пароль зашифрован в режиме scram-sha-256, его можно использовать для методов scram-sha-256 и password. Для перевода существующей инсталляции с md5 на scram-sha-256 требуется миграция паролей.

#### 6. Сопоставление имён
При использовании внешних систем аутентификации (Ident, GSSAPI, LDAP, RADIUS, PAM, SSPI, cert) имя пользователя операционной системы, инициировавшего подключение, может не совпадать с именем роли в PostgreSQL. Для решения этой проблемы используется сопоставление имён пользователей.

Сопоставления определяются в файле pg_ident.conf, который по умолчанию хранится в каталоге данных кластера. Для использования сопоставления в pg_hba.conf указывается параметр map=имя_карты в поле параметров аутентификации.

Формат записей в pg_ident.conf:

```text
# MAPNAME   SYSTEM-USERNAME   PG-USERNAME
mymap       systemuser        dbuser
```
- MAPNAME — имя карты сопоставления (указывается в pg_hba.conf).
- SYSTEM-USERNAME — имя пользователя во внешней системе (например, принципал Kerberos username@REALM). Если начинается со знака /, оставшаяся часть рассматривается как регулярное выражение.
- PG-USERNAME — имя роли в PostgreSQL.

Пример для Kerberos (GSSAPI): принципалу pgusername@realm может быть сопоставлено просто pgusername.

#### 7. Практическая работа
##### 7.1. Хранение паролей в СУБД PostgreSQL
Пароли пользователей в PostgreSQL хранятся в системном каталоге pg_authid в зашифрованном виде. Метод шифрования задаётся параметром password_encryption в postgresql.conf (по умолчанию scram-sha-256 в современных версиях, md5 в старых).

Установка пароля для роли:

```bash
sudo -u postgres psql -c "ALTER USER $USER WITH PASSWORD 'SecurePass123!';"
```
Проверка метода шифрования:

```bash
sudo -u postgres psql -c "SHOW password_encryption;"
```
##### 7.2. Влияние конфигурации /etc/parsec/mswitch.conf на возможность подключения
Файл /etc/parsec/mswitch.conf управляет режимом переключения мандатных меток в Astra Linux. Ключевой параметр — zero_if_notfound.

Проблема: при подключении пользователя, не зарегистрированного в ОС или не имеющего назначенной мандатной метки, сервер PostgreSQL не может получить его мандатные атрибуты и отклоняет подключение с ошибкой error obtaining MAC configuration for user.

Решение: в файле /etc/parsec/mswitch.conf установить параметр zero_if_notfound в значение yes. Это позволит подключаться пользователям, не имеющим мандатной метки в ОС, — им будет присвоена нулевая метка.

```bash
sudo nano /etc/parsec/mswitch.conf
# Изменить zero_if_notfound: yes
sudo systemctl restart postgresql
```
Важно: данное изменение снижает уровень защищённости, поэтому применяется только при необходимости (например, для служебных учётных записей).

##### 7.3. Настройка авторизации в файле pg_hba.conf
Пример настройки для локальной аутентификации по паролю:

```text
# TYPE  DATABASE  USER       ADDRESS         METHOD
local   all       all                        scram-sha-256
host    all       all        127.0.0.1/32    scram-sha-256
host    all       all        192.168.32.0/24 md5
host    all       all        ::1/128         scram-sha-256
```
Пример настройки для домена FreeIPA (Kerberos):

```text
host    all       all        <адрес>         gss include_realm=0 krb_server_keyfile='/etc/postgresql/11/main/keytab'
```
После внесения изменений необходимо перезагрузить конфигурацию:

```bash
sudo pg_ctlcluster 11 main reload
```
Или через psql:

```bash
sudo -u postgres psql -c "SELECT pg_reload_conf();"
```
##### 7.4. Создание файла с паролями ~/.pgpass
Файл .pgpass в домашнем каталоге пользователя позволяет автоматически подставлять пароль при подключении к PostgreSQL, если пароль не указан иным способом.

Формат строки:

```text
<имя_или_IP-адрес_хоста>:<порт>:<имя_базы_данных>:<имя_пользователя>:<пароль>
```
Пример создания:

```bash
# Создать файл
touch ~/.pgpass

# Установить права доступа 600 (иначе файл игнорируется)
chmod 600 ~/.pgpass

# Добавить строку подключения
echo "localhost:5432:mydb:myuser:MySecretPass" > ~/.pgpass
```
Пример для нескольких подключений:

```text
localhost:5432:postgres:postgres:AdminPass123
192.168.32.211:5432:appdb:appuser:UserPass456
```
Файл .pgpass должен иметь маску прав доступа 600, иначе он будет игнорироваться сервером.

Проверка подключения без ввода пароля:

```bash
psql -h localhost -U myuser -d mydb
```
##### 7.5. Полный сценарий практической работы
```bash
# 1. Установить пароль для текущего пользователя в СУБД
sudo -u postgres psql -c "ALTER USER $USER WITH PASSWORD 'MyPass123!';"

# 2. Настроить pg_hba.conf для парольной аутентификации
sudo nano /etc/postgresql/11/main/pg_hba.conf
# Добавить строку:
# local   all   all   scram-sha-256

# 3. Перезагрузить конфигурацию
sudo pg_ctlcluster 11 main reload

# 4. Создать файл ~/.pgpass
touch ~/.pgpass
chmod 600 ~/.pgpass
echo "localhost:5432:postgres:$USER:MyPass123!" > ~/.pgpass

# 5. Проверить подключение без ввода пароля
psql -h localhost -U $USER -d postgres -c "SELECT current_user, current_database();"

# 6. При необходимости настроить /etc/parsec/mswitch.conf
sudo nano /etc/parsec/mswitch.conf
# Установить: zero_if_notfound: yes
sudo systemctl restart postgresql
```

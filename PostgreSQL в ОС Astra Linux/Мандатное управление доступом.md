### Мандатное управление доступом в СУБД PostgreSQL в Astra Linux Special Edition
#### 1. Мандатное управление доступом в Astra Linux Special Edition
*Мандатное управление доступом (МРД)* — это ключевой механизм защиты информации в Astra Linux Special Edition, основанный на присвоении субъектам и объектам классификационных меток (уровней конфиденциальности и категорий). В отличие от дискреционного управления, где доступ определяется правами, назначенными владельцем объекта, мандатное управление устанавливает правила доступа на системном уровне, которые не могут быть изменены пользователями.

Основные принципы мандатного управления:
- Классификационная метка — совокупность уровня конфиденциальности (иерархическая составляющая) и набора неиерархических категорий.
- Уровень конфиденциальности — числовое значение (например, 0, 1, 2, 3), определяющее степень секретности информации.
- Категории конфиденциальности — неиерархические признаки, определяющие принадлежность информации к определённым предметным областям (например, «Кадры», «Финансы»).
- Правила доступа — субъект может читать объект, если его уровень конфиденциальности не ниже уровня объекта, а категории субъекта включают все категории объекта. Запись разрешена, если уровень субъекта не выше уровня объекта.
- Мандатное управление обеспечивает защиту от угроз, связанных с преднамеренными или ошибочными действиями пользователей, а также от утечек информации через скрытые каналы.

#### 2. Мандатные атрибуты, присваиваемые сущностям и субъектам в ОС
В Astra Linux Special Edition мандатные атрибуты присваиваются как субъектам (пользователям, процессам), так и объектам (файлам, каталогам, устройствам, сетевым соединениям).

Мандатные атрибуты субъектов:
- Уровень доступа — максимальный уровень конфиденциальности, к которому субъект имеет доступ.
- Уровень целостности — максимальный уровень целостности, который субъект может использовать.
- Набор категорий — категории конфиденциальности, к которым субъект имеет доступ.
- Привилегии PARSEC — дополнительные права, позволяющие игнорировать отдельные мандатные правила.
- Мандатные атрибуты объектов:
- Классификационная метка — уровень конфиденциальности и категории, присвоенные объекту.
- Атрибут CCR (Container Clearance Required) — определяет, требуется ли учёт уровня конфиденциальности контейнера для доступа к его содержимому.
- Атрибут ehole — позволяет игнорировать любые мандатные правила.

Инструменты управления мандатными атрибутами:

Инструмент	    | Назначение
--------------- | --------------------------
pdpl-user	   | Назначение мандатных атрибутов пользователям
pdpl-file	   | Назначение мандатных атрибутов файлам и каталогам
pdpl-edit	   | Редактирование мандатных меток
pdp-ls    	 | Просмотр мандатных атрибутов

#### 3. Принципы обеспечения защиты от НСД при использовании мандатного управления доступом
Мандатное управление доступом в Astra Linux Special Edition обеспечивает защиту от несанкционированного доступа (НСД) на основе следующих принципов:
- Принцип запрета доступа по умолчанию — любой доступ, не разрешённый явно, запрещён.
- Принцип доминирования — правила мандатного доступа имеют приоритет над дискреционными.
- Принцип контроля информационных потоков — контролируются не только прямые обращения к объектам, но и потоки информации между субъектами с разными уровнями доступа.
- Принцип мандатной целостности — субъекты с низким уровнем целостности не могут влиять на объекты с высоким уровнем целостности.
- Принцип неизменности меток — пользователи не могут изменять мандатные метки объектов и субъектов без специальных привилегий.

В СУБД PostgreSQL из состава Astra Linux Special Edition эти принципы реализуются через интеграцию с подсистемой PARSEC ОС.

#### 4. Средства управления мандатными правилами разрешения доступа
Для управления мандатными правилами в Astra Linux Special Edition используются следующие средства:

Средство	      | Назначение
--------------- | --------------------------
pdpl-user	 | Назначение мандатных атрибутов пользователям
pdpl-file	 | Назначение мандатных атрибутов файлам
pdpl-edit	 | Редактирование мандатных меток
pdp-ls	 | Просмотр мандатных атрибутов
fly-admin-smc	 | Графический инструмент управления мандатными атрибутами
astra-safepolicy	 | Инструмент командной строки для управления политиками безопасности

Пример назначения мандатной метки пользователю:

```bash
sudo pdpl-user -l 0:0 username
```
Эта команда назначает пользователю username уровень конфиденциальности 0 и уровень целостности 0.

Пример назначения мандатной метки каталогу:

```bash
sudo pdpl-file 3:0:-1:ccnr /tmp
```
Эта команда назначает каталогу /tmp уровень конфиденциальности 3, уровень целостности 0, все категории и атрибут ccnr.

#### 5. Мандатное управление доступом в СУБД PostgreSQL
В составе Astra Linux Special Edition используется СУБД PostgreSQL, доработанная в соответствии с требованием интеграции с ОС в части мандатного управления доступом к информации и содержащая реализацию ДП-модели управления доступом и информационными потоками.

Ключевая особенность: После установки параметра ac_ignore_socket_maclabel = false сервер СУБД будет проверять мандатную метку входящего соединения и передавать только информацию с меткой не выше метки входящего соединения.

Привилегии ОС, используемые в СУБД PostgreSQL:

Привилегия      | Описание
--------------- | --------------------------
ac_session_maclabel	 | Текущая мандатная метка сессии пользователя СУБД. Может быть изменена средствами СУБД
ac_capable_ignmaclvl	 | Привилегия, позволяющая игнорировать мандатные уровни
ac_capable_ignmaccat	 | Привилегия, позволяющая игнорировать мандатные категории
ac_capable_chmac	 | Привилегия, позволяющая изменять мандатные метки

Данные привилегии, кроме ac_session_maclabel, не могут быть изменены с помощью средств СУБД ни пользователями, ни администраторами.

Важное замечание: Если пользователь СУБД не зарегистрирован в ОС на стороне сервера СУБД, все его мандатные атрибуты имеют нулевое значение. Администраторам СУБД дополнительно к их атрибутам из ОС всегда добавляются атрибуты ac_capable_ignmaclvl, ac_capable_ignmaccat и ac_capable_chmac.

#### 6. Мандатные атрибуты сеанса пользователя в СУБД PostgreSQL
При подключении к СУБД PostgreSQL сеансу пользователя присваивается мандатная метка, определяемая на основе мандатных атрибутов пользователя в ОС.

Просмотр мандатной метки сеанса:

```sql
SHOW ac_session_maclabel;
```
Изменение мандатной метки сеанса:

```sql
SET ac_session_maclabel = '3:0:Категория_1';
```
Ограничения:
- Пользователь может установить только ту метку, которая разрешена ему в ОС.
- Администраторы СУБД (обладающие привилегиями ac_capable_ignmaclvl, ac_capable_ignmaccat, ac_capable_chmac) могут устанавливать любые метки.
- Мандатная метка сеанса определяет, к каким данным пользователь имеет доступ: только к информации с меткой не выше метки сеанса.

#### 7. Применение мандатного управления доступом
Мандатное управление доступом в PostgreSQL применяется для:
- Разграничения доступа к данным — пользователи с разными уровнями конфиденциальности видят только разрешённые им данные.
- Защиты от утечек — информация с высоким уровнем конфиденциальности не может быть прочитана пользователями с низким уровнем.
- Контроля информационных потоков — запрет на запись данных с высокого уровня на низкий.
- Интеграции с ОС — мандатные метки пользователей ОС автоматически применяются в СУБД.

Пример применения: Если пользователь имеет мандатную метку 0:0 (уровень 0), он не сможет прочитать данные, помеченные меткой 1:0 (уровень 1). При попытке доступа будет возвращена ошибка или пустой результат.

#### 8. Средства управления мандатным доступом к объектам БД
Для управления мандатным доступом к объектам БД в PostgreSQL из состава Astra Linux Special Edition используются:

Средство        | Назначение
--------------- | --------------------------
psql	 | Просмотр и изменение мандатных меток объектов через метакоманды и SQL
pgAdmin3	 | Графическая утилита для администрирования БД, включая управление мандатным доступом
astra-postgresql-mac-control	 | Инструмент командной строки для включения/выключения МРД в кластерах СУБД
ALTER TABLE ... SET MAC LABEL	 | SQL-команда для назначения мандатной метки таблице
CREATE POLICY	 | Создание политик защиты на уровне строк с учётом мандатных меток

Пример назначения мандатной метки таблице:

```sql
ALTER TABLE my_table SET MAC LABEL '2:0:Категория_1';
```
Пример использования astra-postgresql-mac-control:

```bash
# Включение МРД для всех кластеров СУБД версии 15
sudo astra-postgresql-mac-control enable -v 15

# Выключение МРД для кластеров с именем main
sudo astra-postgresql-mac-control disable -i main

# Просмотр состояния МРД
sudo astra-postgresql-mac-control status
```
#### 9. Практическая работа
##### 9.1. Просмотр и изменение уровней доступа пользователей ОС
Просмотр текущих мандатных атрибутов пользователя:

```bash
pdpl-user -i
```
Изменение мандатной метки пользователя:

```bash
sudo pdpl-user -l 1:0 username
```
Проверка изменений:

```bash
pdpl-user -i username
```
##### 9.2. Работа с файлами ОС
Просмотр мандатных меток файлов:

```bash
pdp-ls -M /path/to/file
```
Назначение мандатной метки файлу:

```bash
sudo pdpl-file 2:0:-1:ccnr /path/to/file
```
##### 9.3. Создание пользователей в операционной системе и назначение им классификационных меток
```bash
# Создать пользователя
sudo useradd -m user_high
sudo passwd user_high

# Назначить мандатную метку (уровень 2, все категории)
sudo pdpl-user -l 2:0:-1 user_high

# Создать пользователя с низким уровнем
sudo useradd -m user_low
sudo passwd user_low
sudo pdpl-user -l 0:0 user_low

# Проверить
pdpl-user -i user_high
pdpl-user -i user_low
```
##### 9.4. Просмотр классификационных меток при подключении к PostgreSQL
```bash
# Подключиться как user_high
sudo -u user_high psql -d testdb

# Просмотреть метку сеанса
SHOW ac_session_maclabel;

# Выйти
\q
```
##### 9.5. Настройка кластера, базы и объектов БД для применения мандатного управления доступом

##### Шаг 1. Настройка кластера PostgreSQL:

Отредактировать файл /etc/postgresql/11/main/postgresql.conf:

```text
ac_ignore_socket_maclabel = false
```
##### Шаг 2. Перезапуск кластера:

```bash
sudo pg_ctlcluster 11 main restart
```
##### Шаг 3. Создание базы данных с мандатной меткой:

```sql
CREATE DATABASE secure_db;
ALTER DATABASE secure_db SET MAC LABEL '1:0';
```
##### Шаг 4. Создание таблицы с мандатной меткой:

```sql
\c secure_db
CREATE TABLE secret_data (id serial, info text);
ALTER TABLE secret_data SET MAC LABEL '2:0:Категория_1';
```
##### 9.6. Изменение таблицы для поддержки защиты классификационными метками на уровне строк
```sql
-- Включить защиту на уровне строк
ALTER TABLE secret_data ENABLE ROW LEVEL SECURITY;

-- Принудительно применить защиту для владельца таблицы
ALTER TABLE secret_data FORCE ROW LEVEL SECURITY;

-- Создать политику для пользователей с уровнем 0 (видят только строки с меткой 0)
CREATE POLICY low_level_policy ON secret_data
    FOR SELECT
    TO user_low
    USING (mac_label = '0:0');

-- Создать политику для пользователей с уровнем 2 (видят все строки)
CREATE POLICY high_level_policy ON secret_data
    FOR SELECT
    TO user_high
    USING (true);
```
##### 9.7. Тестирование работы мандатного управления доступом от имени различных пользователей
Тестирование с параметром ac_ignore_socket_maclabel = true (значение по умолчанию):

```bash
# Подключиться как user_low
sudo -u user_low psql -d secure_db

# Попытаться прочитать данные из таблицы с меткой 2:0
SELECT * FROM secret_data;
-- Результат: данные доступны (мандатная метка игнорируется)

\q
```
Тестирование с параметром ac_ignore_socket_maclabel = false:

##### Шаг 1. Изменить параметр:

```bash
sudo nano /etc/postgresql/11/main/postgresql.conf
# Установить: ac_ignore_socket_maclabel = false
sudo pg_ctlcluster 11 main restart
```
##### Шаг 2. Подключиться как user_low:

```bash
sudo -u user_low psql -d secure_db
SHOW ac_session_maclabel;
-- Результат: 0:0

SELECT * FROM secret_data;
-- Результат: пустой набор (доступ к данным с меткой 2:0 запрещён)
\q
```
##### Шаг 3. Подключиться как user_high:

```bash
sudo -u user_high psql -d secure_db
SHOW ac_session_maclabel;
-- Результат: 2:0:-1

SELECT * FROM secret_data;
-- Результат: данные доступны
\q
```
##### 9.8. Изменение значения параметра ac_ignore_socket_maclabel на false
Через файл конфигурации:

```bash
sudo sed -i 's/^#\?ac_ignore_socket_maclabel.*/ac_ignore_socket_maclabel = false/' /etc/postgresql/11/main/postgresql.conf
sudo pg_ctlcluster 11 main restart
```
Через инструмент astra-postgresql-mac-control:

```bash
sudo astra-postgresql-mac-control enable -v 11
```
##### 9.9. Повторное тестирование работы мандатного управления доступом
После установки ac_ignore_socket_maclabel = false:

Пользователь	Уровень	Доступ к данным с меткой 0:0	Доступ к данным с меткой 2:0
Пользователь    | Уровень               | Доступ к данным с меткой 0:0  | Доступ к данным с меткой 2:0
--------------- | --------------------- | ----------------------------- | -----------------------------
user_low	 | 0:0	  | Разрешён	  | Запрещён
user_high	 | 2:0	 | Разрешён	  | Разрешён

Проверка через SQL:

```sql
-- От имени user_low
SELECT * FROM secret_data WHERE mac_label = '0:0';
-- Результат: данные возвращены

SELECT * FROM secret_data WHERE mac_label = '2:0';
-- Результат: пустой набор
```

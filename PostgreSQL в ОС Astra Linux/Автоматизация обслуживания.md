### Автоматизация обслуживания PostgreSQL с помощью pgAgent
pgAgent — это планировщик заданий для PostgreSQL, позволяющий автоматизировать выполнение SQL-скриптов и команд оболочки по расписанию. Он не входит в стандартную поставку PostgreSQL, а устанавливается отдельно и интегрируется с pgAdmin для графического управления заданиями.

#### 1. Планировщик заданий pgAgent
*pgAgent* — это внешний демон (служба в Windows), который непрерывно проверяет наличие заданий, подлежащих выполнению, и запускает их. Каждое задание состоит из нескольких компонентов:

- Задание (Job) — контейнер, представляющий запланированную задачу;
- Шаг (Step) — конкретное действие (SQL-запрос или пакетный скрипт), выполняемое в рамках задания;
- Расписание (Schedule) — определяет, когда задание запускается.

Установка pgAgent
```bash
sudo apt install pgagent
```
После установки необходимо создать расширение в базе данных PostgreSQL:

```bash
sudo -u postgres psql -p 5432
```
В сессии psql:

```sql
-- Проверить доступность расширения
SELECT * FROM pg_available_extensions WHERE name = 'pgagent';

-- Создать расширение
CREATE EXTENSION pgagent;
```
После создания расширения в pgAdmin появится новый раздел pgAgent Jobs.

Запуск демона pgAgent
```bash
# Запуск службы pgAgent
sudo systemctl start pgagent

# Включение автозагрузки
sudo systemctl enable pgagent

# Проверка статуса
sudo systemctl status pgagent
```
> Важно: при запуске pgAgent необходимо указать параметры подключения к PostgreSQL (хост, порт, имя базы данных, пользователь). Эти параметры обычно задаются в конфигурационном файле службы или через переменные окружения.

Классы заданий

*pgAgent* поддерживает пять предопределённых классов заданий для категоризации:

Класс            | Назначение         
---------------- | ------------ 
Routine Maintenance	 | Регулярные задачи обслуживания (резервное копирование, VACUUM, очистка)
Data Maintenance	 | Операции, изменяющие или организующие существующие данные
Data Export	 | Извлечение или выгрузка данных из базы во внешние файлы
Data Import	 | Загрузка или восстановление данных из внешних источников
Miscellaneous	 | Произвольные задачи, не попадающие в другие категории

#### 2. Создание заданий через графическую утилиту pgAdmin
Для создания задания в pgAdmin 4:
```txt
В дереве объектов разверните сервер и найдите узел pgAgent Jobs.
Нажмите правой кнопкой мыши и выберите Create → pgAgent Job.
На вкладке General задайте:
Name — имя задания;
Enabled — Yes;
Job Class — класс задания (например, Data Export);
Host Agent — оставьте пустым, если задание может выполняться на любом агенте.
На вкладке Steps нажмите Add (+) и заполните:
Name — имя шага;
Kind — SQL (для SQL-запросов) или Batch (для команд оболочки);
Connection type — Local или Remote;
Database — база данных, в которой выполняется шаг;
Code — SQL-код или команда оболочки.
На вкладке Schedules нажмите Add (+) и настройте расписание (минуты, часы, дни недели, дни месяца, месяцы).
```
Пример шага для экспорта таблицы (Batch):

```text
/usr/bin/pg_dump -U postgres -h localhost -p 5432 -t employees -f /backup/employees.sql backup_test
Эта команда выгружает таблицу employees из базы backup_test в SQL-файл.
```
#### 3. Создание заданий через сценарии SQL
pgAgent позволяет создавать задания программно через SQL-запросы к системным таблицам pgagent.pga_job, pgagent.pga_jobstep и pgagent.pga_schedule.

Создание задания с шагом и расписанием
```sql
DO $$
DECLARE
    job_id integer;
BEGIN
    -- Создать задание и получить его ID
    INSERT INTO pgagent.pga_job (jobjclid, jobname)
    VALUES (1, 'DELETE_NAMES')  -- 1 = Routine Maintenance
    RETURNING jobid INTO job_id;

    -- Добавить шаг к заданию
    INSERT INTO pgagent.pga_jobstep (jstjobid, jstname, jstkind, jstcode, jstdbname)
    VALUES (
        job_id,
        'DELETE_NAMES',
        's',  -- 's' = SQL step, 'b' = Batch step
        'BEGIN DELETE_NAMES; END;',
        'somedatabase'
    );

    -- Добавить расписание (ежедневно в полночь)
    INSERT INTO pgagent.pga_schedule (
        jscjobid, jscname, jscdesc,
        jscminutes, jschours, jscweekdays, jscmonthdays, jscmonths,
        jscenabled, jscstart, jscend
    ) VALUES (
        job_id,
        'schedule name',
        '',
        '{t,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f}',
        '{t,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f,f}',
        '{f,f,f,f,f,f,f}',
        '{f,f,f,f,f,f,f,f,f,f,f,f}',
        true,
        now(),
        NULL
    );
END $$;
```
В этом примере создаётся задание с одним SQL-шагом, выполняющим хранимую процедуру DELETE_NAMES, и расписанием на запуск ежедневно в полночь.

Создание задания с пакетным шагом
```sql
-- Создать задание
INSERT INTO pgagent.pga_job (jobjclid, jobname, jobdesc, jobhostagent, jobenabled)
VALUES (3, 'backup_job', 'Ежедневное резервное копирование', '', TRUE);

-- Добавить пакетный шаг (Batch)
INSERT INTO pgagent.pga_jobstep (jstjobid, jstname, jstdesc, jstenabled, jstkind, jstcode)
VALUES (
    (SELECT jobid FROM pgagent.pga_job WHERE jobname = 'backup_job'),
    'pg_dump_step',
    'Выгрузка базы данных',
    TRUE,
    'b',  -- 'b' = Batch step
    '/usr/bin/pg_dump -U postgres -h localhost -Fc backup_test -f /backup/backup_test.dump'
);
```
Этот пример создаёт задание с пакетным шагом, выполняющим pg_dump для резервного копирования базы данных.

#### 4. Практическая работа
##### 4.1. Создание файла с паролями ~/.pgpass для учётной записи sa
Файл .pgpass позволяет автоматически подставлять пароль при подключении к PostgreSQL без его ввода в командной строке.

Формат файла:

```text
hostname:port:database:username:password
```
Создание файла:

```bash
# Переключиться на пользователя sa (или создать его)
sudo su - sa

# Создать файл .pgpass
touch ~/.pgpass

# Установить права доступа 600 (обязательно!)
chmod 600 ~/.pgpass

# Добавить строку подключения
echo "localhost:5432:backup_test:sa:SecurePass123" > ~/.pgpass
```
Пояснение полей:

- localhost — хост (можно использовать * как wildcard);
- 5432 — порт;
- backup_test — имя базы данных;
- sa — имя пользователя;
- SecurePass123 — пароль.

> Важно: на Unix-системах права на файл .pgpass должны запрещать любой доступ для группы и остальных пользователей. Команда chmod 0600 ~/.pgpass обязательна, иначе файл будет игнорироваться.

##### 4.2. Установка и запуск pgAgent
```bash
# Установить pgAgent
sudo apt install pgagent

# Создать расширение в базе данных
sudo -u postgres psql -c "CREATE EXTENSION IF NOT EXISTS pgagent;"

# Запустить службу
sudo systemctl start pgagent
sudo systemctl enable pgagent

# Проверить статус
sudo systemctl status pgagent
```
##### 4.3. Подготовка каталога для выгрузки данных
```bash
# Создать каталог для резервных копий
sudo mkdir -p /backup/exports

# Установить права (владелец — postgres)
sudo chown postgres:postgres /backup/exports
sudo chmod 755 /backup/exports
```
##### 4.4. Создание задания на экспорт таблицы в графическом интерфейсе pgAdmin
##### Шаг 1. Откройте pgAdmin 4 и подключитесь к серверу PostgreSQL.
##### Шаг 2. В дереве объектов найдите pgAgent Jobs → правой кнопкой → Create → pgAgent Job.
##### Шаг 3. На вкладке General:
- Name: export_employees
- Enabled: Yes
- Job Class: Data Export

##### Шаг 4. На вкладке Steps нажмите Add (+):
- Name: export_step
- Kind: Batch
- Connection type: Local
- Database: backup_test

Code:
```text
/usr/bin/pg_dump -U sa -h localhost -p 5432 -t employees -f /backup/exports/employees.sql backup_test
```
##### Шаг 5. На вкладке Schedules нажмите Add (+):
- Name: daily_export
- Enabled: Yes
- Настройте расписание: например, ежедневно в 02:00.

##### Шаг 6. Сохраните задание.
##### 4.5. Изменение задания через запрос SQL: добавление шага
Предположим, необходимо добавить к существующему заданию export_employees второй шаг — экспорт таблицы departments.

##### Шаг 1. Найти ID задания:

```sql
SELECT jobid, jobname FROM pgagent.pga_job WHERE jobname = 'export_employees';
```
##### Шаг 2. Добавить новый шаг:

```sql
INSERT INTO pgagent.pga_jobstep (
    jstjobid, jstname, jstdesc, jstenabled, jstkind, jstcode, jstdbname
) VALUES (
    (SELECT jobid FROM pgagent.pga_job WHERE jobname = 'export_employees'),
    'export_departments_step',
    'Экспорт таблицы departments',
    TRUE,
    'b',  -- Batch step
    '/usr/bin/pg_dump -U sa -h localhost -p 5432 -t departments -f /backup/exports/departments.sql backup_test',
    'backup_test'
);
```
##### Шаг 3. Проверить добавление:

```sql
SELECT jstid, jstname, jstenabled, jstkind
FROM pgagent.pga_jobstep
WHERE jstjobid = (SELECT jobid FROM pgagent.pga_job WHERE jobname = 'export_employees');
```

```bash

sudo mkdir -p /backup/exports
sudo chown postgres:postgres /backup/exports

# === 4. Создание задания через pgAdmin ===
# (выполняется в графическом интерфейсе)

# === 5. Добавление шага через SQL ===
sudo -u postgres psql -d backup_test -c "
INSERT INTO pgagent.pga_jobstep (jstjobid, jstname, jstdesc, jstenabled, jstkind, jstcode, jstdbname)

sudo -u postgres psql -d backup_test -c "
```

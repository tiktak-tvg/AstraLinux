### Репликация в PostgreSQL — это мощный механизм, позволяющий создавать копии баз данных для обеспечения отказоустойчивости, распределения нагрузки и аналитики. В Astra Linux Special Edition доступны как встроенные средства физической и логической репликации, так и инструменты для управления ими.

#### Физическая репликация (Physical Replication)
*Физическая репликация* — это процесс, при котором на сервер-реплику по байтово копируется весь кластер базы данных. Она обеспечивает полную идентичность данных на ведущем (primary) и ведомом (standby) серверах.

Ключевые особенности:
- Полная копия: Реплика содержит полную копию всего кластера баз данных.
- Побайтовое копирование: Данные передаются на уровне блоков, что делает этот метод очень эффективным для больших объемов.
- Основа — WAL: Физическая репликация основана на передаче и применении журналов предзаписи (WAL).
- Ограничения: Требует одинаковой архитектуры и, как правило, одинаковой мажорной версии PostgreSQL на ведущем и ведомом серверах.

Настройка в Astra Linux (краткая сводка):
- На ведущем сервере: В файле postgresql.conf необходимо установить параметры: wal_level = replica, max_wal_senders = 1, max_replication_slots = 1. В pg_hba.conf разрешить подключение к базе replication для пользователя-реплики с IP-адреса ведомого сервера.
- Создание слота: На ведущем сервере создается слот физической репликации командой SELECT pg_create_physical_replication_slot('slave');.
- На ведомом сервере: Создается базовая копия с ведущего сервера с помощью pg_basebackup, после чего в postgresql.conf настраиваются параметры hot_standby = on, primary_conninfo и primary_slot_name. Создается пустой файл standby.signal.

#### Переключение на реплику (Promotion)
Переключение на реплику ``(promotion)`` — это процесс, при котором ведомый сервер превращается в новый ведущий. Это необходимо для выполнения плановых работ ``(switchover)`` или в случае аварии ``(failover)``.

Процедура переключения:
- Убедитесь, что старый ведущий сервер остановлен. Это критически важно для предотвращения расхождения данных.
- Подайте команду на повышение реплики. Это можно сделать двумя способами:
- Из командной строки ОС: pg_ctl promote.
- Из SQL-сеанса, подключившись к реплике: SELECT pg_promote();.
- Настройте клиентов. После повышения необходимо перенаправить клиентов на новый ведущий сервер.

> Важно: В PostgreSQL нет встроенных средств для автоматического переключения. Для автоматизации этого процесса требуется стороннее кластерное программное обеспечение, такое как Pacemaker, которое может быть интегрировано в Astra Linux.

#### Логическая репликация (Logical Replication)
Логическая репликация — это метод, при котором реплицируются не файлы, а сами изменения данных (SQL-команды, например, INSERT, UPDATE, DELETE).

Ключевые особенности:
- Гибкость: Позволяет реплицировать отдельные таблицы или их подмножества, а не всю базу данных целиком.
- Совместимость: Работает между разными мажорными версиями PostgreSQL и даже между разными операционными системами.
- Модель "публикация-подписка": Ведущий сервер (publisher) публикует изменения, а ведомый (subscriber) на них подписывается.
- Ограничения: Не реплицирует DDL-операции (изменения схемы), а также изменения в последовательностях (sequences). Схему на подписчике необходимо создавать вручную.

Настройка (основные шаги):
- На ведущем сервере: Установить wal_level = logical. Создать публикацию для нужных таблиц: CREATE PUBLICATION my_pub FOR TABLE table1, table2;.
- На ведомом сервере: Создать те же таблицы (схему). Создать подписку, указав параметры подключения к ведущему: CREATE SUBSCRIPTION my_sub CONNECTION 'host=... port=... user=... dbname=...' PUBLICATION my_pub;.

#### Сценарии использования
Выбор типа репликации зависит от ваших задач.

Физическая репликация идеально подходит для:
- Высокой доступности (High Availability): Быстрое переключение на реплику при сбое ведущего сервера.
- Распределения нагрузки на чтение: Использование реплик для выполнения SELECT-запросов (Hot Standby), чтобы снизить нагрузку на основной сервер.
- Полного резервного копирования: Создание точной копии всей базы данных.
- Логическая репликация предпочтительна для:
- Выборочной репликации: Передача данных только определенных таблиц (например, для аналитики или в другие системы).
- Объединения данных (Consolidation): Сбор данных из нескольких баз в одну для отчетности и анализа.
- Миграции с минимальным простоем: Обновление на новую мажорную версию PostgreSQL или переезд на другую платформу.
- Каскадной репликации: Построение сложных топологий, где подписчик может сам стать публикатором для других серверов.

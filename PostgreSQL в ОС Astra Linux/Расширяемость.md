### Расширяемость 
Это — одна из ключевых архитектурных особенностей PostgreSQL, позволяющая адаптировать СУБД под специфические задачи без изменения ядра.

#### Пул соединений
PostgreSQL создаёт отдельный процесс на каждое клиентское соединение, что при большом числе подключений приводит к значительным накладным расходам. PgBouncer — лёгкий пулер соединений, который поддерживает постоянный пул соединений к серверу и переиспользует их между клиентами.

Режимы пулинга PgBouncer:

Режим               | Описание
------------------- | -------------------------
Session pooling	 | Соединение закрепляется за клиентом на всю сессию
Transaction pooling	 | Соединение выделяется на время транзакции и возвращается в пул после её завершения
Statement pooling	 | Соединение выделяется на время одного оператора (не поддерживает транзакции с несколькими операторами)

Пример конфигурации pgbouncer.ini:

```ini
[databases]
mydb = host=127.0.0.1 port=5432 dbname=mydb

[pgbouncer]
listen_port = 6432
listen_addr = *
auth_type = md5
auth_file = /etc/pgbouncer/userlist.txt
pool_mode = transaction
max_client_conn = 1000
default_pool_size = 20
```
#### Типы для больших значений (TOAST)
PostgreSQL использует фиксированный размер страницы (обычно 8 КБ) и не позволяет кортежам занимать несколько страниц. Для хранения больших значений применяется TOAST (The Oversized-Attribute Storage Technique).

Принцип работы:
- Порог срабатывания — TOAST_TUPLE_THRESHOLD (обычно 2 КБ).
- Большие значения сжимаются и/или выносятся в отдельную TOAST-таблицу.
- В основной строке остаётся указатель на вынесенные данные.
- Для каждого вынесенного фрагмента назначается уникальный OID.
- Стратегии хранения (указываются при создании столбца):


Стратегия           | Описание
------------------- | -------------------------
PLAIN	 | Без сжатия и выноса (для небольших типов)
EXTENDED	 | Сжатие + вынос (по умолчанию)
EXTERNAL	 | Вынос без сжатия (для уже сжатых данных)
MAIN	 | Сжатие без выноса

#### Пользовательские типы данных
Команда CREATE TYPE регистрирует новый тип данных в текущей базе данных. Создатель типа становится его владельцем.

Основные формы:

Форма               | Пример
------------------- | -------------------------
Составной тип	 | CREATE TYPE compfoo AS (f1 int, f2 text);
Перечисление	 | CREATE TYPE bug_status AS ENUM ('new', 'open', 'closed');
Диапазонный тип  	 | CREATE TYPE floatrange AS RANGE (subtype = float8);
Базовый тип	 | Требует прав суперпользователя

Пример использования составного типа:

```sql
CREATE TYPE address_type AS (
    city VARCHAR(100),
    street VARCHAR(200),
    postal_code VARCHAR(20)
);

CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    address address_type
);

INSERT INTO customers (name, address)
VALUES ('Иванов', ROW('Москва', 'ул. Ленина, д. 1', '101000'));
```
#### Классы операторов
Класс операторов определяет, как конкретный тип данных может использоваться с индексом. Он указывает, какие операторы выполняют определённые роли («стратегии») для данного типа и метода индексации.

Пример создания класса операторов:

```sql
CREATE OPERATOR CLASS complex_abs_ops
    DEFAULT FOR TYPE complex USING btree AS
        OPERATOR 1 <,
        OPERATOR 2 <=,
        OPERATOR 3 =,
        OPERATOR 4 >=,
        OPERATOR 5 >,
        FUNCTION 1 complex_abs_compare(complex, complex);
```
Классы операторов позволяют использовать пользовательские типы данных с индексами B-tree, GiST, GIN и другими.

#### Слабоструктурированные данные
PostgreSQL предоставляет два основных типа для работы со слабоструктурированными данными:

Тип                 | Описание
------------------- | -------------------------
hstore	 | Хранит набор пар «ключ-значение» в одном столбце. Идеален для плоских структур с разреженными данными
JSONB	 | Хранит JSON в бинарном формате, поддерживает индексацию и вложенность

Пример с JSONB:

```sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(200),
    attributes JSONB
);

INSERT INTO products (name, attributes)
VALUES ('Ноутбук', '{"cpu": "Intel i7", "ram": 16, "storage": 512}');

-- Запрос с извлечением поля
SELECT name, attributes->>'cpu' AS cpu
FROM products
WHERE attributes @> '{"ram": 16}';

-- Индекс GIN для JSONB
CREATE INDEX idx_products_attributes ON products USING GIN (attributes);
```
#### Фоновые процессы
PostgreSQL может быть расширен для запуска пользовательского кода в отдельных процессах — фоновых рабочих процессах (background workers). Они запускаются, останавливаются и контролируются процессом postgres, что позволяет связать их жизненный цикл со статусом сервера.

Возможности фоновых процессов:
- Подключение к общей памяти PostgreSQL и базам данных.
- Выполнение обычных транзакций.
- Отправка асинхронных уведомлений через NOTIFY или Async_Notify().
- Регистрация через shared_preload_libraries.

Пример расширения pg_background: позволяет выполнять произвольные SQL-команды в фоновых процессах, что полезно для асинхронных задач и длительных операций без блокировки клиентских сессий.

#### Асинхронная обработка
PostgreSQL предоставляет механизм асинхронных уведомлений через команды LISTEN и NOTIFY.

Принцип работы:
- Клиентская сессия регистрирует интерес к каналу командой LISTEN channel_name.
- Другая сессия выполняет NOTIFY channel_name, возможно с полезной нагрузкой.
- Все сессии, прослушивающие канал, асинхронно получают уведомление.

Пример:

```sql
-- Сессия 1: подписка
LISTEN orders_channel;

-- Сессия 2: отправка уведомления
NOTIFY orders_channel, 'Новый заказ #123';

-- Сессия 1 получает: Asynchronous notification "orders_channel" with payload "Новый заказ #123"
```
Применение: уведомления о событиях, синхронизация кэшей, триггеры для внешних систем.

#### Создание расширений
Расширение — это набор SQL-объектов (функций, типов, операторов, индексов), упакованных для установки одной командой. Для создания расширения необходимы два файла:

Файл                | Назначение
------------------- | -------------------------
extension_name.control	 | Содержит метаданные: имя, версию, зависимости
extension_name--version.sql	 | SQL-скрипт для создания объектов расширения

Установка расширения:

```sql
CREATE EXTENSION hstore SCHEMA addons;
```
Просмотр установленных расширений:

```sql
\dx
SELECT * FROM pg_extension;
```
#### Языки программирования
В стандартной поставке PostgreSQL доступны четыре процедурных языка:

Язык                | Описание
------------------- | -------------------------
PL/pgSQL	 | Основной процедурный язык, синтаксис близок к Oracle PL/SQL
PL/Tcl	 | Встраиваемый интерпретатор Tcl
PL/Perl	 | Интерпретатор Perl
PL/Python	 | Интерпретатор Python

Установка дополнительных языков:

```sql
CREATE EXTENSION plpython3u;  -- PL/Python 3
CREATE EXTENSION plperl;      -- PL/Perl
```
Пример функции на PL/Python:

```sql
CREATE OR REPLACE FUNCTION py_fibonacci(n INTEGER)
RETURNS INTEGER AS $$
    def fib(n):
        a, b = 0, 1
        for _ in range(n):
            a, b = b, a + b
        return a
    return fib(n)
$$ LANGUAGE plpython3u;

SELECT py_fibonacci(10);  -- 55
```
#### Агрегатные и оконные функции
Агрегатные функции вычисляют одно значение для набора строк (SUM, AVG, COUNT, MAX, MIN, string_agg и др.).

Оконные функции выполняют вычисления над набором строк, связанным с текущей строкой, не сворачивая результат в одну строку. Любая агрегатная функция может использоваться как оконная при наличии предложения OVER.

Пример оконной функции:

```sql
SELECT
    employee_id,
    department,
    salary,
    AVG(salary) OVER (PARTITION BY department) AS avg_dept_salary,
    RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS rank_in_dept
FROM employees;
```
Основные оконные функции:

Функция             | Описание
------------------- | -------------------------
ROW_NUMBER()	 | Номер строки в окне
RANK()	 | Ранг с пропусками
DENSE_RANK()	 | Ранг без пропусков
LAG() / LEAD()	 | Значение предыдущей/следующей строки
SUM() OVER (...)	 | Накопительная сумма

#### Обзор полнотекстового поиска
PostgreSQL предоставляет встроенные средства полнотекстового поиска (FTS) на основе двух типов данных и оператора @@.

Тип                 | Описание
------------------- | -------------------------
tsvector	 | Документ в форме, оптимизированной для поиска — отсортированный список лексем
tsquery	 | Поисковый запрос, содержащий лексемы и булевы операторы (&, |, !)

Пример:

```sql
-- Преобразование текста в tsvector
SELECT to_tsvector('russian', 'Книга о приключениях в далёких странах');
-- Результат: 'далёк':6 'книга':1 'приключен':3 'стран':7

-- Поисковый запрос
SELECT to_tsquery('russian', 'книга & приключения');
-- Результат: 'книг':1 & 'приключен':2

-- Поиск
SELECT title
FROM books
WHERE to_tsvector('russian', description) @@ to_tsquery('russian', 'приключения');
```
Индексация для полнотекстового поиска:

```sql
CREATE INDEX idx_books_fts ON books USING GIN (to_tsvector('russian', description));
```
Дополнительные функции:

- plainto_tsquery() — преобразует обычный текст в tsquery, нормализуя слова.
- phraseto_tsquery() — поиск фразы.

ts_headline() — выделение фрагментов текста с совпадениями.

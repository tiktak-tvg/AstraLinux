### Установка и настройка СУБД PostgreSQL в Astra Linux Special Edition
#### 1. Терминология
*PostgreSQL* — свободная объектно-реляционная система управления базами данных (СУБД), базирующаяся на языке SQL и поддерживающая многие возможности стандарта SQL:2011. В составе Astra Linux Special Edition поставляются как защищённая версия СУБД (доработанная для взаимодействия с комплексом средств защиты Astra Linux), так и незащищённая версия.

Ключевые термины:

Термин                    	| Определение
--------------------------- | ----------------------------------------------
Кластер баз данных (database cluster)	 | Совокупность баз данных, управляемая одним экземпляром сервера PostgreSQL. В Debian-подобных системах (включая Astra Linux) кластеры управляются утилитами pg_createcluster, pg_ctlcluster, pg_dropcluster, pg_lsclusters
Экземпляр сервера (instance)	 | Процесс сервера PostgreSQL, обслуживающий один кластер баз данных. Может быть запущен, остановлен или перезапущен
Служебный пользователь postgres	 | Системная учётная запись, от имени которой работает сервер PostgreSQL и выполняются административные команды
Суперпользователь PostgreSQL	 | Роль в СУБД с максимальными правами (по умолчанию — postgres), не обязательно совпадающая с администратором ОС
psql	 | Интерактивный терминал PostgreSQL для выполнения SQL-запросов и административных команд
pgAdmin	 | Графическое средство управления СУБД PostgreSQL

#### 2. Установка СУБД PostgreSQL из дистрибутива Astra Linux Special Edition
##### 2.1. Версии PostgreSQL в составе Astra Linux
В составе Astra Linux Special Edition x.7 доступны следующие версии СУБД:

Версия           | Тип         	| Расположение
---------------- | ------------ | -------------
11.10-astra.se5	 | Защищённая	  | Основной репозиторий (установочный диск)
11.10-astra.se13 | Защищённая	  | Основной репозиторий (оперативное обновление №1)
11.12-astra.ce5	 | Незащищённая	| Компонент astra-ce расширенного репозитория

> Важно: при установке СУБД из компонента astra-ce расширенного репозитория защищённая версия СУБД, доработанная для взаимодействия с КСЗ Astra Linux Special Edition, будет заменена на стандартную версию.

##### 2.2. Установка защищённой версии
```bash
# Обновить список пакетов
sudo apt update

# Проверить доступные версии
apt policy postgresql-11

# Установить пакет postgresql-11 старшей доступной версии
sudo apt install postgresql-11

# Или указать конкретную версию
sudo apt install postgresql-11=11.10-astra.se5
```
После установки служба PostgreSQL запускается автоматически. Проверка:

```bash
systemctl status postgresql
```
Ожидаемый вывод:

```text
postgresql.service - PostgreSQL RDBMS
   Loaded: loaded (/lib/systemd/system/postgresql.service; enabled; vendor preset: enabled)
   Active: active (exited) since ...
```
> Примечание: служба postgresql.service имеет тип active (exited), поскольку она управляет кластерами через вспомогательные утилиты, а не запускает один процесс.

#### 3. Управление экземпляром сервера
Управление экземпляром сервера PostgreSQL в Astra Linux осуществляется через системные службы и утилиты управления кластерами.

##### 3.1. Управление через systemd
```bash
# Запуск службы PostgreSQL (всех кластеров)
sudo systemctl start postgresql

# Остановка
sudo systemctl stop postgresql

# Перезапуск
sudo systemctl restart postgresql

# Проверка статуса
sudo systemctl status postgresql

# Включение автозагрузки
sudo systemctl enable postgresql
```
##### 3.2. Управление через pg_ctlcluster
Для управления отдельным кластером используется утилита pg_ctlcluster. Формат вызова:
```bash
pg_ctlcluster <версия> <имя_кластера> <действие>
```
Действия:

Действие                    | Описание
--------------------------- | ---------------------
start	 | Запуск экземпляра СУБД для указанного кластера
stop	 | Останов экземпляра СУБД
restart	 | Перезапуск экземпляра
reload	 | Перечитать конфигурацию без перезапуска
status	 | Просмотр состояния кластера
promote	 | Превратить резервный сервер в основной

Примеры:

```bash
# Запуск кластера main версии 11
sudo pg_ctlcluster 11 main start

# Остановка кластера main
sudo pg_ctlcluster 11 main stop

# Перезапуск кластера main
sudo pg_ctlcluster 11 main restart

# Просмотр состояния
sudo pg_ctlcluster 11 main status
```
#### 4. Управление кластером баз данных
##### 4.1. Просмотр списка кластеров
```bash
pg_lsclusters
```
Пример вывода:

```text
Ver Cluster Port Status Owner    Data directory              Log file
11  main    5432 online postgres /var/lib/postgresql/11/main /var/log/postgresql/postgresql-11-main.log
```
##### 4.2. Создание кластера
```bash
sudo pg_createcluster <версия> <имя_кластера>
```
Пример создания кластера reserve для версии 11:

```bash
sudo pg_createcluster 11 reserve
```
По умолчанию новый кластер будет использовать порт 5433, если порт 5432 уже занят кластером main. Проверить можно командой pg_lsclusters.

##### 4.3. Удаление кластера
```bash
sudo pg_dropcluster <версия> <имя_кластера>
```
Важно: удаление кластера необратимо, все данные будут потеряны.

##### 4.4. Обновление кластера
```bash
sudo pg_upgradecluster <старая_версия> <имя_кластера> <новая_версия>
```
#### 5. Использование psql
psql — интерактивный терминал для работы с PostgreSQL. Запуск от имени служебного пользователя postgres:

```bash
sudo su - postgres
psql
```
Или напрямую:

```bash
sudo -u postgres psql
```
##### 5.1. Основные команды psql

Команда                     | Описание
--------------------------- | ---------------------
\l	 | Список баз данных
\c <dbname>	 | Подключиться к базе данных
\dt	 | Список таблиц
\du	 | Список ролей
\dn	 | Список схем
\d <table>	 | Описание таблицы
\q	 | Выход
\?	 | Справка по командам
\h	 | Справка по SQL

##### 5.2. Выполнение SQL-команд
```bash
# Установка пароля администратора СУБД
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD 'Пароль';"

# Создание базы данных
sudo -u postgres psql -c "CREATE DATABASE mydb;"

# Создание пользователя
sudo -u postgres psql -c "CREATE ROLE myuser LOGIN CREATEDB;"
```
При установке пароля текст пароля заключается в одинарные кавычки, а вся команда — в двойные.

##### 5.3. Подключение к удалённой базе
```bash
psql -h <IP-адрес> -U postgres -d mydb
```
#### 6. Установка pgAdmin
pgAdmin4 — веб-приложение с открытым исходным кодом для управления и администрирования баз данных PostgreSQL. Предоставляет удобный интерфейс для выполнения SQL-запросов, управления объектами базы данных и мониторинга производительности.

##### 6.1. Установка
```bash
sudo apt install pgadmin4
```
Пакет pgadmin4 устанавливает все необходимые компоненты для запуска десктопной и веб-версии.

Дополнительные пакеты:

Пакет                       | Описание
--------------------------- | ---------------------
pgadmin4-desktop	 | Пользовательский десктоп-интерфейс
pgadmin4-web	 | Пользовательский веб-интерфейс
pgadmin4-server	 | Пакет основного сервера

##### 6.2. Настройка веб-версии
После установки десктопное приложение готово к работе, веб-приложение требует дополнительных настроек.

Выполните сценарий автоматической настройки:

```bash
sudo /usr/pgadmin4/bin/setup-web.sh
```
В ходе выполнения сценария:

- На запрос настройки веб-сервера Apache ответить yes;
- На запрос перезапуска Apache ответить yes.
- Для использования PAM-аутентификации:

```bash
# Установить модуль
sudo apt install libapache2-mod-authnz-pam

# Активировать модуль
sudo a2enmod authnz_pam

# Раскомментировать в /etc/apache2/conf-available/pgadmin4.conf параметры:
# AuthType Basic
# AuthName "example_pam"
# AuthBasicProvider PAM
# AuthPAMService apache2

# Перезапустить Apache
sudo systemctl restart apache2
```
Доступ к pgAdmin4 будет возможен по адресу http://localhost/pgadmin4 или http://имя_сервера/pgadmin4.

#### 7. Использование pgAdmin
##### 7.1. Подключение к серверу
- Откройте pgAdmin4 (десктопное приложение или веб-интерфейс).
- В левой панели нажмите правой кнопкой мыши на «Servers» → «Create» → «Server».
- В поле «Name» укажите произвольное имя сервера.
- На вкладке «Connection» укажите:
- Host name/address — localhost или IP-адрес сервера;
- Port — 5432 (или порт нужного кластера);
- Maintenance database — postgres;
- Username — postgres;
- Password — пароль, установленный ранее.
- Нажмите «Save».

##### 7.2. Основные возможности
- Просмотр и управление базами данных, схемами, таблицами;
- Выполнение SQL-запросов через Query Tool;
- Мониторинг активности сервера;
- Резервное копирование и восстановление;
- Управление ролями и правами доступа.

#### 8. Настройка параметров конфигурации на различных уровнях
PostgreSQL использует несколько уровней настройки:

Уровень          | Файл           	| Описание
---------------- | ---------------- | -------------
Глобальный	 | /etc/postgresql/<версия>/<кластер>/postgresql.conf	 | Основные параметры сервера
Аутентификация	 | /etc/postgresql/<версия>/<кластер>/pg_hba.conf	 | Правила доступа клиентов
Идентификация	 | /etc/postgresql/<версия>/<кластер>/pg_ident.conf	 | Сопоставление системных и СУБД-пользователей
Уровень БД	 | ALTER DATABASE ... SET ...	 | Параметры для конкретной БД
Уровень роли	 | ALTER ROLE ... SET ...	 | Параметры для конкретной роли

##### 8.1. Основные параметры postgresql.conf

Параметр         | Описание         | Значение по умолчанию
---------------- | ---------------- | -------------
listen_addresses	 | IP-адреса для прослушивания	 | localhost
port	 | Порт сервера	 | 5432
max_connections	 | Максимум подключений	 | 100
shared_buffers	 | Размер разделяемой памяти	 | 128MB
log_destination	 | Формат журнала	 | stderr
logging_collector	 | Сбор журналов	 | off

Для разрешения удалённых подключений установите:

```text
listen_addresses = '*'
Допустимые значения:

'*' — все сетевые интерфейсы (IPv4 и IPv6);

'0.0.0.0' — все IPv4-интерфейсы;

'::' — все IPv6-интерфейсы;

'192.168.1.2,10.0.0.2' — конкретные адреса.
```
##### 8.2. Настройка pg_hba.conf
Файл pg_hba.conf определяет, какие клиенты могут подключаться и с какой аутентификацией.

Пример конфигурации для разрешения подключений из локальной сети:

```text
# TYPE  DATABASE  USER  ADDRESS        METHOD
local   all       all                  peer
host    all       all   127.0.0.1/32   md5
host    all       all   192.168.32.0/24  md5
host    all       all   ::1/128        md5
```
Методы аутентификации:

Метод                       | Описание
--------------------------- | ---------------------
trust	 | Без пароля (небезопасно)
md5	 | Пароль с MD5-хэшированием
scram-sha-256	 | Более безопасный метод
peer	 | По системному пользователю (только local)
ident	 | По системному пользователю (TCP)

##### 8.3. Применение изменений
```bash
# Перезагрузка конфигурации без остановки сервера
sudo pg_ctlcluster 11 main reload

# Или через psql
sudo -u postgres psql -c "SELECT pg_reload_conf();"

# Полный перезапуск (если изменены параметры, требующие перезапуска)
sudo pg_ctlcluster 11 main restart
```
#### 9. Практическая работа
##### 9.1. Установка PostgreSQL
```bash
sudo apt update
sudo apt install postgresql-11
systemctl status postgresql
```
##### 9.2. Создание кластера БД reserve и запуск обслуживающего его экземпляра
```bash
# Создать кластер reserve для версии 11
sudo pg_createcluster 11 reserve

# Запустить экземпляр СУБД для кластера reserve
sudo pg_ctlcluster 11 reserve start

# Проверить список кластеров
pg_lsclusters
```
Ожидаемый вывод:

```text
Ver Cluster Port Status Owner    Data directory              Log file
11  main    5432 online postgres /var/lib/postgresql/11/main /var/log/postgresql/postgresql-11-main.log
11  reserve 5433 online postgres /var/lib/postgresql/11/reserve /var/log/postgresql/postgresql-11-reserve.log
```
##### 9.3. Подключение к кластеру БД main через psql
```bash
# Подключиться к кластеру main (порт 5432)
sudo -u postgres psql -p 5432
В интерактивной сессии psql:

sql
-- Просмотреть список баз данных
\l

-- Выйти
\q
```
##### 9.4. Создание суперпользователя PostgreSQL
```bash
# Создать роль adminuser с правами суперпользователя
sudo -u postgres psql -c "CREATE ROLE adminuser WITH SUPERUSER LOGIN PASSWORD 'AdminPass123!';"

# Проверить создание
sudo -u postgres psql -c "\du"
```
##### 9.5. Установка pgAdmin
```bash
sudo apt install pgadmin4

# Настройка веб-версии
sudo /usr/pgadmin4/bin/setup-web.sh

# Установка и активация модуля PAM
sudo apt install libapache2-mod-authnz-pam
sudo a2enmod authnz_pam
sudo systemctl restart apache2
```
Доступ к pgAdmin4: http://localhost/pgadmin4.

##### 9.6. Изменение параметров конфигурации под учётной записью администратора ОС
Администратор ОС (например, пользователь с правами sudo) может редактировать конфигурационные файлы напрямую:

```bash
# Открыть файл конфигурации кластера main
sudo nano /etc/postgresql/11/main/postgresql.conf

# Изменить параметр listen_addresses
listen_addresses = '*'

# Открыть файл pg_hba.conf
sudo nano /etc/postgresql/11/main/pg_hba.conf

# Добавить строку для локальной сети
host    all    all    192.168.32.0/24    md5

# Применить изменения
sudo pg_ctlcluster 11 main restart
```
##### 9.7. Изменение параметров конфигурации под учётной записью суперпользователя PostgreSQL
Суперпользователь PostgreSQL (например, adminuser), не имеющий административных полномочий в ОС, может изменять ряд параметров через SQL-команды:

```bash
# Подключиться как adminuser
psql -h localhost -U adminuser -d postgres
В сессии psql:

sql
-- Изменить параметр для текущей сессии
SET work_mem = '64MB';

-- Изменить параметр для конкретной базы данных
ALTER DATABASE mydb SET work_mem = '128MB';

-- Изменить параметр для конкретной роли
ALTER ROLE adminuser SET work_mem = '256MB';

-- Просмотреть текущие значения
SHOW work_mem;

-- Проверить все настройки
SELECT name, setting, unit FROM pg_settings WHERE name LIKE '%work_mem%';
```
Важно: суперпользователь PostgreSQL может изменять только параметры, не требующие перезапуска сервера (параметры, помеченные как user или superuser в pg_settings). Параметры, требующие перезапуска (например, shared_buffers, max_connections), могут быть изменены только через файл postgresql.conf администратором ОС.

##### 9.8. Проверка результатов
```bash
# Проверить статус кластеров
pg_lsclusters

# Проверить подключение к кластеру reserve
sudo -u postgres psql -p 5433 -c "SELECT version();"

# Проверить список ролей
sudo -u postgres psql -c "\du"
```
